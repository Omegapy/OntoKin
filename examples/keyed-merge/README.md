This corpus contains **144 predetermined source cases**: 79 valid cases with separately authored explicit .16 controls and 65 intended refusals. It is input evidence for reviewed adoption. It does not assert that C084 runtime implementation or any release gate has passed.

The [adoption](../../docs/language-design/keyed-merge-v0.1/ADOPTION.md) defines exact common types, left-before-right admission, canonical collision refusal, detached provenance and cumulative work. Its union keys, scalar arithmetic, rectangular panel geometry and fixed motion samples come from authored values. The generator imports no OntoKin parser, runtime or exporter.

## Reading the expected records

`expected_outcome` is the inherited binary corpus classification: `valid` or `invalid` (an intended refusal). It is not the runtime's protocol category. The separate `expected_protocol_outcome` must match the exact runtime validation outcome: `valid`, `invalid`, `unsupported` or `resource_limit`. A resource refusal cannot substitute for a required semantic diagnostic.

For new merge diagnostics, `diagnostic_anchor_mode: exact_token` requires the exact first lexical token of the authored operand, including an opening parenthesis. New collision diagnostics also bind the exact single related left token, category, phase, rule and details. Complete merge provenance spans remain distinct from these tokens. `contains_token` denotes only an independently authored token within an inherited constructor/name diagnostic; it does not assert that the inherited diagnostic covers only that token.

`source_merge_records` is the source syntax inventory. The probe's required merge expressions identify actually selected derivations; an unselected merge can remain in the syntax inventory while producing no dynamic record. Nested scalar and generated-entry cases prescribe full aggregate-before-contribution record order. Constructor recipes identify original typed leaf values; every valid case also has a no-merge .16 control for complete typed-value comparison.

Frozen location tuples contain source ID, source revision and UTF-8 start/end bytes. They intentionally omit `filename`: the exact runtime filename must equal the canonical supplied-unit filename for that source ID. Enrich each tuple from `canonical_manifest.units` before exact runtime comparison. Runtime locations must contain exactly the five schema fields, with no unknown or missing fields; the shorter authored tuple is not permission to ignore a runtime filename.

## Representative repair and finite evidence requirements

The pinned panel library contains standard `left` and `right` panels and a separately defined optional `vent`. Two independent occurrences share the library and exact PNG. In [panel-task](panel-task.files.json), both optional sets are disabled. Changing only the first occurrence's `include_optional` parameter to `true` adds its 0.5-meter vent while keeping its existing panels, sibling, library, asset and unrelated moving marker unchanged. Turning it off removes only that added part. Three delivered names deliberately share the same disabled source bundle; their identities are disclosed by the manifest records.

[workflows.json](workflows.json) specifies ten actual Agent workflow groups, including add/remove, collision and absent-key rollback, stale cursors, current host authority, two genuine cancellation stages, durable reopen/retry, changed payloads, interrupted publication and complete byte retrieval. These are requirements, not execution counts.

[delivery-comparison.json](delivery-comparison.json) enumerates the narrow metadata differences allowed after independent validation. Complete BIN, compact raw JSON/member order and padded framing must otherwise agree with the explicit .16 control. [supplied-byte-adversaries.json](supplied-byte-adversaries.json) requires nineteen mutation kinds across three actual source artifacts, plus unchanged positives. Mutations operate on supplied bytes, including operand spans, contribution sides and provenance order. Pinned native readers and direct capture review remain separate required observations.

[budget-expectations.json](budget-expectations.json) fixes low and adequate authority outcomes from the authored workload and inherited accounting requirements. Ordinary defaults remain 100,000 operations and 30,000 ms. The higher fixture explicitly requests 400,000 operations and 80,000 ms with independent current host permission. Animation duration remains 1 second. No exact candidate-derived consumed-operation claim or changed original gate is included.
