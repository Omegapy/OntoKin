# Adopted impulse-0.1 fixtures

These source fixtures and independently derived expectations were authored before implementation of [OK-LANG-004](../OK-LANG-004-source-impulses-and-free-sphere-dynamics.md), then adopted without changing their bytes. [adoption.json](adoption.json) binds that decision to the proposal commit and exact acceptance hash. Original proposed/unexecuted labels in the immutable inventory preserve its authorship history. No case is marked executed or passed by adoption; implementation results belong in separately identified evidence.

`acceptance.json` is the complete gate and oracle inventory. It records each source manifest, exact source revisions and program bundle revision, positive samples, rejection category and operational acceptance procedure. `sources/` contains complete `.ok` entry units. The root `*.files.json` files use the existing `ontokin.files/0.1` transport and declare the full pinned offline closure with paths contained in this folder.

`libraries/01-surface-parts03.ok` is an exact-byte copy of the adopted [surface library](../surface-v0.1/01-surface-parts.ok), hash `sha256:87fed50bdcb9b6274ec87981cc67028463c10b1cdce301060416c69586b428ce`. It remains a `0.3` declaration. A proposed `0.4` sphere component inherits its visible loft while adding explicit own sphere mass/radius and dynamic mode. A pure `0.2` vector helper demonstrates mixed-profile definitions without reinterpreting their declaring profiles. This closure exercises actual native source geometry and distinct PBR regions; no Python-authored geometry substitutes for `.ok`.

The core fixture sphere normally has mass `2 kg`, radius `0.5 m`, inertia `0.2 kg m²`, and zero gravity. Individual complete sources make every variation explicit. Application points use the object's self frame, while impulse vectors use world. Off-center response is independently determined by `R q × J`; the visible loft and its local placement contribute no mass or inertia.

Numerical expectations use the inherited core tolerances recorded in the manifest. Formula records for orientation denote mathematical reference rotations, not values read back from an implementation. Extreme finite-cancellation cases are evaluation-only and do not claim float32 GLB delivery. All event times and `before`/`after` sides are exact; the decimal-clock case distinguishes authored binary64 `0.1[s]` from protocol decimal `"0.1"`.

Generated repair cases have the same module/scene/occurrence identities. Only the first generated child's root occurrence mass or radius entry changes. The fixture comparison requires stable sibling physics, exact imported source bytes, unchanged native visual geometry and unchanged PBR factors. Runtime Agent acceptance must perform the source patch and return the resulting immutable revision; separately compiling two candidate files is insufficient evidence for the Agent gate.

`impulses.schema.json` specifies the new profile's bounded per-object influence projection. It is a proposed shape check, not an implemented protocol claim. Geometry summary/page schemas are inherited unchanged and continue to name the `surface-0.1` geometry capability even in a `0.4` entry.

During implementation, retain actual evidence separately. Do not change these expected values or source bytes to suppress a failure. A deliberate specification correction needs a reviewed versioned decision and new hashes. The parent release's evidence, acceptance matrix and historical source files remain untouched.
