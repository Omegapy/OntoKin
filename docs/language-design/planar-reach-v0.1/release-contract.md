# Proposed finite planar reach release gate

This is **OK-LANG-006 0.1.0-draft.2** acceptance preparation. It is unadopted and
unimplemented. A separate published adoption record must freeze this document,
the effective [profile](profile-draft2.json), [requirements](requirements-draft2.json),
all original and supplementary sources/expectations, numerical strategy and
Agent/GLB schemas before runtime implementation begins.

The finite release is `planar-reach-0.1`, explicit `ontokin.agent/0.6`, recorded
`ontokin.glb/0.6` and its separate durable store. It advances reusable purposeful
actions in complete articulated assets. It does not complete the [GOAL](../../../GOAL.md),
establish a dynamic actuator/contact model, or measure an authoring improvement.

## 1. Predetermined scope and acceptance

R01–R12 and Q01–Q22 in the effective requirement matrix are all mandatory. Every
original P01–P26 and N01–N15 case must execute through actual source typing,
construction and the indicated evaluation/prefix boundaries. All supplementary
L01–L04 cases and every separately enumerated protocol step must execute with
their retained expected values. The public P18/P19 held-outs remain public
predetermined variants; no claim of secret evaluation follows from their name.

The old 41-case fixture closure, original oracle and three original library
files must retain their exact bytes. The Draft 2 source supplements and
requirement amendments are independently identified additions. If a real
mathematical/source defect is found, first publish its exact old/new input
identities and a versioned requirement decision, retain the failed evidence,
and require independent review. A failing implementation cannot adjust a target,
tolerance, required object set, diagnostic or test mapping to claim a pass.

Source goal coordinates and exact-rational coordinate samples require exact
binary64 equality, including the specified canonical half-turn/zero rules.
Derived poses use the existing separately stated comparison tolerances; source
goal residual remains at most `1e-9 m`. Default recorded carrier/landmark limits
remain `0.001 m` and `0.001 rad`, with time tolerance at most `1e-6 s`. Every
caller-specified tighter setting retains its meaning. Failure is explicit when
a requested source/delivery level cannot be established within its support and
work bounds.

## 2. Exact identities and provider-neutral evidence

The new audit contract is `ontokin.reach-release-evidence/0.1`. Evidence records
identify the actual published Git commit/tree, actual runtime version and
implementation hash, and every eligible input by normalized repository-relative
path, byte length and SHA-256. Eligible inputs include runtime, tests, tools,
source libraries/examples, adopted schemas/contracts/corpora, workflow policy,
verification pins and the literal requirement-to-test mapping. Hash comparisons
use named file bytes; file enumeration order is not a semantic change.

Each mandatory role records its schema/version, command and working-directory
policy, start/end UTC clocks, process result, provider, interpreter/platform,
tool versions, exact input identity and output members with hashes/lengths.
Commands that never started, an interrupted run, skipped test or missing output
cannot be reported as a pass. A tool or renderer must be actually invoked before
its version and result can establish a role. A collector only binds existing
files; it cannot invent run status, review observations, cost or provenance.

The owner-approved [local validation policy](../../engineering/OK-ENG-006-local-validation-and-hosted-ci-policy.md)
governs every role. Use fresh local commands and verification-only pinned tools;
no hosted job dispatch/retry, paid execution or Actions setting change is needed.
Existing workflows remain manual-only with default-false hosted opt-in. Record
observed remote CI state honestly; no hosted run is not a failed local role.
Runtime retains standard-library-only dependencies unless a separately reviewed
decision changes that policy.

Each output path must be relative, unique and contained within its evidence
root. Independently verify member hashes, duplicate paths, manifest closure,
source/artifact/Agent identities and eligible input equality before accepting
role claims. Reject absolute paths, traversal, symlink escapes, inaccessible
members and mismatched hashes. Evidence from an older source can apply only
when every eligible named input required by that role is demonstrably identical;
a past green label or equal runtime version alone is insufficient.

it is not itself a substitute role or a new execution of missing work. Its
requirement rows use `passed`, `failed` or `pending`. A missing role is pending;
an executed contradiction is failed. The finite release passes only when every
mandatory row and role passes. `full_product_goal_completed` remains false.

## 4. Source and retrieved delivery corpus

The mandatory source-built GLBs are P01–P23, P25, P26 and L01–L03: **28 artifacts**.
P17 is delivered only through its valid `t=2` prefix; its separate full `t=4`
request must fail at exact `t=3` with no successful artifact. L04 supplies its
valid requested `t=0.25` prefix as the separately required Agent recovery
artifact below; the full request crossing its failed boundary must fail.
P24's 128 constructed named actions remains a mandatory positive source/Agent
budget case, but does not promise a complete oversized GLB history. Combined
history/response caps are enforced without increasing any profile maximum.

The mandatory Agent-retrieved corpus is P01, P11, P13, P20, P16, P17's valid
prefix and L01–L03: **nine artifacts**. A **separate tenth Agent artifact** is
required after LP01's reset and fresh successful `t=0.25` run: issue an actual
delivery request with inherited `options.end: "0.25"`, then retrieve and
independently validate its exact bytes, new run identity and unchanged L04
program revision. Reset does not change source identity. This is
an additional delivery gate; LP01–LP05's original 42 fixed steps do not already
contain this export or retrieval and remain unchanged. Use the actual repeated
source library bytes. Required
delivery failures include N06's selected-branch limit, P17's full prefix, L04's
failed boundary, collapsed semantic times, impossible requested quantization
and cancellation/budget failures. Preserve any earlier valid artifact with its
own identity; never relabel it as output of a failed request.

Independently inspect full expected object/visible-carrier sets, original surface
vertices/regions/PBR and actual placed local geometry. Validate every retained
key and both sides of each source semantic boundary. For each adjacent key
interval, check at least its midpoint and seven further distinct interior
parameters; add the fixed source fixture samples and phase-boundary neighbors.
Check complete site and released-payload trajectories, not only carrier centers.
The arithmetic certificate establishes the continuous bound; dense comparisons
exercise the actual reader/destination and cannot replace that proof. All
validation poses consume the inherited aggregate cap before expansion.

No format-only success is enough: native geometry, actual application transforms,
source goal outcome and recorded histories must agree independently. Any tolerated
Khronos warning must be identified and reviewed before the gate; the default
required corpus has zero errors and no unexplained warnings.

## 5. Browser and human-visible review

Source browser selection is P01, P11, P20, P16, P18, P19 and L01–L03. Agent browser
selection is the nine mandatory retrieved artifacts above. For each, retain a
complete front view, complete side view and an action-specific intermediate
playback capture with exact displayed/sample time. This is at least **54 fresh
reach captures**, separate from any required inherited captures.

Use intermediate times that visibly exercise the action: the paused L01 state
and a resumed moving check; L02/L03 after the second owner begins; P16 after
release while the independent sphere moves; P17 within its valid prefix. Record
all numerical sampling times even when only one intermediate image is retained.
Default camera fitting must include the entire asset and supported trajectory
extent without clipping. The full bench, character limbs/eyes, rack siblings and
payload must be inspectable across the selected views.

Actual visual review checks complete silhouettes, missing or substituted parts,
regional materials, unreasonable occlusion, motion/pose presentation, viewport
clipping, controls and displayed source/artifact/time identity. Record legitimate
visibility limits rather than declaring unseen surfaces verified. A reviewer
must actually open the images; a generated contact sheet, a successful screenshot
command or a script that writes observations is not a review. Numerical accuracy,
continuous playback and goal acceptance remain separate evidence.

## 6. Hostile probes and independent implementations

Freeze the Q01–Q22 mapping and all supplementary protocol steps before executing
acceptance. The concrete test/function names may be assigned during implementation,
but the literal mapping must be published before the final execution and audited
against the real test inventory. Count actual named tests; do not infer coverage
from broad filename patterns, passing wrapper commands or a receipt's counts.

Each corrupt-byte probe starts with an otherwise valid, identified artifact.
Keep its complete expected object set and unrelated source/geometry/history
structure. Recompute transport hashes where needed to isolate the intended
semantic mutation. Record the exact mutation path, original/new member hashes,
actual rejection code/stage and preflight allocation counts. A duplicate-key
parse failure cannot satisfy a direct-rounding probe, and a missing-object failure
cannot satisfy the shared-accessor aggregate-pose probe.

The independent numerical/source oracle and supplied-byte reader must not call
the production reach solver, source sampler, exporter planner or certificate
generator to choose expected values. Reuse of raw parsing/format utilities must
be disclosed and cannot create a shared authority for the claim being checked.
The retained independent equations, original predetermined expected values and
rounding certificates provide separate checks on the numerical implementation.

## 7. Publication and resulting-main verification

Publish the implementation, literal mapping, commands, actual logs/reports,
review observations and all evidence members in GitHub with verified identities.
Large artifacts may use exact ordered Git-sized parts with full-file hashes,
member inventories and a verified restoration script. Retain failed/interrupted
attempts separately; never overwrite them with the successful run's status.

Use the repository's observed-head integration lease and protected expected-head
PR merge. Verify the actual resulting `main` commit/tree and input equality,
then execute the relevant local regression/Agent/source/delivery/native checks
and re-audit the release evidence against those actual inputs. Record what ran,
what was byte-identical and any remaining limitation. Release or renew the lease
at meaningful verified checkpoints.

Only the completed independent audit plus verified integration closes this finite
release. Update STATUS with the exact accepted scope and the next unmet GOAL gate.
The direct-tool authoring comparison still needs its own frozen preparation,
unseen variants, actual task/repair measurements, quality checks and disclosed
cost availability. Richer physical domains, controllers, appearance, deformable
matter and live delivery remain explicit subsequent requirements.
