# C191-A1: identity for an oversized source rejected before admission

**Decision, November 9, 2026:** adopt this narrow clarification before formal
C191 runtime qualification, following independent reviewer agreement. Preserve
the original contract manifest, diagnostics and all frozen fixtures unchanged.

The original diagnostic prose assigns `C191_E_RESOURCE_LIMIT` an execution-block
or source-header span. The output schema permits null source identity and spans.
For a source larger than the fixed 65,536-byte admission limit, computing an
exact full-source identity would require reading bytes beyond that limit. The
implementation must enforce the read bound before decoding or parsing.

## Required behavior

Read at most **65,537 bytes** from the requested source. If that read exceeds
65,536 bytes, reject before source admission with `C191_E_RESOURCE_LIMIT`, phase
`execute`, and the existing blocked-level list. Set the attempted source's
full-source SHA-256 and diagnostic span to **null**. Do not present a hash of the
read prefix as the identity of the full file. No source level is achieved and no
accepted revision or artifact is changed.

A file of exactly 65,536 bytes remains subject to all ordinary grammar, token,
semantic and budget checks. Once its entire admitted byte sequence is available,
its exact source hash and all required diagnostic spans retain their existing
meaning. This clarification applies only to rejection at the source-byte
admission ceiling; it does not permit missing identities for admitted sources.

The supplemental independent fixtures must include an otherwise valid source
padded to exactly 65,536 bytes, and a source of 65,537 bytes. The first must
validate with its complete hash. The second must produce the rejection above
without a full-source hash or source span. An oversized file must not trigger
an unbounded read before rejection.

## Scope and provenance

Keep all source/profile/backend/output bindings, physical expectations,
canonical solver inputs, ordinary and qualification budgets, native object and
output limits, and every previously frozen source-span assertion unchanged.
This is an explicit resolution of the pre-admission diagnostic ambiguity, not
a change to physical acceptance. Include this file's SHA-256 in the prototype's
verified contract dependency closure and qualification evidence.

The coordinator publishes the amendment and independent supplemental approval
before formal runtime qualification. The initial draft and previously published
contract retain their original hashes and remain reviewable.
