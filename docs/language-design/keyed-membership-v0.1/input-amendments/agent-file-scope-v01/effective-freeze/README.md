## Predecessor controls and independence

The effective predecessor cohort has 256 controls: 232 core literal/reduction
programs, eight direct old-name/binding cases, and sixteen representative
controls. The full cohort passed on exact C087. A later independent review found
that literal control metadata had an extra `literal_flags` property; the revised
literal library reuses the existing `override_flags` property instead. All eight
affected literal programs were then rechecked, including exact property-name
order, original semantic values, source hashes/revisions, panel corners,
triangles, PBR, UVs, image bytes and motion. Source/reduction library bytes and
all semantic geometry answers stayed unchanged.

The first failed input-preparation run, every draft and observer version are
retained in the adjacent preparation history. Its failures are not runtime
successes. No predecessor frozen expectations or production source were edited.
No .21 product module was imported or executed to create these answers.

The representative task has two independent instances of one pinned three-panel
component library and one pinned catalog. Sparse width override insertion,
update, removal and restoration affect only the first occurrence. Both
occurrences retain exact stable keys, texture/PBR facts and independent motion.
The unused override state creates no extra panel. The invalid selected width
retains the existing extrusion refusal and cannot become accepted state.

## Execution and review boundaries

The native direct-operation cases use fresh actual ledgers admitted through the
real entry-header API. The independently counted header costs 14 operations;
caller caps use that real admission prefix plus the fixed local operation
allowance. Successful tests must not preload counters, replace clocks, edit
resolved limits, or synthesize accepted authority. Deliberately malformed
ledger states are used only for the four explicit refusal tests.

Expected values are read-only. A source, producer, observer, transport or oracle
defect must preserve the failed run and original manifest, obtain a separately
reviewed correction, and publish a successor input identity before continuing.
Passing these predecessor preflights alone makes no claim about .21 runtime,
Agent, native delivery, integration, release, or external user validation.
