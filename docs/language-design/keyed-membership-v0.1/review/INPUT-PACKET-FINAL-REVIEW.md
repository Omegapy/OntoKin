## Acceptance coverage and reasoning

The 180 source cases cover empty, singleton, canonical first/middle/last/absent,
reordered and maximum-cardinality membership; case and punctuation distinctions;
key-domain boundaries and invalid scalar sequences; the 24 existing authored
leaf families; wrong types and arities; unsupported grammar forms; eager child
and payload failures; abstract and unselected behavior; guarded versus unguarded
lookup; separate old/new declaring units and ordinary name scopes; callback and
generated-part binders; generated views, access and shape restrictions; helper
recomputation and immutable binding reuse. The inherited String cases include
successful .21 composition, mixed-type refusal, the 65,536-byte result boundary
and refusal, and the 4,194,304-byte cumulative boundary and refusal, preserving
the original String diagnostic profile.

The 101 native negative cases and 68 valid/opaque cases exercise both expected
and leaf metadata. They distinguish native wrapper shape from leaf type errors,
exclude foreign equality/hash/conversion calls, bound kinds and Ref names, cover
Quantity extrema and zero/Bool refusal, retain legal Int children in empty
Vec3/Vector3/Range values, require Point3 length, reject recursive/deep metadata,
and compare valid-but-different units, vector children and nominal Ref names.
Explicit malformed and UNKNOWN second leaves cannot be hidden by a first-key
match. The 257-entry error fixes the exact budget, limit and consumed details.
Three callback cases require captured tuple/descriptor semantics and no payload
reread. The expected Type mutation uses isolated fresh Type objects, avoiding
global-singleton or leaf-alias ambiguity. Four abstract cases pay no dynamic
stage and preserve signature checking before an unknown result.

The ten resource schedules fix every operation-cap prefix and every cancellation
and deadline seam, including maximum first-match and maximum last/absent scans.
They use the exact five category names and distinguish completed work from the
counter increment on a refusing operation/deadline tick. Callback identity and
callback-before-cap-before-deadline order are explicit. The fresh native header
has 100 bytes through the first body token: 12 tokens plus two 64-byte blocks
produce 14 actual admission operations. Local caps add to that real prefix;
successful tests may not preload counters, alter resolved limits or replace the
original clock. Shared String quota and prior stage restoration remain checked.

The thirteen provenance cases require both Boolean outcomes across inherited
map/filter/reduce/merge/zip/rekey families, complete aggregate source records,
actual member dependencies, no invented membership lineage, and no fictitious
query-selected leaf. Warm and reopened requests retain those obligations. The
source-owned spans provide an independently authored origin basis rather than

The eleven authoritative Agent scenarios contain actual request templates for

## Material findings closed before this approval

1. Native type validation now tests closed shallow metadata and valid-but-
   mismatched units/children/nominal identities, rather than merely different
   kind names or malformed shapes.
2. Full admission is tested with an explicit malformed or UNKNOWN tail after an
   early matching key; resource details and interruption counters are exact.
3. Existing String behavior is tested under .21, not inferred solely from .20
   predecessor passes.
4. Composition verifies retained detached origins and actual dependencies, not
   only Boolean and geometry output.
5. Agent edit requests include the mandatory `element_id`; cursor and interrupted
   publication expectations match the inherited service paths.
6. The literal representative control formerly introduced an extra public
   `literal_flags` property. Existing lowering/export emits every param/derive,
   so that property defeated the stated complete JSON comparison. The final
   literal control reuses `override_flags` at the original declaration position.
   Its property names/order and values now align with source/reduction controls;
   no broad metadata exemption was introduced. All eight affected literal
   programs were separately rechecked while source/reduction bytes and semantic
   geometry answers remained unchanged.
