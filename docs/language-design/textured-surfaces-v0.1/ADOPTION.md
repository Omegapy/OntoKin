## Explicit versions and finite promise

Select source `ontokin "0.13";` with profile `textured-surfaces-0.1`, immutable `ontokin.bundle/0.2` and `ontokin.files/0.2`, explicit `ontokin.agent/0.13`, and recorded `ontokin.glb/0.13`. Earlier source, bundle, Agent and destination bindings retain their exact meanings and defaults. This profile includes the existing .12 geometry and execution-budget capabilities. A .13 declaring unit may import compatible earlier pinned definitions under their original declaring semantics. Earlier declaring units cannot import .13 or gain its builtins through an import.

C080 attaches opaque offline PNG images to stable keyed material regions of existing native surfaces. One affine planar mapping and one base-color image belong to each textured region. Underlying positions, normals, triangle ownership, indices, rigid placement, carrier motion, mass and physical authority stay unchanged. The representative tasks are labeled equipment housings, warning panels and marked tray floors.

No automatic unwrapping, atlas, painting, transparency, material graph, normal/roughness map, deformation mapping, network retrieval, live-engine physics or Unreal support is introduced. Complete appearance and product release acceptance remain false.

## Immutable source and asset closure

The inline payload has exactly `schema_version`, `entry`, `modules`, and `assets`. Entry and module descriptors retain bundle/0.1 fields and exact UTF-8 source semantics. Each asset has exactly `asset_id`, `sha256`, `media_type`, and `data_base64`. `media_type` is `image/png`; `sha256` is `sha256:` followed by 64 lowercase hexadecimal digits. The digest is SHA256 of the entire original PNG byte string. Base64 uses the canonical padded standard alphabet, no whitespace, and exact decode/re-encode equality. Check encoded length before decoding.

Asset IDs are global, case-sensitive ASCII strings matching `[a-z][a-z0-9._-]{0,63}`. Supplied IDs are unique. Two different IDs may hold identical bytes; their identities remain distinct. Zero through four images are allowed. Every image is at most 300,000 encoded PNG bytes; the aggregate is at most 1,200,000 bytes. The unchanged source and module limits still apply. Agent/0.13's complete JSON request envelope is at most 8,388,608 UTF-8 bytes; earlier transport limits are unchanged.

`png_asset("id", "sha256:...")` calls are literal declarations as well as typed image references. Both arguments must be string literals. Collect calls resolved as this builtin in .13 declaring source units throughout the parsed entry and the entire reachable, pinned module closure, including noninstantiated reusable definitions and unused palette expressions. Profile .13 reserves the new builtin and nominal type names. Earlier lexical profiles retain their names and user functions; an earlier user function named png_asset or a qualified user-function call is not an asset declaration. Comments and string contents do not declare assets. Repeated declarations of the same ID/digest share one attachment; the same ID with conflicting digests is invalid. Dynamic image-ID or digest expressions are invalid. Every actual reference must resolve to its declared attachment. The supplied attachment set must equal this declared set exactly. Missing, extra and wrong-digest attachments are errors; no ambient file search fills a gap.

The bundle/0.2 canonical manifest retains the .1 sorted source-unit descriptors, changes `schema_version` to `ontokin.bundle/0.2`, and adds assets sorted by `asset_id`, each with `asset_id`, `media_type`, `sha256`, and `byte_length`. Canonical JSON uses sorted object keys, compact separators, unescaped Unicode and no nonfinite numbers. The program revision is `sha256:` plus SHA256 of `b"ontokin.bundle/0.2\0" + canonical_manifest_utf8`. Filenames keep their existing source meaning; asset transport paths and base64 text are not new identity fields. Reordering supplied assets/modules does not change revision. Source bytes, asset bytes, asset identities or source filenames do. A source unit's own revision remains SHA256 of its exact UTF-8 bytes alone.

The new asset bundle is immutable, including detached accessors and payload copies. Legacy bundle/0.1 loaders remain strict. Profile .13 requires bundle/0.2 even when its asset set is empty. A stored image, revision, prior validation or retry grants no execution authority.

The file manifest uses `ontokin.files/0.2`, keeps existing entry/module file descriptors, and replaces each asset's `data_base64` with `path`. Paths are explicit ordinary files confined to the manifest root, without symlinks, traversal, absolute paths, network URLs or mutable lookup. Read exact bounded bytes, check digest and stability, and protect all source/image input paths from output overwrite. The manifest is transport, not source authority. CLI export selects this manifest explicitly with `--bundle` and target `ontokin.glb/0.13`; Agent selection is explicit `--protocol ontokin.agent/0.13`.

## PNG admission and work

The admitted subset is noninterlaced 8-bit RGB (color type 2) or RGBA (type 6), dimensions 1 through 256 inclusive on each axis, compression/filter methods zero, and fully opaque alpha. RGB implies alpha 255; every decoded RGBA alpha byte must be 255. Pixel samples are not premultiplied. Individual reconstructed pixel data is at most 262,144 bytes, aggregate at most 1,048,576. Filtered data has exactly `height * (1 + width * channels)` bytes; bound that amount before decompression.

Only the PNG signature, one first IHDR of 13 bytes, one through 64 contiguous IDAT chunks, and one final empty IEND are supported. All ancillary and other critical chunks are refused in this finite profile. Check each chunk's length and CRC before accepting it; reject duplicate, reordered, truncated or trailing data. Concatenated IDAT data must be one complete zlib stream, with no preset dictionary, extra stream or trailing compressed bytes. Decompression is bounded by the exact expected length plus one detection byte, and must end at the exact expected length with no unused compressed tail. All five standard PNG row filters are supported; other filter bytes fail. Preserve original PNG bytes unchanged for export and retrieval.

Bundle sealing performs only bounded transport validation, base64 conversion, immutable copying and digest checks. PNG parsing and decompression occur under an admitted current execution ledger during represented validation, never as unmetered transport work. Charge one operation for each started 64-byte block of encoded image data, each chunk, each row and each reconstructed channel byte. Charge before work; retain bounded cancellation checkpoints during chunk, decompression and reconstruction loops. Image validation is once per declared asset per compilation, without persistent authority caches. Existing source/compiler/export work remains cumulative. Bound source numeric operations by the existing 32,768-bit operand limit.

Ordinary limits remain 100,000 operations and 30,000 ms. Large fixtures may explicitly request up to 2,000,000 operations and 80,000 ms, only within independently supplied current host authority. Caller caps only reduce execution. Source computation time and modeled animation duration remain separate. Larger new cases do not pass old fixed-budget gates.

## Source constructors and mapping

The new nominal types are `TextureImage`, `PlanarUV`, and `TextureBinding`. Existing geometry and material types retain their shape. Constructor signatures are:

| Constructor | Arguments | Result |
| --- | --- | --- |
| `png_asset` | literal String ID, literal String digest | TextureImage |
| `planar_uv` | Vec3<Length> origin, Vec3<Quantity[m^-1]> u, Vec3<Quantity[m^-1]> v, Real u_offset, Real v_offset | PlanarUV |
| `texture_binding` | TextureImage image, PlanarUV mapping | TextureBinding |
| `texture_surface` | Geometry surface, Keyed<TextureBinding> bindings | Geometry |

These Vec3 values are unframed recipe-local coordinates, like existing polygon coordinates. They do not pretend to be world or carrier frames. `vec3(1[m^-1], 0[m^-1], 0[m^-1])` is an inverse-length basis example. `texture_surface` accepts one existing unplaced native loft, extrusion, holes, ring loft, framed loft or pockets recipe, with no existing texture bindings. Its one through 16 binding keys must be distinct existing material-region keys. Bindings may name an existing authored palette key with zero emitted faces; its image is still part of declared closure and image admission, but it emits no primitive or UV rows. Other material regions remain untextured. An explicitly empty wrapper, primitive sphere/box, placed input, nested wrapper or unknown region is refused. Place the returned surface using the existing placement constructor afterward. The underlying geometry kind and source recipe stay intact.

For raw unplaced local position p, origin o, inverse-length row vectors u/v, and offsets a/b, define `U = dot(u, p-o) + a` and `V = dot(v, p-o) + b`. Canonical binary64 source inputs are interpreted as exact rational numbers for these dot products and sums; round each result once to binary64. Each origin component is within ±256 meters; each basis component within ±1024 inverse meters; each offset within ±1024. The two basis rows must be linearly independent under exact arithmetic. Each evaluated referenced UV component must be finite and within ±4096. Mapping scale, offset, shear and reflection are explicit. There is no auto-normalization, epsilon, winding adjustment or geometry change.

Evaluate a region's mapping only at the raw mesh corners referenced by that region. A full-size UV accessor uses `(0,0)` at corners not referenced by its region. The exporter converts referenced UVs to binary32. Underflow, quantized UV coincidence and a face projected to a UV line are allowed appearance outcomes; they do not imply geometric degeneracy or a guaranteed texture-detail resolution. Mapping does not depend on face normals, placement, world pose or current time. Material boundaries can have discontinuous UVs. Existing normal and back-face rules remain unchanged.

UV `(0,0)` is the upper left of the original PNG and `(1,1)` is the lower right. Increasing V goes down image rows. The fixed sampler has `magFilter=9728` and `minFilter=9728` (nearest), `wrapS=33071` and `wrapT=33071` (clamp to edge), without mipmaps. Values outside [0,1] intentionally sample the clamped edge. A textured material's existing alpha factor must equal 1. RGB image samples use the sRGB transfer function, decode to linear values, then multiply the unchanged linear RGB material factor. For normalized channel c, decode as c/12.92 when c<=0.04045, otherwise `((c+0.055)/1.055)^2.4`. Existing metallic and roughness factors and lighting retain their meanings.

## Agent lifecycle and inspection

Retain all twelve operations: discover, create, edit, validate, inspect, surface.mesh_page, evaluate, reset, export, artifact, status and cancel. Agent/0.13 has a separate durable store `texture-program-agent.sqlite3`, schema `ontokin.texture-program-agent-store/0.1`, and loader. Discovery describes the asset/mapping bounds and current host view through fresh bounded copies. Source create/edit, acceptance, reopen/retry, validation, inspection and artifacts bind the same complete source/asset revision.

Edit retains existing source patches and module changes and adds at most eight `asset_changes`. Add is `{operation:"add", asset:<descriptor>}`. Replace is `{operation:"replace", asset_id, expected_sha256, asset:<same-ID descriptor>}`. Remove is `{operation:"remove", asset_id, expected_sha256}`. Each ID may be touched once; add requires an absent original ID, and replace/remove require the exact original digest. Build one candidate containing all source, module and asset changes; then check declared closure and image validity under current authority. Rejecting any part preserves the prior accepted source and all prior attachments. Source-only edits preserve attachment bytes exactly. Asset-only transactions are structurally allowed but must still satisfy declared literal digests. Identical retries return the existing outcome; changed-payload retries fail under inherited request identity rules.

Use `inspect` with `selector.kind="texture_asset"` for asset metadata, or `selector.element_id=["assets", asset_id]` for one attachment. This route supports only identity/source fields, with metadata pagination bound to program, protocol and implementation. Optional `asset_slice={offset, max_bytes}` is permitted only with the exact asset element selector, no cursor/run/time/frame, integer offset within [0,total_bytes], and max_bytes in [1,65536]. It returns exact base64 bytes plus asset_id, element_id, program_revision, sha256, media_type, total_bytes, offset, returned_bytes, next_offset and complete. An EOF request returns an empty complete slice. Asset identities are not source-module identities.

Surface inspection includes image selection, mapping and actual UV values; its fingerprint and cursors bind them as well as unchanged geometry. No raw image array is copied into each surface page. Accepted state must be reauthorized under current host policy before any work, including asset retrieval. Charge current byte/copy work and honor caller caps, cancellation, stale revisions/pages and output limits. Export publication and its PNG-bearing GLB remain atomic; interrupted or failed export exposes no successful artifact.
