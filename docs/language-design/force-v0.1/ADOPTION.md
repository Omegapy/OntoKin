## Normative clarifications

1. **Identity and grammar.** The event grammar is `force <object-path> @ <stable-key> using <world-force-expression> for <positive-time-expression>;`. A missing key is `OKL-E-SYNTAX`; a key outside the inherited 1–64 ASCII stable-key grammar is `OKL-E-ID`; a duplicate force key is `OKL-E-NAME`. The force identity is `[module_key, scene_key, "force", force_key]`, distinct from object matter and motion authority.
2. **Prefix requests.** Existing `evaluate()` and evaluated-level validation check the complete scene horizon, even when only a few output samples are requested. `evaluate_prefix()` checks only its requested endpoint. The latter must preserve a valid shorter prefix when a future force start or completion would fail. It must not evaluate unrequested future trajectories to plan a prefix. Initial construction remains before-side at zero.
3. **Output projection.** New-profile object snapshots contain `forces` with `active`, `net_force_world_n`, `acceleration_world_m_per_s2`, `started_count`, `completed_count`, `last_change_time_seconds`, and `last_changes`. `active` is sorted by force key. Acceleration is null for nondynamic objects. The last-change clock is initially null; a change list is initially empty. Each change adds `kind: started` or `kind: completed` to the full force record. Unrelated boundaries preserve the latest per-object change list. All force vectors remain explicitly world-expressed, including in scoped self-frame inspections.
4. **Full force record.** Each active/change record contains `force_key`, `force_element_id`, `target_path`, `target_element_id`, `program_revision`, `source_location` (source ID, exact source revision, UTF-8 start/end bytes), `sequence_index`, `force_world_n`, `activation_time_seconds`, `duration_seconds` and `completion_time_seconds`. Clock strings use the inherited exact rational-time serialization; a completion beyond binary64 magnitude remains valid metadata.
5. **Automatic boundary failure.** Final active-set numeric failure is reported at that exact boundary, after-side, and rolls back its entire tentative state. The diagnostic names the target and the complete changed-force source records in canonical key order. Its primary source location is the first such record, including the original statement for an automatic completion. Failure before a boundary, including an interior extremum, preserves the inherited before-side diagnostic and last certified prefix.
6. **Finite results, not partial sums.** Net force is rounded once from its complete exact sum. Acceleration then combines canonical gravity and the exact quotient of canonical net force by canonical mass before its final rounding. Intermediate summation and quotient overflow are not failures when all exposed final values are representable. Nonfinite exposed results are not clamped. No force changes angular velocity.
7. **Work bounds.** The existing 100,000 logical output-entry and 1,000 sample caps remain. Complete active and retained change records count, including nested IDs and source spans. Conservative preallocation accounting may reject oversized output but cannot publish a truncated successful projection. Prefix planning considers only boundaries through the requested endpoint. Existing callback/deadline and caller-lowered construction/service limits remain enforceable. Cancellation cannot commit a partially processed boundary.

## Predetermined operational checks

The implementation must exercise zero-time cancellation, cancellation during an active-set scan and after tentative completion, lowered construction budgets, oversized nested output, exact key ordering, source/program identity propagation, unchanged-anchor replacement and cancellation, rollback of an earlier activation when a later statement fails, rollback of a release with a later invalid force, original impulse/source behavior, same-profile imports and rejected older-to-newer import edges. The Agent layer must also execute invalid/stale edits, idempotent retry, source-authorized mass/force/duration repairs, unchanged siblings and libraries, independent protocol stores, reset and exact artifact retrieval. These checks are not satisfied by this adoption record.

GLB/0.5 must retain source-built geometry, PBR and placement; account for nested force history in both construction and byte validation; reject float32 boundary collapse; conservatively sample translational acceleration and inherited angular motion; and pass independent format, decoded intermediate-pose and reviewed browser checks. No GLB/0.5 implementation or live destination physics is claimed here.

The next implementation checkpoint is the source 0.5 parser/compiler and bounded analytical evaluator, with all 56 actual source cases exercised. F09–F12 remain separate unfinished release requirements until their concrete Agent/destination/evidence work is executed. The complete product scope in GOAL remains unchanged.
