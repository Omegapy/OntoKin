# Experimental semantic export contract

**Identity:** ontokin.semantic-export/0.1  
**Finite profile:** construction-primitives/0.1  
**Date:** November 11, 2026, America/Denver  
**State:** Explicit experimental sidecar; integration and executed validation are recorded separately.

## Purpose and existing representation

A semantic export preserves what named parts mean alongside their delivered geometry. This contract supplies a JSON sidecar for one existing construction profile. Accepted .ok source remains authoritative; the sidecar cannot reconstruct or replace it.

The implementation reuses the normalized SceneModel, ObjectModel, SiteModel, JointModel and FollowModel records in [model.py](../../../ontokin/model.py). [construction.py](../../../ontokin/construction.py) already resolves typed parameters, stable identities and original definition/occurrence source locations. [scene.py](../../../ontokin/scene.py) already supplies checked program metadata, primitive geometry and baked world transforms. [gltf.py](../../../ontokin/gltf.py) already writes and reads GLB/0.2 and validates actual geometry, metadata and sampled animation against the source model.

The missing contract is a portable, versioned projection that binds those supported declarations, including sites and authored placements, to exact GLB node/mesh/primitive/accessor references. No parallel intermediate representation, source syntax, Agent protocol, exporter default or backend is added. The sidecar is generated by [semantic_export.py](../../../ontokin/semantic_export.py); no existing compiler, Agent or GLB implementation file is changed.

## Finite admission boundary

The producer accepts a complete valid construction-0.1 source bundle and existing ontokin.glb/0.2 bytes. The source must contain only box, sphere or empty geometry; prescribed objects with no_body and disabled collisions; hinge joints; existing rigid follows; move/tween actions; and start/stop events. Original compiler/source limits, default work budgets and GLB validation bounds remain unchanged. JSON sidecars additionally use the existing bounded JSON walker with a 4 MiB encoded ceiling, 100,000 logical entries and depth 128.

The selected GLB must cover the full declared source horizon and must have helpers=false. Partial playback intervals and visual helper nodes are rejected explicitly as unsupported by this small profile. Rejecting an otherwise valid older GLB here does not change its existing export contract. This profile does not admit rigid-body motion, contact, impulses, forces, torque, richer surface profiles or new relationship kinds. Unsupported declared source features reject; they are not silently omitted.

The keyed-rack fixture fits this boundary: 18 objects, 34 sites, eight hinges, eight follows, two actions, one event block and two source units. The fixture's no_body declarations do not imply inferred matter, simulated mass or live destination physics.

## Producer and verifier

The explicit Python entry points are:

    build_semantic_manifest(bundle, glb_bytes,
                            accepted_program_revision=trusted_revision,
                            required_features=())

    verify_semantic_manifest(manifest, bundle, glb_bytes,
                             accepted_program_revision=trusted_revision,
                             required_features=None)

The bundle is either the existing immutable ProgramBundle or its exact inline payload. The producer reloads its source bytes, verifies the expected revision, recompiles them at evaluated level, admits the finite profile, and runs the existing source-to-GLB validator on the actual delivered bytes. It checks the existing GLB program map against compiler provenance and extracts actual geometry/animation references. It never edits accepted source, artifact bytes or Agent state.

**Acceptance authority remains external to this pure API.** The required revision argument binds the exact source identity supplied by a trusted caller. An arbitrary string, a manifest field or successful recompilation does not prove that an Agent accepted that program. The accompanying proof records actual acceptance and failure atomicity through ProgramAgentService. Consumers must retain that evidence or their own trusted accepted-state record.

The verifier recomputes the entire canonical sidecar from exact source and GLB bytes. Changed semantic values, missing objects, altered requirements, stale source/GLB combinations and broken geometry references reject. Consumers with their own feature requirements must pass them explicitly; omitting that argument verifies the manifest's declared list, not an unstated external policy. This is integrity and consistency checking, not a cryptographic signature or hostile-storage authentication scheme.

## Content and units

| Record | Retained meaning |
| --- | --- |
| Binding | Expected accepted program revision, complete source manifest, source IDs, exact dependency versions/hashes, and exact GLB SHA-256 and byte count. |
| Object | Stable occurrence and nominal definition IDs, source path, owning occurrence, resolved typed properties, normalized primitive dimensions, source appearance, declared placement, physical declaration and initial motion values. |
| Provenance | Existing definition/declaration spans, source hashes, generated keys and collection/input origins. Original source bytes are delivered separately. |
| Site | Stable identity, owner, frame, local pose, interface, size and original source location, including system origin sites. |
| Hinge | Stable identity, parent/child sites, axis in the parent-site frame, angle limits, initial angle and source location. |
| Follow | Stable identity, parent frame, child object, rigid offset and source location. |
| Action/event | Existing resolved move/tween and start/stop descriptions, source locations, exact canonical times, velocities or hinge goals. These are metadata only. |
| Geometry binding | Actual node, mesh, primitive, material, accessor and buffer-view indices; accessor type/count/component type and SHA-256 of actual strided element bytes. |
| Motion binding | Actual animation channels/samplers/accessors, initial world pose and exact accessor-data hashes. |

Canonical source quantities use SI: metres, seconds, radians and kilograms. Geometry stays object-local. Source rotations use WXYZ quaternions; GLB rotations use XYZW. The existing right-handed, +Y-up mapping remains unchanged. The manifest separately records source duration and delivered interval.

Ownership, placement, following and mechanical connection have distinct fields. No ownership edge becomes a GLB parent. Every delivered object remains a scene root with its already evaluated world pose. OntoKin's existing evaluator owns reference motion; the receiving application owns any future runtime behavior. Preserved hinge constraints and gravity are not executed by GLB.

Source linear RGBA is retained alongside actual GLB material values. Metallic zero and roughness 0.7 are identified exporter defaults, not newly inferred material physics. Geometry content hashes exclude numerical index locations but include actual attribute/index bytes and material values. This permits an unchanged sibling's content to be compared even when array indices change after an edit.

## Machine-readable feature treatment

Every output has a features array. Each row gives a stable feature ID, treatment, reason and required Boolean. The allowed treatments are preserved, approximated, baked and unsupported.

| Feature IDs | Treatment and limit |
| --- | --- |
| source_closure, stable_identities, dimensions_units_frames | Preserved as exact supported source identities and normalized records. Source code is still required for reuse. |
| ownership, following, hinge_constraints, physical_declarations | Preserved as separate semantic metadata. No destination executable behavior is claimed. |
| materials | Source RGBA and actual GLB PBR values preserved; exporter defaults identified. |
| primitive_geometry, numeric_precision | Approximated: finite sphere tessellation, triangles and binary32 representation. Source dimensions and exact times remain available separately. |
| world_motion | Baked: the existing sampled translation/rotation tracks over the full interval. |
| action_execution, live_physics, source_reconstruction | Unsupported: declarations are not an executable program, simulator or complete source archive. |

A required unsupported or unknown feature rejects with OKS-E-UNSUPPORTED and its reason. Required feature IDs mean the treatment specified in this version; requiring world_motion accepts baked motion and does not request live execution. A consumer needing exact curved surfaces or live physics needs a different contract. A successful metadata export does not establish Unreal, Blender or other destination support.

## Deterministic comparison

Same exact source bundle, implementation, GLB export settings and environment must produce identical GLB bytes for this proof. Sidecars compare as UTF-8 JSON with lexicographically sorted object keys, unchanged array order, compact separators, finite numbers and no timestamps/request IDs. The source and artifact hashes are included. The rule does not promise identical output across future implementation or numeric-environment versions.

After a successful edit, program/source hashes and revision-bound provenance are expected to change. Stable IDs and semantic values are compared separately. The proof excludes only each object's provenance and numerical geometry/motion reference locations from its semantic equality check, then independently requires equal geometry and animation content hashes for every unrelated object. Site source locations are compared separately from site values.

## Executable proof and checks

From the repository root, choose a new output directory:

    python3 tools/build_semantic_export_demo.py --output-dir /tmp/ontokin-semantic-c210
    python3 -m unittest discover -s tests -p 'test_semantic_export.py' -v

[The driver](../../../tools/build_semantic_export_demo.py) uses a derivative of the unchanged keyed-rack fixture. Its starting override is 0.65 m; a valid scoped edit restores the frozen 0.75 m value. It discovers the pinned Finger definition, creates and exports accepted source, obtains the public initializer target through inspection, rejects an edit with kilogram units, retries it, and verifies accepted source/artifact preservation. It then applies and retries the valid edit, rejects changed-payload reuse and a stale-revision edit, and exports the accepted result. A new Agent store regenerates identical GLB bytes and canonical sidecar bytes.

All 18 occurrence identities must survive. Only the selected Finger's resolved length and its blade's geometry/placement consequences change. Sixteen unrelated objects, including the entire eleven-object second rack, preserve semantic values and delivered geometry/animation content. Only the selected blade's base site changes its local pose. Declared joints, follows, actions and event values remain unchanged.

The before and after bundles, .ok files, GLBs, export reports, sidecars, references, compact actual Agent transcript and proof checks are saved together. Artifact chunk base64 is omitted from transcript summaries; exact assembled GLB bytes and chunk hashes/sizes are retained. The frozen expected.json remains untouched. Its before-reference adjustment changes only the selected blade length and shifts that blade's world center by its frozen world rotation applied to (-0.05, 0, 0) metres. Seven frozen observation times and every other object's independent expectations remain unchanged.

Focused tests add stale source/dependency bindings, actual corrupted GLB geometry, altered sidecar values/references, external requirement enforcement, full-interval admission, helper rejection and callback interruption. Separate independent review, Khronos/Three.js loading/numerical checks and visual inspection remain required evidence. The driver does not claim those checks passed by writing a sidecar.

No C201 native admission, Unreal plugin, second backend, new language syntax, author study or model training is part of this contract.
