# C179 · Qualifying the rotary repair comparison

Can the same agent repair and reuse a moving mechanism in OntoKin and in direct Blender/Python? Both editable starting projects now reproduce the frozen five-part rotary indexer. They use a two-second quarter turn in metres. The north guard intersects the moving shoe between the sampled presentation poses.

An independent reader decoded each GLB's triangles, node transforms and quaternion animation. It checked cuboid faces, dimensions, five part identities, colors, static guards and continuous motion. It computed each guard's limiting angle and independently checked mesh poses on a 1 ms grid, at key times and at the interior extrema. All three starting GLBs gave the same two minima to 0.001 mm.

| Guard | Minimum signed clearance | Time after the turn starts |
| --- | ---: | ---: |
| East | +18.953 mm | 0.142640 s |
| North | −7.047 mm | 1.857360 s |

The negative sign means the shoe penetrates the guard. The first Blender export matched both endpoints but eased between them. Its peak rate error was 42.227 degrees per second. Setting the authored keys to linear reduced that error to 0.000567 degrees per second. Both final native exports rebuilt byte for byte. Khronos Validator reported zero errors or warnings on each.

The independent checker passed 13 private geometry and motion controls. The scorecard also passed five controls covering valid evidence, missing information and incorrect declarations. The control scores qualify the scoring code. Agent repair quality, retries, time and cost remain unmeasured.
