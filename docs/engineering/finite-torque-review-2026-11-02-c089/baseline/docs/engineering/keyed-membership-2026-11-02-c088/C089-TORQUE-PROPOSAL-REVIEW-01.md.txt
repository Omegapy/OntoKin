# Independent C089 proposal review

**Accepted as a proposal for a separate contract and utility review. No torque implementation or adoption is authorized by this review.** The reviewed NEXT-TASK draft is bound by its exact hash in the companion JSON receipt.

The proposed free homogeneous sphere torque increment is useful. A continuous external torque gives an agent a physical spin-up or braking interval with changing angular velocity, beyond the current instantaneous impulse and prescribed visual rotation inputs. Two reusable occurrences with an asymmetric visual marker provide a concrete targeted repair task. This is a qualitative scope judgment; no measured authoring improvement is claimed.

I recommend the fixed-axis collinear scope first. For scalar sphere inertia and one fixed axis, signed angular speed is affine and signed angle quadratic between true event boundaries. For a general initial world angular velocity and a noncollinear constant angular acceleration, the generators at different times do not commute: omega(t1) cross omega(t2) = (t2-t1) (omega0 cross alpha). The draft correctly refuses the integrated-vector quaternion shortcut outside the collinear domain.

## Decisions to make before adoption

1. **Close the axis domain under the actual number representation.** Specify axis selection, persistence through zero and reversal, cancellation, whether every active input or just net torque must align, and when an axis can change. A persistent signed scalar representation is a reasonable first direction. An exact predicate applied to independently rounded public components can otherwise reject a previously valid trajectory. These choices belong in the contract and original negative corpus.
2. **Keep pure torque from changing translation through anchor rounding.** Current force runtime advances translation and constant-spin rotation from one complete dynamic anchor; linear acceleration changes reanchor that complete state. A torque-only boundary must preserve the independent translational trajectory and its canonical rounding behavior, even with gravity or a COM force active. Separate anchor semantics, zero torque, cancelling overlap and same-net replacement need explicit controls. See `ontokin/force_runtime.py`, especially the dynamic trajectory and aggregation functions.
3. **Extend the actual recording proof.** `ontokin/force_export.py` explicitly assumes constant angular contributions and checks translation chord error plus angular travel. Torque adds angular acceleration. For ideal fixed-axis short-arc SLERP, the angle interpolation error is bounded by |alpha| dt²/8; source numeric, actual interpolation and quaternion/time quantization errors remain separate. Keep the anti-alias angular-travel bound and test reversal with equal endpoint orientations but real interior motion. A convincing screenshot or endpoint match cannot establish that bound.
4. **Keep the representative physical meaning narrow.** Make the asymmetric marker massless visual geometry or `no_body` visual descendants. Use only the carrier's own homogeneous sphere mass and inertia; visual shape must not silently become a compound body. The input is an external couple, with no added COM force, joint motor, reaction body or contact claim.
5. **Name the unit convention and transaction rules.** `Torque` and `Inertia` aliases already exist, while Angle has its own type dimension. The physical operation must state its SI-radian conversion convention without changing generic dimensional arithmetic. Freeze exact clocks, canonical net torque/acceleration rounding, finite bounds, impulse ordering and axis-refusal precedence, complete-boundary rollback, source-file patch scopes and current request authority before implementation.

The draft preserves the complete GOAL, the retained gates, manual hosted execution policy, separate adoption and independent input freeze, predecessor controls, publication/readback and actual named destination evidence. Those are appropriate prerequisites. The remaining questions above are future contract decisions, not permission to weaken an earlier gate or to start a torque runtime in C088.
