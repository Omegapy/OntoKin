# Recording arithmetic within the existing request budget

This implementation continuation keeps the adopted 100,000-operation request
limit, the 256-entry numerical cache, source requirements, exact clock policy,
and complete supplied-byte inequalities. It is not a new tolerance or a release
acceptance record. [Issue 26](https://github.com/Omegapy/OntoKin/issues/26) and
[draft PR 27](https://github.com/Omegapy/OntoKin/pull/27) identify its ownership.

## Removed repeated work

The Agent records the successful source-prefix observations and phase anchors
from its one actual evaluation. A retained plan is accepted only for the same
model object, same request work, requested endpoint and complete boundary/phase
shape. A failed prefix cannot finish a plan. Direct exports retain their own
ordinary prefix planner. Recording samples omit unused derivatives; boundary,
release and rate observations continue to evaluate them.

Pure numeric reuse retains immutable answers in the original charged cache.
Keys include all numerical operands, and caller identity/coverage/clock data are
checked separately on every output row. Operands are bounded before keys are
built. Lookup, promotion, insertion and eviction retain the original cancellation
callback. The independent reference and supplied-byte checker use separate key
namespaces and independently derived answers, never writer certificates as
their source oracle.

The JSON preflight can reuse the encoded size of a bounded repeated object-key
shape. Every value, occurrence, logical entry, nesting depth, cycle and total
encoded-byte limit is still checked. Only the repeated Unicode scans of the
same field names are omitted. The cache belongs to the same request and cannot
extend either numerical work or the cache-entry maximum.

## Conservative groups of interval certificates

Every adjacent key pair and carrier still has its own complete certificate.
Rows with the same source phase and enclosing phase set can share conservative
numeric fields. The writer visits every actual source/stored endpoint and takes
the maximum position-conversion error, quaternion-conversion error, translation
magnitude, authored width and endpoint clock shift for that group. Source
numeric bounds include the union of required endpoint phases. Grouping changes
neither actual clocks nor required source phase coverage.

All coefficients in the adopted complete error formulas are nonnegative.
Replacing each input by a group maximum therefore cannot understate any member
row, even if the maxima occur in different intervals. Primitive bounds are
rounded outward before recomputing dependent totals from those rounded values.
Both authored and actual stored quarter-allocation plans and final requested
tolerances remain binding. The independent checker still compares every actual
key, boundary, source identity and geometry occurrence, then checks complete
inequalities against the actual supplied values. Pure successful algebra can be
reused only for identical checked inputs. Width is removed from a cache key only
when every coefficient using that width is exactly zero.

The independent reader additionally aggregates rows with identical supplied
numeric fields in batches of at most 64 groups. It constructs these groups
from the actual supplied quantities, without reading the writer's grouping.
Every row retains its own identity, exact clock, phase coverage and actual
endpoint comparison. Every member's independently derived lower bounds,
authored/stored widths and destination magnitude contribute to group maxima.
A constant supplied quantity dominates every member exactly when it dominates
their maximum. The complete inequalities are monotone in both positive widths,
so proving them for the maximum widths proves every row. Groups are checked and
discarded at the fixed batch bound; no unbounded numeric reuse cache is added.
Changed payloads form separate groups, and later members cannot inherit a
verdict that omitted their endpoints or phase bounds. Destination-domain and
quarter-allocation failures remain binding even when introduced by a later row.

For nonzero quaternion vectors a and b, the normalized difference is bounded by
2 times their raw difference divided by the norm of a. A verified source norm
of at least one half therefore permits the bound 4 times the raw difference.
A zero stored quaternion is rejected. The general normalized calculation
remains the fallback for smaller source norms. The existing source rotation
allowance and normalization allowance are retained separately.

Endpoint conversion uses an exact L1 upper bound for the source-to-binary32
differences. The same finite-conversion subtraction argument used for geometry
avoids decoding both sides and subtracting arbitrary-precision fractions at
every key. A quaternion component of magnitude at least one half establishes
the required norm lower bound directly; otherwise the guarded exact squared
norm is still evaluated. The L1 bound is conservative for the Euclidean norm,
and complete tolerance checks remain unchanged. The independent checker still
normalizes actual stored bytes and compares them with independently derived
ideal orientation intervals. It selects one antipodal reference using the
largest stored component's sign. Either representative gives an upper bound
for physical orientation error; an ambiguous sign can only make that bound
larger. No endpoint comparison is omitted.

For unit endpoint chord error e at most one half, the corresponding S3 arc is
at most 2e. The ideal path length is at most angular-speed times authored-width
divided by two. Adding 4e covers both endpoints and also bounds their stored
chord c. The writer then applies the monotone rational envelope
`c / (1 - c*c/4)`, matching the independent checker's outward chord-to-arc
criterion. A true-arc bound alone can be smaller than that outward criterion;
the first grouped prototype exposed precisely that mismatch and its failure is
retained. The chord and arc domain checks remain mandatory.

Independent geometry reconstruction can use an L1 radius and the Euclidean
norm of the three maximum axis-conversion errors. These are conservative bounds
for every actual local vertex and promised site. All actual vertex conversions,
topology, material identities and aggregate repeated-occurrence limits remain
checked against source. No source geometry or native buffer is substituted.

The reader finds these same exact geometry extrema without rationally decoding
every coordinate. Every vertex first passes the actual finite binary32
conversion comparison. For a source binary64 value x and its nonzero rounded
binary32 value y, the magnitudes have the same sign and ratio between one half
and two, including the first binary32 subnormal and ties. Their binary64
subtraction is exact by Sterbenz's lemma; when y is zero the difference is x
itself. The three maximum absolute errors can therefore be selected as floats
and decoded exactly once. Non-float source inputs use the original rational
calculation.

The radius remains the maximum exact L1 sum, without enlarging it to a box
bound. Two nonnegative binary64 additions, each followed by `nextafter(+inf)`,
provide only a screening upper bound. A candidate is skipped only if that upper
bound cannot exceed the incumbent rounded downward. Every possible larger
candidate receives its full guarded exact sum. This preserves the original
radius and key plan, including sums whose nearest binary64 rounding lies below
the true rational value. Every point retains its cancellation/work checkpoint,
and the existing topology, conversion and PBR checks remain unchanged.

## Evidence limits

The original development prefix artifact completed at 90,381 shared operations
and subsequently passed actual native and browser checks for that identified
implementation. Subsequent changes require fresh artifacts because numerical
basis hashes identify their implementation and derivation bytes. Development
probe failures, source patches and exact input hashes are preserved separately;
they are not relabeled as final clean-commit acceptance. Full recordings, all
Agent delivery cases, the full source/Agent artifact corpora, compatibility and
the complete release audit must pass before integration. The full product goal
remains open.
