# C257 integrator structural review plan

Scope: the new finite ownership observer only. The independent reviewer owns
source/artifact numerical and mutation controls; this review checks the
implementation boundary and refusal/resource handling after a frozen candidate.
No findings or passes are claimed by this plan.

Review the following against the actual code and execute a probe only when
it resolves a concrete remaining risk:

- Actual `.ok` token/byte origins and module visibility determine containment.
  Follow, hinge, transform and display-name data must not create ownership.
- Supported keyed literals and direct helpers remain explicit. Unknown
  ownership-affecting forms, ambiguous definitions, duplicate keys and cycles
  must refuse instead of producing a partial graph labeled complete.
- Full occurrence and definition identities, source closure and program hash
  remain distinct. Artifact claims must agree at every admitted location.
- Raw observations remain untrusted; comparison is ownership-only; exact
  historical admission is separate. No complete C255 semantic, runtime,
  revision, rebuild, release or native qualification appears by implication.
- Bound total bytes, tokens, collection size, expansion depth, occurrences,
  metadata count and all numeric conversions before allocation or recursion.
  Check duplicate JSON keys, nonfinite values, wrong types and integer/bool
  ambiguity where these can affect identity or owner records.
- Fixed endpoint file reads remain bounded. Do not read an arbitrary closure,
  invoke product evaluation, import expected semantic answers, or execute code.
- Retain failed probes and exact input hashes. Re-run only affected controls
  after a concrete correction, then verify input equality for reused evidence.

Integration separately verifies the changed-file inventory, unchanged runtime,
historical source/expectations/workflows, relevant C256/C255/C253 checks,
documentation preservation, actual main and completed branch deletion.
