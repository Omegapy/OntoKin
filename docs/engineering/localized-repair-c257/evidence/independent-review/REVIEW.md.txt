class part and generated-part declarations. The source evidence contains
the exact declaration/key byte spans, including the helper's three keys and
the second rack's five-key override. Neither C255 expected semantic records
nor a producer sidecar supplied these observations. The baseline utilities
import no project module or expected-source helper.

Both original endpoints contain 18 source object occurrences: two scene roots,
eight generated fingers and eight ordinary blades. Their 16 ownership edges
match independently traversed GLB node owners, node source-mapping owners and
program occurrence owners, with full occurrence and separate definition IDs.
All 18 GLB nodes are scene roots. That distinct count confirms why transform
hierarchy cannot supply the source ownership graph.

A supported containment mutation moved the blade declaration from Finger into
Rack, using an explicitly public, qualified imported class and updated source
digest. The independent changed graph contains 12 objects, two roots and ten
edges. Original artifact comparison refuses. A separate mutated GLB, built
from directly inspected source spans and artifact records without the reader's
output, agrees with the changed graph. This demonstrates actual changed
ownership observations beyond historical hash admission. It does not qualify
the synthetic artifact's unchanged geometry or other relationship claims.

Source/metadata origins resolve to the actual supplied bytes and JSON locations.
UTF-8 comments retain correct byte offsets. Stable root, ordinary-part,
generated-key and definition-key changes produce the relevant identity changes;
reordering keyed entries leaves surviving identities intact. A literal dotted
key remains one key. Frame, follow, hinge and transform decoys do not become
ownership evidence.

## Findings and corrections

The first exact candidate, `055d1e83f33586e488a35961d29f405b2884beea`, passed
85 of 90 controls. Five failures were observed and retained:

1. A module class without explicit visibility was incorrectly treated as private.
2. A module function without explicit visibility had the same error. The adopted
   construction contract defaults module visibility to public.
3. A floating-point source byte offset passed integer-span comparison.
4. A contradictory source-mapping class identity was ignored.
5. A contradictory program source revision was ignored despite the source
   association claim.

The corrected `c415fd752def78524cc1a8520e42887570933ff4` passed the original
90 controls and 16 relevant added checks. These cover symmetric source/span/
identity claims, new source-authority origins and planned key-order invariance.
The source binding now checks both source units and duplicate entry/module/
scene/profile authority fields coherently.

The main agent's separate structural review then found an uncaught filesystem
`OSError` in the public bound-file API. Final candidate `499a19d0` adds explicit
`Fault("IO", ...)` normalization. The reviewer reran all 106 controls on that
changed source and added an actual too-long filesystem path call in the hosted
workspace. All 107 passed. The initial I/O failure remains in the parent's
structural-review evidence; this directory records its final independent pass.

`attempt-01` retains the original reviewed reader, all results and concrete
failed input files. `attempt-02` and `attempt-03` separately bind their actual
commits, trees, reader/harness hashes, interpreter, commands and logs. No failed

## Refusal and qualification boundary

Controls cover missing or contradictory owners, identity swaps and duplicates,
unknown definitions/owners, malformed metadata shapes, duplicate JSON keys,
large integers/deep JSON, source/GLB/node limits, unsupported ownership inputs,
composition cycles, import/private access, exact historical admission and
public file-I/O failure. Root null owners must be explicitly present.

Successful output remains partial: complete source validity is false; complete
C255 semantics and execution permission are false; trial success is absent.
Follow, hinge, pose, geometry, physical parameters, actions, accepted revisions,
clean rebuilds and invalid-edit atomicity are not qualified by this review.
The finite public family does not establish general comparative advantage.

No reviewer source edits, native application launches, model trials or remote
repository mutations occurred. This approval does not substitute for the main
agent's applicable authored/prior/documentation checks, integration ownership,
live merge verification, branch cleanup or confirmed saved handoff.
