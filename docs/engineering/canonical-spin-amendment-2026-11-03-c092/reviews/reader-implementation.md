## Exact canonical reader dataflow

`torque_axis_exact.py` implements the source point selector independently of
the producer. Its only selector operands are the admitted canonical angular
vector and actual elapsed time. It walks the original precision schedule
`(96, 192, 384, 768, 1536)` in order and selects the first completed guard that
certifies. The guard uses the exact scaled-axis square-root enclosure,
independently computed Machin-pi enclosure, and the adopted argument-error
formula, including the existing `2^-97` term and `2^-86` threshold.
Only a completed negative guard comparison advances to another stage.
Arithmetic/domain/resource failures propagate. Failure of the subsequently
selected reduction is terminal. Neither a whole-phase producer plan nor
agreement among every eligible plan can choose the canonical source result.

The independent replay of the unchanged exact module covers all 30 frozen
signed stage-transition rows, equality and final exhaustion, five exact pi
bounds, six rounding ties, the original zero-axis witness, the discriminating
force-origin quaternion, and a malformed selected-reduction control. This is
separate from the original 14,172-check reference gate. The general algorithmic
argument is the ordered exact comparison and the authority's guard-to-reduction
lemma; finite replay is supporting evidence rather than a claim to exhaust all
supported operands.

`torque_axis_reference.py` retains complete canonical origins: exact quaternion,
exact angular velocity, source time, frozen publication projection, and full
rotation error. `frame_support` iteratively visits the admitted source graph,
including sites, follows, rigid/grip dependencies, hinges, sliders, and root
sources. It composes canonical rotations and transformed angular vectors with
the inherited projective product and vector grid. It introduces no smaller
recipe-depth ceiling. Its retained graph values are bounded by the admitted
source graph and original charged arithmetic.

The lifecycle review covers these distinct cases:

- Prescribed spins use accumulated running action time; pause time is excluded.
  A paused operation keeps the original rotation origin rather than reseeding
  from a sampled quaternion.
- Dynamic legacy evolution uses elapsed time from the complete canonical
  source origin. The split torque law uses its exact source polynomial and
  canonical scalar rounding, with its existing finite phase domain.
- Release materializes the complete dependency-derived incoming source state
  in the inherited order. Spin completion creates the specified public origin
  and retains its already frozen projection on later materialization.
- Impulses independently reconstruct the transformed lever, cross product,
  inertia division, and canonical angular vector. Zero impulse is neutral in
  every route. A nonzero unchanged-angular impulse preserves the source origin
  only after the split law exists; the legacy route still performs inherited
  complete materialization.
- A force boundary with unchanged canonical acceleration moves only the
  separate reference/error clock. It retains the whole old canonical source
  origin. A real acceleration change follows the inherited source materialization
  rule. The split COM and rotation origins remain distinct.
- Slider identity rotation still passes through its actual canonical product
  and final angular grid. An identity-looking relationship is not removed when
  that rounding would matter for a materialized parent.

`torque_reference.py` uses support derived from those exact canonical values to
admit an axis. A wide interval is never treated as an exact zero proof. A true
nonzero off-axis component refuses even if tiny. Conversely, independent exact
cancellation is admitted instead of being refused because a conservative
interval crosses zero. The separate smooth ideal trajectory, complete upper
transfer uncertainty, and independently required lower error allowances retain
their original roles. The axis/product/exposure constants remain `2^-74`,
`2^-91`, and `2^-50`; the canonical source vector grid remains 96 bits.

The new reader does not import the producer plan selector. Its bounded private
arithmetic cache stores independently computed pure operands and re-admits the
live operand domain. It is not the caller's shared `work._cache`. The unchanged
complete validator still checks both the original and detached source through

## Point cache and callback authority

The producer helper uses the original admitted work object, original callback,
original counters and clock, and one existing LRU. It places immutable native
tokens in a distinct point namespace. A cache value is accepted only when it
has the exact completed-entry ownership identity and matching point key.
Callback-written replacement entries cannot establish numerical provenance.
Unpacking reconstructs detached arithmetic objects from already owned native
tokens. The final point admission remains before returning a result.

The cache-capacity defect discovered on Candidate01 is closed in the reviewed
code: admission requires a native integer capacity in `1..256` and an actual
cache length no larger than that capacity before traversing ownership metadata.
Entries evicted from the single LRU are removed from the metadata catalogue.
Original operand watches include mutable Fraction slots, lists and complete
RotationValue/SpinPlan fields. Stationary operations retain the actual complete
admitted origin, including its frozen projection and error allowance.

The current helper/runtime seal checks raw runtime class resolution before
ordinary instance attribute lookup. It retains MRO/base identities, original
method descriptors, storage providers, every earlier witnessed absence, and
instance method-shadow absence. The common exact class uses compiled native
mapping reads; supported subclasses retain complete effective-MRO resolution.
A newly planted descriptor in an earlier namespace cannot hide behind a later
original provider. Helper class descriptors are checked before scope fields.

After each original callback returns, a private immutable request receipt uses
captured native operations to check helper functions and bindings before calling
any mutable public helper entry. Constructor bootstrap is captured at import,
so a source-preflight callback cannot replace the first trusted helper alias.
The subsequent full runtime and native context checks retain the original
source, work, ledger, event order, object owners, limits, callback, clock and
accepted-state identities. Original callback exceptions keep their precedence.
This remains an ordinary source/callback ownership boundary, not a sandbox
against arbitrary interpreter memory or private receipt-cell replacement.

### Reviewed performance reductions

The final repair changes traversal cost without changing live predicates:

1. Duplicate runtime global bindings are compiled once per exact native
   `(mapping identity, key)`. All original records remain strongly owned.
   PRESENT keys use native lookup and `is_`; ABSENT keys require native
   containment to be false. A fresh fallback cannot equal any original value,
   so deleting a present sentinel or planting the canonical missing sentinel
   cannot disguise a binding change.
2. Native `all(map(operator.is_, ...))` compares object identity without
   allocating an integer identity token for each repeated field. Strong
   references to every original function, code/default/closure object and
   binding value remain in immutable raw receipts. No foreign equality runs.
3. Native FunctionType class, globals, closure and builtins pointers are
   read-only under the existing ordinary-Python boundary. Actual assignment,
   deletion, object-level access, instance shadow, immutable-type and subclass
   probes passed 28 checks each on CPython 3.11.17, 3.12.14 and 3.13.16.
   Every callback still freshly checks the three mutable function slots:
   code, defaults and keyword-defaults. Keyword dictionary length/order and
   every key/value identity remain checked, as do global/builtin contents.
4. Only duplicate checks with no intervening callback are combined. Public
   context admission remains complete. The private guard checks the helper
   entry receipt before its captured after-entry function performs helper
   class and full runtime admission. PointScope performs full helper/primitive
   authority first, then captured public context once, then all work/cache/
   operand checks. Cache lookup retains admission after the original charged
   parent lookup; only the duplicate admission following callback-free owned
   token unpacking is removed.

Complete Fraction descriptors/slots, numeric functions, math/struct bindings,
class members, original charges, stage decisions, errors, limits, and final
admission remain. There is no time-based freshness shortcut, callback skipping,
new budget, or persistent positive authority cache.
