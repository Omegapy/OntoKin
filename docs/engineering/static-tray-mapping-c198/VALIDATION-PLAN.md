This plan is the independent acceptance boundary for the finite two-tray mapping in [SPECIFICATION.md](SPECIFICATION.md). ## 1. Execution gate and evidence ownership

C198 permits zero native exports, native simulations, receiving jobs and timed authors. The next implementation task can qualify the adapter only after an independent reviewer seals an immutable executable input lock. The lock must bind the actual compiler closure, two source frontends, shared constructor, independent reader, corruption writer, lifecycle supervisor, receiving probe, all source/expected fixtures, settings and transitive dependencies. A planned filename or placeholder hash cannot satisfy this gate.

The compiler/lowerer author must not approve the independent reader by inspecting only producer-generated expectations. A separate reader implementation reads delivered geometry. Its expected fixture measurements are hand-derived from the exact decimal constants here and the adopted mathematical definition. Canonical binary64 arithmetic follows SPECIFICATION exactly; no host-dependent intermediate float evaluation may redefine it. The reader may use the Python standard library; it must not import, execute, copy-generated lookup tables from, or call the producer lowerer, native constructor or their geometry helpers. The common frozen specification and ordinary JSON/GLB format knowledge are shared inputs, not a shared geometry oracle.

Each result names the exact implementation commit and tree, input-lock SHA-256, fixture ID, native slot, route, raw/final artifact hashes, reader hash, command, interpreter/platform and actual outcome. Retain failures and partial evidence. No success label for a contract, schema or synthetic input stands in for native qualification. Read-only post-result review may occur later with no worker running; the 65,000 ms ceiling applies to each actual qualification transaction and its mandatory receiving/promotion path.

## 2. Source and canonical-record controls

Use the existing `construction-0.1` compiler and the exact `main.ok`/`tray.ok` pinned dependency closure. Direct Python uses exactly `main.py`/`tray.py`; no extra local import is silently admitted. Each route has a 32,768-byte cap per source unit and 65,536 bytes total, with at most 32,768 bytes for the canonical record. Its direct-source identity follows the separate source-manifest algorithm in SPECIFICATION. Exercise actual source compilation and each route's production validation boundary. The canonical record is validated strictly against the schema plus the semantic restrictions and stage order in SPECIFICATION. CONTROLS expands test expectations within that order; it cannot replace the source compiler's diagnostic semantics. Require exactly fourteen delivered nodes: two empty roots and twelve named mesh children, six under each root in canonical order. There is no wrapper node. Reject unsupported features before Blender starts. Reordering valid source declarations must preserve occurrence identity and canonical geometry; changing source spelling or units can change provenance while preserving geometry.

The machine-readable controls enumerate malformed numbers, ranges, identity/ownership/follow mistakes, extra placement authority, unsupported physics/motion/geometry, wrong pin closure, noncanonical encoding and corner overlap. Real scalar strings contain exactly sixteen lowercase hexadecimal digits representing the eight big-endian IEEE-754 binary64 bytes; Python `float.hex()` text is not this encoding. Preserve the specification's explicit per-operation nearest-even rounding and expression trees. Positive zero, finite-domain checks and exact canonical bytes are mandatory. Boundaries use the immediate binary64 predecessor/successor of each admitted scalar boundary. Test all twelve allowed exact root orientations without launching Blender. Positive source controls also exercise each sign-reversed equivalent literal quaternion: the existing compiler must produce the same canonical orientation. Reject unsupported orientations; do not project, snap or silently approximate them. The source compiler's existing semantic error remains authoritative when it rejects earlier than adapter-specific checks.

## 3. Independent GLB reader

The reader operates on actual final GLB bytes and separately on the raw GLB when that is a distinct retained artifact. It validates the GLB header/chunk lengths, strict JSON, internal binary buffer lengths, accessor types/counts/stride/offset/bounds, triangle indices, scene graph and exact fourteen-node inventory. Each root has exactly the six mesh children `[back,base,front,left-wall,payload,right-wall]`; roots are scene children, and no wrapper is permitted. It rejects duplicate identities, cycles, extra scenes/meshes, sparse or compressed accessors, external resources, skins, morphs, animation, cameras, lights and other features outside this output contract. No external fetch is permitted.

Decode every POSITION value and triangle index; resolve each actual node's complete world transform. Dimensions in `extras`, accessor min/max or a source receipt are not measured geometry. Compute positions from the binary buffer, including any valid buffer offsets and strides admitted by the contract. Source or record metadata may identify the expected part; it cannot override its measured shape or position.

For each of the twelve part nodes:

1. Match its exact stable semantic ID, role, owner projection and fixed material with the contract. Enforce the fixed scene/hierarchy mapping. The canonical record separately retains explicit follows; GLB parenting is only the chosen static transform mapping, not evidence that ownership causes placement or that a live following relation survived delivery. Geometry with a missing or duplicate identity fails.
2. Derive the expected source-frame rigid transform independently from the frozen root pose and part equations. Convert decoded world vertices back into that expected local frame. Check actual world corners as well, so a locally correct box in the wrong place fails.
3. Prove a centered closed rectangular surface using the measured-box procedure below, allowing only the exporter's coincident normal splits. Compare that measured box with the independent expected placement/sizes as a separate check. A valid box with the wrong size must still reach clearance measurement; it cannot disappear behind a generic shape rejection. Reject missing, duplicate, internal or inverted surfaces. Compare full side lengths, face positions, signed volume and topology, not only the bounding box.
4. Verify the expected finite proper rotation and absence of scale/shear/reflection. Check that the source Y-up to Blender Z-up rotation and glTF Y-up return occur once. The rotation is `(x,y,z) -> (x,-z,y)` before Blender export; output is measured in the source Y-up metre frame.
5. Check tray-solid partitioning in each tray's local frame. Base interior is below the cavity floor, walls begin at it, front/back own the corner strips, and left/right terminate at the front/back inner planes. Shared faces are allowed; positive interior overlap above tolerance fails.

Measure cavity width/depth from the inward wall planes and cavity height from floor to rim. Measure both horizontal clearances on each X/Z side from actual payload faces. Verify payload bottom at the measured floor and payload top below the rim by the required headroom. The proxy remains a visible geometry measurement object; it adds no mass, collider, force or live physical claim.

### Exact measurement and topology rules

All checks use decoded binary64 host values of the actual float32 GLB data without display rounding. Transform into the independently expected tray frame. For each part, derive its **measured** local minima/maxima from all decoded vertices, then the eight candidate corners formed by those bounds. Let `delta = 0.000005 m`. Assign each vertex to the unique measured corner whose maximum componentwise distance is at most `delta`; reject an unassigned or ambiguous vertex. Every corner bucket must be present. In each bucket, choose the lexicographically smallest decoded coordinate tuple as its representative and require every member within `delta` of that representative. This defines geometric welding; it does not reuse a producer vertex table or average away an error.

After welding, require exactly twelve triangles, with three distinct corner labels per triangle. Each triangle must lie on exactly one of the six box faces. Each face must have two triangles whose union uses exactly its four corners and whose shared edge is one diagonal. Reject repeated triangles, degenerate faces, internal triangles and absent faces. Every welded edge, including the six diagonals, must have exactly two incident triangles. Compute each triangle cross product from actual decoded positions and require its dot product with the relevant outward face direction to be strictly positive.

Compute signed volume by the oriented triangle sum `sum(dot(p0, cross(p1,p2)) / 6)`, using exact rational arithmetic for the decoded finite binary values; round only the reported value. Require positive volume. For expected full sides `sx,sy,sz`, compare against `sx*sy*sz` with fixed allowance `(sx+2*delta)*(sy+2*delta)*(sz+2*delta) - sx*sy*sz`. This bound accommodates the already allowed corner displacements; it cannot replace the independent per-side/per-corner checks. A topology failure remains a failure even if its signed volume or bounds match.

Measure clearance using actual extrema in the tray frame: left `payload.minX - left-wall.maxX`, right `right-wall.minX - payload.maxX`, back `payload.minZ - back.maxZ`, and front `front.minZ - payload.maxZ`. Cavity width is `right-wall.minX - left-wall.maxX`; depth is `front.minZ - back.maxZ`. Floor is `base.maxY`. Check each wall top against its expected rim height, then use the minimum of the four measured wall tops for cavity height and headroom. Bottom gap is `payload.minY - floor`; headroom is `rim - payload.maxY`.

For every pair of tray-solid boxes, calculate the three intersection lengths from measured minima/maxima. Positive material overlap is forbidden when **all three** lengths exceed `delta`; shared faces and numerical overlap at or below this fixed threshold are permitted. The payload proxy is excluded from material accounting, but its required clearances and floor/rim placement are checked separately.

For a structurally valid artifact, collect all bounded measurement findings in stable semantic-ID/code order. Do not stop after an expected-size or pose mismatch when the actual geometry still supports the required clearance or sibling measurement. D01 must include `CLEARANCE`; D03 must include `SIBLING`, even when they also generate `GEOMETRY` or `FRAME`. Invalid GLB structure may stop dependent geometry checks, but that structural rejection cannot satisfy a control whose required finding is geometric.

### Fixed tolerances

Each dimension, signed clearance and world corner must differ from its independently derived expected value by no more than **0.000005 m (0.005 mm)**. A required minimum clearance/headroom is met only if measured value is at least the requirement minus this same tolerance. Rigid-transform matrix elements have absolute allowance **0.000001**; identity and semantic role matching is exact. These numerical allowances account for this finite float32 delivery path and are unvalidated design choices until C199 tests them. A failure requires a preserved result and reviewed version change; it cannot widen the tolerance in place.

The reader must expose each measured value, expected value, difference, threshold and classification. Near-boundary classifications remain tied to these rules. It must not round millimetres to display precision before deciding.

## 5. Delivered-content controls

Before accepting the reader, apply D01–D08 in CONTROLS to copies of actual retained accepted GLBs. Use a separately implemented corruption writer and retain before/after hashes and exact changed ranges. If a mesh/accessor is shared, fork its local buffer/view for the corruption so the intended unrelated sibling stays intact. Modified GLBs must stay structurally valid when the expected finding is geometric, rather than passing because parsing failed first.

The two required admission precursors are D01 and D02/D03. These controls specify required finding sets, not a race for the first generic diagnostic. D01 increases only the actual left payload X size by 0.004 m: each side gap changes from 0.005 to 0.003 m and the reader must reject insufficient clearance. D02 removes the actual right/base node; D03 moves actual right/front geometry by 0.002 m in its tray-local Z direction. The reader must reject the missing or changed sibling for the named identity/geometry reason. A false source annotation, changed JSON expectation or synthetic failure receipt does not satisfy these controls.

D04 preserves outer bounds but damages a face/interior surface, guarding against an AABB-only checker. Other controls corrupt frame mapping, identity and unsupported output structures. Unmodified copies must pass. Classification mismatch stops qualification; no new native build is needed to repeat a corruption diagnosis, and no changed artifact may be promoted as accepted.

## 6. Receiving implementation and visual review

Reopen each delivered artifact through the selected pinned Blender build in one clean receiver process with factory startup. That process first opens the retained `.blend` and measures its actual geometry, then clears the scene, imports the actual GLB and independently collects object identities, actual mesh vertices, world transforms, bounds and fixed materials. Both inputs belong to the same sealed candidate closure; the receiver cannot edit or export them. Compare those measurements with the independent reader within the same 0.005 mm allowance. A manifest or successful importer exit is insufficient. The importer must be from the same pinned distribution and recorded independently of the constructor process.

At most twelve receiving imports are permitted, one per native slot that produced a valid delivery. A receiving job may render at most one static review image. It must pass its required measurements before candidate promotion; later visual review and the complete control matrix remain overall profile-qualification gates. Use a 1024×768 orthographic Workbench view, solid material color, opaque objects, no overlays, ambient world background and a fixed isometric direction `(1.5,1.2,1.5)` from the expected scene center. Frame all expected geometry from independently derived expected bounds; record the exact camera/settings. A reviewer inspects the actual image for visible omissions, axis reversal, unexpected intersections and role/material distinction. Record findings without claiming a complete hidden-surface review from one image; geometry checks cover the hidden faces.

No saved-scene simulation, animation playback, contact or live destination physics runs belong to static tray qualification. An unavailable importer, render or reviewer is an unmet gate; it is not replaced by metadata or fabricated images.

## 7. Bounded process and atomicity controls

Ordinary source operations remain **100,000 operations / 30,000 ms**. C198 explicitly adopts one separately named **future qualification transaction host allowance of 65,000 ms**. This is an outer supervisor ceiling for the two-stage delivery pipeline; it does not raise the source's operation/time budget, change a historical gate or authorize a C198 run. The actual C199 input lock must record this requested/effective host allowance before launch.

A single monotonic transaction clock starts before source/preflight work and never resets. The construction stage, including source/record preparation, one native worker, independent GLB reading and sealing candidate artifacts, has its own **30,000 ms** ceiling. Successful construction records `BUILT_PENDING_RECEIVING`; it has not changed the accepted pointer. The one receiving process has a separate **30,000 ms** ceiling for native-scene reopen, GLB import, measurements and its optional static render. Only passed receiving checks permit conditional promotion, bounded at **3,000 ms**; cleanup has at most **2,000 ms**. The overall 65,000 ms deadline always wins, including time between stages. No stage starts if the remaining outer allowance cannot cover its declared limit. An earlier timeout or cleanup failure prevents the next stage and preserves the predecessor.

The native slot is consumed when the construction Blender process starts. Waiting for receiving or promoting the same candidate does not create a new export allowance. Receiver failures consume that receiver slot and cannot trigger a rebuild, another receiver or another export. If either stage or the transaction cannot complete, retain the failure and propose a reviewed version change before another attempt; no budget is extended after observing the failure.

The supervisor polls at most every 50 ms, terminates the process group on cancellation/deadline, waits at most 500 ms, then kills and reaps it. Cancellation completion is bounded at 2,000 ms after observation. Every phase remains charged to the unchanged transaction clock and its own stage limit; a worker cannot reset either clock. Native output is capped at 64 MiB per attempt, each GLB at 8 MiB, captured logs at 4 MiB, and structured results at 4 MiB. Reject paths outside a newly created staging directory, symlinks to accepted storage and any attempt to replace an existing immutable object.

Use append-only attempt records with nonterminal states `RESERVED`, `STARTED`, `BUILT_PENDING_RECEIVING`, `RECEIVING`, and exactly one terminal state: `ACCEPTED`, `REJECTED`, `TIMEOUT`, `CANCELLED`, or `UNKNOWN`. Reserve a unique slot before work. Store expected accepted revision, source/input hashes, requested/effective budgets, child process group, start/end monotonic times, exit status, actual artifacts, cleanup outcome and rejection reason. A timeout or lost reply remains consumed/unknown until reconciled from real process and storage state; it never permits an automatic retry.

Stage candidate source, dependencies and output together. After construction plus independent GLB checks, seal an immutable **candidate** closure and record `BUILT_PENDING_RECEIVING`, without changing the accepted pointer. Validate the actual native scene and GLB in the separate receiver stage. Before the accepted-pointer compare-and-swap, reap all required child processes, close their output handles and verify mandatory cleanup succeeded. Only then conditionally change one accepted-state pointer. Cleanup failure prevents promotion; it must not be discovered only after the pointer has changed. `ACCEPTED` in this ledger means this source/artifact transaction passed its mandatory geometry and receiving gates; it does not by itself qualify the profile, whose corruption, lifecycle, paired equality and visual-review obligations remain separate. A stale expected revision or any failure preserves all prior accepted source/output bytes and their pointer. Unknown promotion outcomes are resolved by reading that pointer and the immutable receipt; do not launch another child to discover what happened.

L01–L08 use at most eight directly launched controlled worker processes to exercise the production supervisor/transaction path, including L05's one additional controlled grandchild. Thus the total process count ceiling is nine. Each case launches at most one direct stub; any other stage uses a sealed prevalidated fixture or a deterministic in-process stage seam. The input lock identifies which production stage is under test and which seam supplies the other stage. L01 and L08 cover receiving-to-promotion; L02–L07 cover construction/cleanup. No fixture or seam can be cited as an executed second native/receiver process. These controls qualify supervisor and transaction mechanics with fixed stubs. **They do not establish observed cancellation or timeout behavior of Blender itself.** The production native guard remains required; a deliberate actual-Blender cancellation claim needs separately frozen slots/evidence and is not made by this plan.
