## Expected errors and order

All flags failures use the unchanged `CHI-UNSUPPORTED`, reason `Unsupported dynamic flags`, state `REJECTED`, empty details and no cause. New selector pair failures use `CHI-PLAN`, reason `Unsupported libc static-TLS schema/profile pair`, details `{stage: profile_selection, rule_id: FLAGS-PROFILE}`. The unchanged closed `libc_plt` shape failure uses the P16 reason `Invalid libc PLT policy shape` and `PLT-SHAPE` selector. Missing/unknown fields do not supply an implicit profile.

P16 architecture/trio errors retain `PLT-ARCH` / `PLT-TRIO`. P16 binding errors retain the exact `PLT-ROLE`, `PLT-DESCRIPTORS` and `PLT-PIN` semantics. D01 retains `CHI-DRIFT / An admitted input changed before/after the command`, with `stage=recheck`, `rule_id=LP-RECHECK` and the bound-descriptor error as its cause. Every complete expected dictionary is literal in `EXPECTATIONS.json`; shorthand in this document does not replace it.

Order is existing external plan authentication and inherited shape/structural guards, exact pair/closed shape, inherited role–descriptor–pin proof and actual file binding, then the raw reader's structural guards, architecture, unknown tags, trio, flags, and remaining metadata/identity guards. Old routes keep their old order. No success may be returned immediately after a flags match.

## Mocked observations and faithful future adapters

B01–B05 and D01 are explicitly derived from exact P16 inert logical contexts. Each records its predecessor path, size and SHA-256. The newly selected pair/route and literal expectation are frozen here; every original context and original expectation remains unchanged. Their `actual_fixture_bytes` reference is inherited synthetic provenance, not an image to execute or a successful `_bound` observation. These cases test finite equality/role/pin logic only. B05's coherent synthetic descriptor still fails the real operational pin.

X01/X02 supply an explicitly mocked, already-bound internal-policy observation so the future adapter can exercise actual dispatch against inert bytes. The adapter may map its temporary fixture path to the supplied subject relation at this private seam. It must disclose that mapping and must not alter production pin constants, claim a real file-binding success, feed mocked review approval into production, or bypass an actual operational gate in a host test. X02 must actually invoke the old reader, as evidenced by the declared route and its existing flags refusal. The two cases are not a complete plan.

The future adapter must identify its exact source, map every case to the real production symbol, consume each original oracle unchanged, and retain the distinction between metadata, selector, mocked binding, dispatch and drift evidence. Dispatching on a case identifier to synthesize the expected exception is forbidden. The selected actual-libc plan remains a later gate and has no positive fixture here.

## Callbacks, cleanup and limits

The new raw route adds private named checkpoints `before_libc_static_tls_flags` and `during_libc_static_tls_flags`, each calling the existing zero-argument `check`. The latter is reached during the bounded entry scan that collects/checks flags. The preexisting P16 `before_final_elf_identity` checkpoint remains in force. These seams add no public option or caller-selected mask. Old routes gain no callback calls.

F01/F03 supply a `RuntimeError` sentinel; F02 supplies a `HostInspectionError` sentinel with the stored category/reason/details. The future adapter must inject only at the actual reached boundary and observe the identical exception object escaping the private reader. It must observe exactly one close of the descriptor opened by that call. A pre-reader synthetic raise is not execution of the case. Successes and ordinary refusals also require one close. Binding and selector cases open no ELF descriptor.

Existing short-read, I/O failure, descriptor/path identity, callback and closure controls remain mandatory through unchanged P16 and inherited corpora. This flags-only change adds no read, value-derived allocation or new resource ceiling. The 65,536-byte dynamic table, 16 MiB document reader, source 100,000-operation / 30,000-ms ceilings, and every inherited limit remain exact.

## Static integrity is not behavioral execution

`build_controls.py` performs direct fixed `struct` writes, copies declared historical logical observations and emits literal expectations. It does not implement the flags acceptance rule. `verify_static.py` validates the candidate's inventory, bytes, intended layouts, source references, predecessor preservation and coverage. It does not import OntoKin, evaluate a flags policy, run a future adapter, inspect a live host, or execute any fixture. Its report groups data-integrity findings; they are not product-test counts.

A later implementation must keep all 135 inspection, 40 mapping, 96 P13-applicable origin runtime obligations and every P16 control, then execute this corpus under independently reviewed adapters. Historical N57 remains externally accounted for; it is neither a runtime pass nor a skip. No case here closes H0/H1, R03, the complete routine, integration or parent delivery.
