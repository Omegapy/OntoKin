# P06 scoped learning

The existing project memory already covers local verification, explicit scope and reconciliation after uncertain operations. P06 does not promote a broader capability claim into project memory or knowledge. The new provider is still unqualified on an actual host. The following implementation lessons remain attached to this phase and its evidence.

An input hash check does not protect a later blocking pathname reopen. The provider and new probe helpers now open regular files with no-follow and nonblocking flags, then verify the opened descriptor and the named file before and after bounded reads. The original findings and pre-correction source snapshots remain in the session evidence. Protected historical JavaScript helpers remain unchanged; their inherited limitations are separate from the corrected new helpers.

A refusal needs an observable record of what was rejected. The driver now retains both the externally supplied expected digest and the observed configuration identity on mismatch. It records whether a process actually started, so a failed prelaunch stage stays in the unexecuted list even if later inventory collection fails.

A test that counts checker starts must isolate unrelated metadata queries. The initial driver-test fixture intercepted `platform.platform()` calling `uname -p`. A two-line fixture correction isolates that metadata leaf while preserving all ten test identities and 39 assertion calls. The failed attempt remains available; the affected group was rerun after independent review. This does not justify suppressing execution predicates or relabeling mocked behavior as a real process result.

The initial approval-channel interpretation was too strong. The adopted contract prohibited unbound extra arguments and explicitly allowed parser/bootstrap adaptation. Independent source review resolved the channel through an externally selected digest argument before the unchanged terminal job pair. The initial finding and its correction are both retained.

These are source and focused-control observations. They establish no actual Node behavior, runtime performance, full-routine result, product qualification, integration approval or parent completion.
