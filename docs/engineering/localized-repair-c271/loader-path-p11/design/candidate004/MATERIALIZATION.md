# Faithful private materialization of inert P11 evidence

Git preserves file contents and its executable-bit class. It does not preserve each artifact's recorded private read/write mode: an authored `0o600` regular file can arrive from a normal checkout as `0o644`. The manifest's byte and metadata identities remain authoritative. This procedure restores those inert evidence modes before static checks or future control adapters consume a checkout.

1. Authenticate `CANDIDATE-MANIFEST.json` against its independently recorded SHA-256. Do not trust a manifest hash supplied only by that same manifest. Validate all payload names as unique safe relative paths within the candidate. Confirm each frozen byte count and SHA-256 before interpreting content. Do not execute a source checkout to regenerate expectations.
2. Create one fresh private owned destination root, with exclusive creation and no overwrite. It must be separate from repository source, operational runtimes and host input paths. Reject symlink traversal, hardlink destinations and special files. Logical aliases, FIFO and other exceptional states remain JSON descriptions.
3. Copy each verified payload as an ordinary regular file under that root. Apply its manifest-recorded inert mode, `0o600` or `0o644`, and verify its exact size, SHA-256 and mode after the copy. Preserve every `.bin` as nonexecutable. Directory creation uses private owned directories; their transport metadata is not an operational path observation.
4. Supporting references of the form `../name` are the explicit sibling filenames bound by the manifest. They are not arbitrary archive traversal permissions. If a support script or prior candidate is needed, map the authenticated named source to that exact sibling under the same fresh owned evidence root. Never resolve a supplied relative path beyond that root. Prior candidate/support hashes remain independently bound by their preserved manifests.
5. Run the frozen static checker or a later reviewed adapter only against the faithful private copy. Retain an external materialization receipt with source/candidate hashes, destination identity, actions, resulting modes and verification outcome. Keep that receipt outside the frozen candidate payload. An observed byte mismatch refuses copying/consumption; no expectation is regenerated from implementation output.

This procedure grants authority only to reproduce inert evidence-file metadata. It does not change the operational Python's fixed hash, size, path or mode. A logical subject field of `0o755` remains test data; it never authorizes making an ELF fixture executable, changing a runtime's permissions, selecting another executable or approving a host. The selected real-image admission and the synthetic control seam remain separate obligations.

P11 freezes this procedure; it does not add a production materializer or change repository file modes to simulate operational subject permissions.
