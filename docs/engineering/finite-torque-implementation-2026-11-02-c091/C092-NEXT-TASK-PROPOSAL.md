**Status: proposal for a separately reviewed contract amendment. C091 remains an implementation checkpoint with a release blocker. This document does not adopt a new rule, authorize a main merge, or turn incomplete acceptance into a pass.**

The next task is to resolve the conflict between exact inherited canonical angular evaluation, exact off-axis admission, and reconstruction from immutable source alone. Adopt and publish a deterministic canonical plan-selection rule before implementing it. Then finish the independent reader and execute the complete acceptance sequence on one immutable candidate.

## 1. The demonstrated conflict

The source witness has a prescribed parent angular velocity with canonical binary64 components corresponding to `(0.6, 0.8, 0)`. A hinge uses that same axis and reaches its zero-angle endpoint at one second. An ordered release is followed by a world-X torque activation. An unrelated dynamic sibling, with the same angular velocity, has a real COM force event at 16,384 seconds. The entire source is unchanged between the following two controls:

| Public execution using a fresh compilation and admitted shared work | Result at exactly one second |
| --- | --- |
| Call `evaluate_prefix(model, "1", work=work)` | Accepted, after side; released canonical angular velocity is exactly `(0, 0, 0)`; world-X axis is latched. |
| First successfully call `evaluate_prefix(model, "16384", work=work)`; immediately call `evaluate_prefix(model, "1", work=work)` with that same work | Refused with `OKL-E-FRAME` / `incoming_axis`, before side; released canonical angular velocity is exactly `(0, 0, 2^-96)`; no axis is committed. |

Both controls use the original 100,000-operation and 30,000-ms limits. On the closing pin they consume 16,971 and 40,969 cumulative operations respectively. The adjacent public calls perform no private plan/cache observation, plan injection, callback replacement, or source mutation. The unchanged entry is 1,858 bytes, SHA256 `8d02d0fb3ca61f275bb85f019a45451c34e89925e488e7d2236432b6085fc27e`, with program revision `sha256:a2e3fb4fc44349355ede9480cc35f5d699663de084e5bbbcd010d143aedb3b1e`.

The independent guarded calculation explains the result. With the same literal source and elapsed clock, the inherited 96-stage spin plan gives an exactly zero released vector. Eligible 192/384/768/1536-stage plans give a Z component of exactly `2^-96`. Their internal quaternion values differ by a fixed-grid unit. The residual survives binary64 publication exactly. It is not an uncertain physical interval, a presentation-only difference, or an underflow that can be treated as zero.

Exact evidence is retained in:

- `reference/axis-completeness-review/`: literal sources, independently implemented controlled arithmetic, public-call driver, complete observations, reviewed WIP snapshots, and its ten-file manifest.
- `reference/axis-public-history-2513b07-reproduction01.json`: independent public replay on the later runtime source identified in that receipt; its filename is historical, not a claim about the receipt's actual source commit.
- `runtime/integrated-blocked-checkpoint-attempt02/public-history.json`: complete public replay on the closing `8190ed7` pin, with stable source-file hashes.

Passing the existing 31 analytic cases does not remove this counterexample. A source-only reader cannot select the producer's answer for both histories, and a reader that rejects every unresolved case would exclude a supported source execution that the canonical producer accepts.

## 4. Recommended rule to put through review

Define each controlled .22 constant-angular-velocity point operation from its immutable canonical input vector, complete source-derived rotation origin, and exact elapsed rational `d = requested_clock - actual_origin_clock`.

For nonstationary orientation evaluation, consider the existing schedule `(96, 192, 384, 768, 1536)` in that order. For each stage, independently construct the existing scaled-axis norm enclosure and Machin-pi enclosure. Evaluate the existing argument-error certification expression with **maximum elapsed magnitude exactly `abs(d)`**. Select the first stage that certifies under the unchanged guard. Use that stage's exact operands in the existing controlled reduction, polynomial, axis construction, projection, and multiplication. If none certifies, retain a bounded numerical refusal. Stationary/zero-elapsed operations retain the existing complete anchor and current admission checks; this rule must not add a physical anchor or reseed from an exposed quaternion.

The normative rule should specify which certification failure advances to the next stage and which remains the inherited finite refusal. In particular, it must not invent a retry after a later reduction failure unless that behavior is independently reviewed. “First certifying” must be an executable definition, not an instruction to keep searching until the desired axis result appears.

Apply the rule to every .22 source-point angular operation that can contribute to an admitted canonical pose or velocity: prescribed parents, hinge/reach dependencies, dynamic legacy evolution, release materialization, ordered impulses, and subsequent reanchors as applicable. A local change only at the torque statement or only after split leaves the demonstrated pre-latch ambiguity intact. Enumerate actual affected call sites during design review. Keep all earlier bindings and the nine predecessor numerical-basis files byte-for-byte unchanged; use a narrowly dispatched .22 extension that calls unchanged primitives where they already implement the required operation.

A whole-phase plan may certify a continuous bound or reserve work. It may not substitute its higher-stage operands into a point operation whose normative stage is determined from that point's actual elapsed clock. A retained cache entry is reusable only for the same fully identified normative computation after current source, native ownership, operand/cap, cancellation, deadline, and callback admission. Cache hits do not grant authority or change results. Repeated requests may have different actual work costs, but must consume and report the work they actually perform under the same original ledger.

The amendment must also address precision-stage boundaries in continuous certificates. First-certifying point values can differ by fixed-grid units as the chosen stage changes. Uniform source-error bounds must cover every such stage across the closed phase; a continuous ideal reference plus the complete controlled-kernel discrepancy can establish this. Sampling a few stages or assuming the rounded point map has no jumps is insufficient. Preserve the phase cap, marker-radius propagation, speed/acceleration maxima, rounding cells, and complete interval inequalities.

This is a narrow .22 numerical semantics exception to exact inherited plan selection, not an exception to exact axis admission. Genuine nonzero orthogonal canonical components still refuse. Full `RotationValue` error, ordered transfer uncertainty, separate reference/error origins, canonical neutral-anchor behavior, and all translational records remain required. Existing literal C3 controls keep their exact frozen expectations. If a proposed rule cannot meet one, preserve the failure and seek a specifically reviewed input/comparison amendment; do not broaden C3 silently.

Finally, decide implementation identity and durable-state compatibility before code. New numerical/derivation identities must hash the actual adopted method and implementation bytes. Existing historical idempotent responses remain exact. State created under the old numerical method must either resume under its explicitly supported original method or be refused by a predetermined compatibility rule; it must not be silently reinterpreted. The amendment must state whether an explicit .22 amendment identity suffices for this unreleased profile or a new binding/schema version is required. Do not infer that decision from convenient existing fields.
