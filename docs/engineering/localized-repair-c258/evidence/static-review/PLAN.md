## Resources and refusal behavior

Inspect limits before allocation, conversion or recursive expansion: two source
files; 65,536 bytes and 8,192 tokens each; depth 32; 128 objects/follows; 64 keyed
members/helper calls; 4,096 expression steps; 64-character numeric lexemes;
4 MiB GLB and 2 MiB JSON. Check that counters cover the whole admitted operation,
and that graph traversal terminates within the admitted graph. Do not introduce
unrelated general source-validity or glTF-validation gates.

Numeric lexeme length alone does not bound an exponent or a denominator.
The reconciled contract now requires explicit decimal exponents in [-400, 400]
before Decimal/Fraction construction or powers of ten, including zero, and
nonzero adjusted exponents after unit conversion in [-324, 308]. Inspect that
admission order and the three-candidate projection search bound. This concerns
resource admission and truthful method claims; the independent reviewer owns
the exact rounding proof and comparison-policy mathematics.

Inspect relevant untrusted rows, node-property copies and vectors for strict
container/scalar types, exact vector widths, duplicate keys/identities and
integer/bool ambiguity. Unrelated metadata remains outside this finite observer's
authority. Verify bounded historical reads before allocation and hashing.

Check all four public APIs and the CLI for consistent typed refusal on concrete
structural, Unicode, numeric, recursion and I/O failures. Follow exception classes
across the pinned helper boundary, including Decimal arithmetic if used. The
previous C257 long-path I/O gap is a specific regression candidate, not an
assumption that the new code is defective.

## Targeted probes and disposition

Run a probe only when static inspection identifies a concrete remaining risk.
Use ordinary, deterministic malformed inputs and bounded reproductions; do not
drive uncontrolled allocation. Candidate routes include a changed dependency,
overlong file path, malformed relevant JSON shape, exhausted aggregate counter
or exponent amplification, depending on the actual implementation.

Save the exact reviewed hash, input recipe/hash, invocation, bounded exception
and complete result. Preserve the first failure before requesting a correction.
Report actionable findings to author and parent. Recheck only affected controls
after a correction and establish byte equality for reused evidence.

Finish with approval or blockers for exact bytes, explicit unresolved limits
and evidence paths. No full source/glTF validity, complete C255 semantics,
execution, revision, rebuild, native/model or release qualification follows from
this structural review. Final integration, package verification and saved delivery
remain parent-owned.
