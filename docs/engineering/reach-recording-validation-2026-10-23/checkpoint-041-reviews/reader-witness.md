## Blocking authority persists without a counter read

Every ordinary `ReachExecutionWork.charge` executes `self.counts[kind] = self.counts.get(kind, 0) + 1` at `reach_numeric.py:88`. Both lookup and insertion can invoke foreign-key equality on an exact native dictionary. Avoiding the aggregate counter read in the proposed optimization does not remove these existing callback entry points.

A flag solely at the rational fallback branch cannot witness code that is bypassed after a foreign callback temporarily replaces the cell helper or changes other relevant state. Before/after function identity checks do not establish that the same bindings held throughout the interval. A collision callback can run during the row's preceding original charge, before `clock_cell_contains` is looked up at line 653. The flag remains eligible if a replacement returns successful membership without entering the original fallback branch. This is source reasoning about the proposed design, not an executed attack or product test.

The current native gate explicitly handles this concern by checking every category key/value type (`reach_conformance.py:2811–2813`), alongside function/code/global/builtin bindings, work and budget state, observer exclusion and trace/profile exclusion. That gate cannot be borrowed as already paid authority for the earlier retained-clock stage.

The concrete design “lexical fallback flag plus an exact-dict-type-only work gate” is therefore unsafe. Adding a complete post-row category authentication pass gives the same unfavorable source-flow bound preserved by C040: at least 266 category inspections against 205 potentially omitted P16 authored comparisons, before any other new work. This 266 figure remains the C040 inference from C038's categories and native control flow, not a fresh snapshot.

An early provenance scheme that guarantees every later category insertion remains a native string would be a different design. It must show how the ordinary externally mutable dictionary and all mutation/callback boundaries remain covered. Merely storing `counts` object identity, or invalidating on attribute replacement, cannot detect mutation of that same dictionary.

## Other concrete routes do not yet close the cost bound

1. An additional eligibility result stored, copied or checked for each of 206 rows has at least 206 new logical occurrences/admissions, exceeding the 205 comparison charges. This is a bound on that explicit per-row route, not every lexical implementation.
2. A callback observer that newly checks work, domain or dispatch on every row also incurs at least 206 new admissions. A post-charge observer must itself be trustworthy and must not overwrite an existing observer.
3. Unconditionally retiring the proof before any potentially foreign dictionary equality is safe but makes the optimized path ineligible under the existing charge implementation. Selectively avoiding retirement requires authenticated key provenance or another independently justified mechanism.

No complete H < 205 schedule was established for the fallback-only design. There is no claim that all future scoped-witness architectures are impossible.

## Failure order and retirement obligations

The exact source sequence remains row parsing, metadata equality, binary32 cell membership, label/semantic checks and shift calculation; then endpoints, authored ordering, semantic coverage and time tolerance (`reach_conformance.py:640–666`). Private proof acquisition must not reorder these first failures. A narrowed or changed work domain requires the original adjacent guard behavior. Any unfamiliar dispatch, reader, callback or observer must retain the complete original helper path.

Private witness state must be request-specific and bounded, with retirement on success, fallback, cancellation, exception and reentrancy. Cleanup cannot introduce a new callback failure in place of the original exception. Precharging retirement itself changes the schedule and must appear in H. A flag must not survive a failed request or certify a later model/reader.

## Verdict

Do not select this concrete fallback-only flag architecture for implementation yet. It removes the explicit counter read but leaves unclosed native-work and cross-stage authority; the available full authentication repair already exceeds P16's 205 gross comparison budget. Prefer examining an independently scoped higher-volume reduction. A new witness could be reconsidered only with a concrete callback/provenance mechanism and a complete positive charged bound.

All caps, fixtures, independent predicates, original first-failure requirements and remaining release gates remain unchanged.
