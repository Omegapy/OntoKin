## What the full native gate actually checks

`_certificate_fields_native` (2855–2879) checks the term/raw/key function identities, selected module attributes and saved code/default/keyword-default/closure/global/builtin state for its four saved functions before invoking `_certificate_term_native`.

The term gate (2762–2828) checks exact `_Bounds` type and field-reader identity; class descriptors/methods across arithmetic/work/construction/Fraction/ABC/number classes; selected module attribute identities; inactive trace/profile hooks; saved Python function code/default/closure/global/builtin state; absence of arithmetic method overrides; exact work type; work method overrides; no work observer; full native operand cap; native counter/limit/start shapes; a bounded native category dictionary with native string keys and integer values; and either no external callback or the original native `ConstructionBudget.tick` with no nested custom check and native bounded budget state.

The proof is site-specific. A foreign callback or observer is intended to decline to ordinary arithmetic before the comparison admission. The absence of foreign callbacks gives the successful first equal comparison a different failure corridor from atan: both operands have already been shown to be small native Fractions and original operand guards run before its charge. The proposed atan seam still has `F(a)` and `F(b)` pending after its original charge (reference source126–145), and that original earlier callback may have changed the dynamic `F` binding.

## Passive storage authority gap

The gate's raw reads must themselves be passive for the fallback claim to follow. Source does not establish that property for every dictionary it inspects.

In particular, `_term_function_state` (2737–2744) snapshots every `function.__code__.co_names` entry through `namespace.get` and `builtins.get`, including names used as attributes. The native gate repeats these dictionary lookups at2790–2792. There is no prior complete key-type audit of the externally mutable module globals dictionary. Native `dict` type alone does not make a lookup passive when a foreign key with a colliding hash can invoke equality.

A conditional helper-entry source witness can be stated without executing product code or calculating any hash:

1. Create a comparison context in the ordinary native environment and retain it.
2. Before its next comparison, insert a foreign key K into the conformance module's globals dictionary. Let K have the hash of the string `charge`, and let equality with that string raise existing exception E. Its other equality results can be false. The original module has no top-level `charge` binding.
3. Keep the named native functions, all saved referenced values, the small equal Fraction operands and the genuine work object otherwise unchanged. No callback or trace/profile hook is needed.
4. `_tick` uses `work.charge` (46–49), so `charge` is an attribute-name entry in its code-name inventory. `_tick` is the first entry assembled by `_term_functions` (2719–2734).
5. A current-gate scan reaches `_tick`'s globals lookup for the absent name `charge`; that dictionary lookup can invoke K's equality and raise E before admission or fallback.
6. The direct original `_Bounds.compare` uses ordinary native Fraction fields and `work.charge` attribute resolution. It does not look up a global variable named `charge`; the extra gate's dictionary lookup is absent from that original path. The native charge is chosen to return normally within adequate original limits, and every non-`charge` lookup sees unchanged values; K's equality returns false for all other strings.

This is a conditional source-order witness to the missing passive-lookup proof at helper entry. It has not been executed. No proof is supplied that a full original recording naturally reaches this mutated state; the statement is a helper-level hazard under the explicitly described environment. It is not a runtime repair or a historical acceptance rewrite. If arbitrary module-dictionary mutation is intended to be outside the supported environment, that boundary must be stated and justified separately; it cannot be inferred from the gate's use of a native dictionary or from earlier tests.

The comparison context class and saved bootstrap aliases also require an explicit trust/lifetime boundary. This review does not turn every theoretically mutable Python object into another audit target. The specific dictionary lookup above is sufficient to withhold a general passive-gate proof.

## Funding and failure qualifications

Budget section3 lines103–110 permits omission of real work avoided by exact finite reuse, while explicitly retaining charges for new lookups, type/limit/claim checks and copied logical occurrences. The accepted derivation lines86–90 and145–150 documents one first comparison admission per group and changed native checkpoint schedules. It supplies no complete grouping map that makes all the new precharge scans or every later current-field proof part of that single unit. Do not infer zero cost, per-bytecode units, retrospective funding by the group tick, or a single composite unit from these documents.

Under an explicit passive, stable native environment, the first successful equal proof reaches a native budget check at the same broad stage as the original comparison, after the initial operand guard and before the prospective guard. This explains a limited useful property. It does not prove all admission work funded, and it does not make the postcharge ordinary fallback a saved continuation.

`ReachExecutionWork.charge` (71–94) calls the external check and performs resource checks before incrementing its own operation/category counter. A rejected charge is not necessarily a successful unit. `ConstructionBudget.tick` (75–87), when actually used, increments its construction count before checking its operation bound. Neither counter can be silently substituted for the other.

The term gate also explicitly permits `owner is None` (2797–2799). In that local no-work mode, `_Bounds.tick` calls `_tick(None, kind)`, which performs no request charge (46–49,69–70). The presence of the admission call in the source is therefore not, by itself, evidence of a positive request-budget increment on every route. The unchanged global operand guard still applies. Whole-request conclusions must bind an actual work owner.
