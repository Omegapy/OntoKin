## 3. The replace-and-retire source witness

The original `round64` obtains its Interval argument, then ticks before checking its live endpoint limits and converting the endpoints to binary64. Both shoulder and elbow Interval objects have already been computed when the final elbow rounding tick begins.

Consider a native successful first128 path that produced a child pi entry. An already installed nested `ConstructionBudget.check` callback can remain inert through the calculation. At that final rounding tick it can obtain the current child through the active call frame, without installing a trace or profile hook, and replace only:

`child.cache[("pi",128,32768)] = Interval(F(25,8),F(25,8))`.

It then sets its own owner's `check` to `None` and returns normally. Its executing frame still retains the callback while it finishes; no exception needs to be raised or recorded.

The genuine shoulder and elbow Interval objects remain intact. Even if an elbow directly aliases the old pi Interval, replacing the dictionary mapping does not mutate that old object. The original target checks can finish using the genuine values. All classes, method/code identities, owners and current observer slots can be native again before S1 begins. The new current-state checks see no remaining nested callback.

The replacement is native, positive, ordered, dyadic and exactly aligned to the 128-bit grid; it lies between three and four. It satisfies S1's stated endpoint-shape checks. It is not the independently calculated pi interval. The C052 series/grid argument places the genuine lower endpoint above

`1184/375 - 4/239 - 20*2^-128`,

with an exact pre-grid margin of `11183/717000` over `25/8`. The original later cold parent calculation therefore cannot return the substituted interval.

Under the original program, the child's false cache dies with the child and does not certify later residual work. S1 promotes that entry into the parent. A perfect final current-state recheck still observes the same false payload it saw earlier; identity stability after the first S1 observation is not authenticity before that observation.

This is a constructed source counterexample, not an observed corruption, an executed hostile request, or a claim that recorded inputs contain such a callback. Original callback exceptions retain their object identity. A current native outer bound method does not imply that its nested callback was always absent.

Parent insertion adds further obligations:

- A resident custom key can execute equality after a hash collision even in a native dict. S1's full key scan is not free, and safely inspecting an arbitrary key graph needs its own bounded method.
- At capacity, eviction may drop the last reference to an arbitrary value and execute a destructor. Safe keys alone do not establish passive eviction.

- The new alias can extend Interval/Fraction lifetime. Exact numerical equality is not object identity or an automatic guarantee against identity-sensitive observers.
- `_event` target-map access and assignment, `active.targets` storage, `_base_tip` and `sincos` all belong to the immediate consumer proof. Arithmetic methods alone do not cover effectful source keys or descriptors.

No extra work cap, cached Boolean, work-cache allowance or swallowed callback error repairs these issues. The reader's `a.cache` and production `ReachExecutionWork._cache` are different caches with different existing charging rules.

## 5. Conditional cache convergence

Assume authentic exactly equal child/native128 pi endpoints; fully native passive storage, keys, owners, methods and source fields; fixed matching domain; no effectful observers or concurrent mutation; and successful operation/elapsed/operand guards. Assume also that the immediate `_base_tip` lookup and first nonzero `sincos` lookup genuinely miss.

After canonical return, the ordinary event path stores the target and enters `_base_tip`. Those two misses do not promote any parent key. Before its pi call, this native route adds no parent numerical entry.

In the original path, pi's miss computes and then appends its result, evicting the oldest entry if necessary. In the candidate path, the extra earlier `remember` has already made the same append/eviction; the later pi hit promotes an already-last entry. At that pi return, both caches have the same key order and equal numerical contents, including the same evicted key.

The pi objects themselves differ: the candidate retains child objects, whereas the original makes fresh parent objects. With native consumers and no escaped/identity-sensitive observer, subsequent calculations can be equivalent up to renaming those objects. Under this complete premise, no later charged difference need remain from the insertion, so the modeled remaining-work term can be zero. At capacity, the proof also assumes eviction is passive and its earlier timing is unobservable.

This theorem is useful because earlier insertion does not necessarily create an irreparable later cache difference. It does **not** authenticate S1's child entry, prove the real request follows those misses, authorize arbitrary callbacks, establish acceptable elapsed timing, or imply complete-request savings. A hit in `_base_tip` or `sincos`, a zero-angle bypass, a domain change, an interruption or later eviction can remove or change the opportunity.

## 6. Costs across successful and unsuccessful paths

The native128 cold pi computation costs 165: lookup 1, the 28-iteration atan at 1/5 costs 115, multiplication by16 costs5, the 8-iteration atan at1/239 costs35, multiplication by4 costs5, subtraction3 and publication1. A genuine pi hit costs1. All original child work remains in C053.

Thus one actual cold parent miss replaced by a hit saves164 gross. The added early parent `remember` costs1 even before the new admission checks. On the strongest stable convergent path, **163 operations remain before those checks**. This is normally a first-parent-miss opportunity, not164 per canonical target or child pi call.

For matched completed executions, define:

`saving = 164*H - Q - A_nonpublication - Delta_remaining`.

Here H counts actual matched cold misses removed; Q counts newly reached publication ticks, including final-admission rejections; A includes every other new reached charge; and Delta is the signed candidate-minus-original remaining work outside those counted terms. Do not count the same synchronization or cache effect in two terms. Refused/interrupted attempts need their exact event-prefix and counter accounting instead of this completed-run identity.

S1 scans all m resident keys. Even giving each entire resident inspection just one charge, one completed convergent publication has

`net <= 163 - m - A_other`.

At m=256 the optimistic ceiling is **-93 before other costs**. At m>=163 this bound cannot be positive. These are sufficient, non-sharp bounds: A_other includes the entry discriminator and deeper key/current-authority work. They are not actual setup occupancies or a universal lower bound on every safe design.

The [ledger](checkpoint-053-cost-ledger.json) keeps distinct paths. Warm parent and empty child have no saved cold miss but pay reached gates. Failed128 is not published; a later success pays the discriminator. A final rejected publication still pays its reached tick and prepaid checks. A published value that is not used, is evicted or is invalidated cannot claim164. Multiple publication attempts must each be charged even if only one later miss disappears.

Restoring every omitted pi checkpoint with a charged tick consumes all164 gross and leaves the new publication and other costs. Merely restoring counts would not restore callback timing, prospective guards or state.

H, Q, actual gate costs, setup occupancy, first128 incidence and general remaining-work differences are unmeasured. Subtracting163 or164 from a failed100001 count does not establish a successful completed request.
