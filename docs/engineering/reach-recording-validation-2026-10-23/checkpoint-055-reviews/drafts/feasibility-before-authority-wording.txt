Date: October 27, 2026, America/Denver. Owner: `interactive-reach06-cold-pi-used-state-20261027-c055-7c91`. Branch: `work/reach06-cold-pi-used-state-20261027-c055-7c91`. [Declared scope](https://github.com/Omegapy/OntoKin/issues/26#issuecomment-6454605895).

**C055 rejects an eager admission charge at the original cold-pi boundary.** The original program captures callable references and can fail before its first factory checkpoint. Moving a callback-bearing charge ahead of that work can change both the function used by a rejected fallback and the exception returned. Saving only the outer callables does not close the gap. An eager charge immediately after the first atan square also fails: the original next evaluates `F(0)` before its next checkpoint.

These are conditional source counterexamples to three specified schedules. They are not executed hostile requests, observed recording failures, or a proof that every specialization is impossible. A use-sensitive dependency analysis removes irrelevant checks, but **no complete safe admission or positive all-path cost bound is established**. The complete gate cost remains unknown. No numerical endpoint proof, constant generation, runtime implementation or collector is selected.

The [schedule](checkpoint-055-schedule.json), [ledger](checkpoint-055-cost-ledger.json), [review index](checkpoint-055-reviews.json), [validation](checkpoint-055-validation.json), [source binding](checkpoint-055-source-binding.json) and [next scope](checkpoint-055-next-scope.json) keep those claims separate.

The source analysis follows the native positive atan calls, their interval multiplications, and final subtraction. It is a finite inventory for the stated native branches, not a completed safe authentication procedure for arbitrary Python objects.

There are useful exclusions. The old `pi` binding is not a future omitted-factory call after entering its replacement frame. `sincos`, target-map owners, active targets, already finished child observer fields and two-pass resident-tag screens do not belong to this factory slice. Original lookup and remember semantics remain required, but their bookkeeping must not be added as avoidable factory work.

The analysis also avoids C054's blanket five-field metadata screen. Most arithmetic calls supply every argument, so unused defaults cannot change those invocations. For `Fraction.__new__`, one-argument calls consume `denominator=None`; its unused `numerator=0` default does not affect these calls. With exact Fraction operands on the proved native branch, a forward arithmetic wrapper uses its `monomorphic_operator` cell, not its unused fallback delegate. Checking an unrelated same-named class slot would inspect the wrong authority. Native `work.tick` calls `charge()` with omitted `kind` and `amount`, so those defaults matter.

Function identity plus current code and code plus current globals/used closures are possible alternative authentication designs. They are not all automatically cumulative requirements. Shared globals may be checked once only if the accepted callables are proved to use that exact dictionary and the values stay valid through use. Captured delegates must not be charged twice under two different inventory labels. C055 therefore adopts no artificial 164- or 180-operation rejection floor for all use-sensitive designs.

## 3. G0: eager charging changes a rejected fallback

G0 retains the original lookup and warm-hit return, then invokes a new callback-bearing charge before evaluating the original cold factory. It inspects authority after precharge. If inspection rejects, it reevaluates the original factory expression. For the counterexample, grant any desired accuracy and completeness to those later inspections; the failure occurs earlier.

Take an otherwise native cold context with the two arithmetic observer slots unset and a bounded check callback. The lookup callback returns normally. On its first subsequent invocation the callback replaces this arithmetic instance's `mul` binding with `R`, then becomes passive. `R` raises an existing exception object when its scalar argument is 16; for scalar 4 it delegates to the saved native bound multiplication. Nothing else is changed.

In the original, the first native `mul` is already captured when the first factory checkpoint runs inside the first atan square. The callback replacement therefore cannot redirect that first multiplication. The later second `mul` resolves `R`, but its scalar is 4 and it delegates. Grant the usual native completion for the remaining calculation; no endpoint values are needed for the argument.

In G0, the added charge runs that same callback before the first `mul` capture. Even if the gate correctly notices the changed binding and rejects, its fresh-expression fallback now captures `R` for scalar 16 and raises the marker. A normal-returning precharge has changed a rejected fallback. Returning to identical source text has not restored the original pending call references.

This witness uses a supported callback route. It requires no numerical certificate, cache collision, trace hook, finalizer or concurrent writer. It is a conditional source construction, not an executed attack or a statement about setup incidence.

## 4. Exception order and the two partial repairs

An independent failure-order witness does not need the original factory to complete. Let the original lookup callback return; let its next invocation raise an existing exception B. Let the current `F` binding raise a distinct existing exception E when the original evaluates `F(1,5)`. The key, lookup and domain path do not call F. The original therefore raises E before its next callback. G0 calls the callback first and raises B before it can reject the changed F binding. Swallowing B would violate callback exception identity rather than repair the schedule.

### G1: retaining the outer captures is insufficient

G1 first retains the original `remember`, `sub`, first `mul`, first `_atan_small`, and `F(1,5)` result, then precharges before calling the captured atan. This repairs the particular outer binding gap only.

The original still calls that captured atan before reaching the first square tick. A captured callable can raise E immediately; the new charge can raise B first. Even when the captured atan body is native, its initial `F(value)`, sign comparison, `F(1,2)`, comparison, `self.exact` lookup and entry precede the square checkpoint. Their authority and failure order need proof. Merely saving four callables cannot establish it.

The original first square tick also captures both arithmetic observers before calling `check`; product observer then ordinary observer run after normal return. The work charge captures its observer before the external callback. Inspecting slots after a callback cannot undo an observer already captured by that tick. Source locations and exact identities are recorded in the authority review.

### G2: immediately after the original square is still too early for a new charge

Moving the gate inside `_atan_small`, after `square = self.exact(value, value, "mul")` has completed, preserves more original frames and their captures. However, the next original statement evaluates `F(0)` while initializing `power, total`. It then sets up the loop and resolves the first term's exact call before the next checkpoint.

For this source witness, an F proxy delegates the earlier nonzero conversions and arithmetic attributes to the native class, but raises E for `F(0)`. Earlier callbacks return normally; the next callback raises B. The original post-square path raises E without that callback. G2's eager precharge raises B first. This rejects the relocated eager-charge repair; it does not reject every possible in-place tail design.

### The scoped ordering rule

At a proposed seam, suppose the original can execute an unproved event and raise E before its next checkpoint. If a candidate inserts a new callback-bearing charge before that event, a callback that raises a different B on the new attempt distinguishes the paths. This rule covers the three schedules above. It is not a theorem that all optimizations or all admission locations are impossible. A different schedule needs a concrete proof of original event order, safe charging and continuation on rejection.

## 5. Operation accounting and the stopping decision

The inherited stable native128 factory opportunity is **163**, with original lookup and final remember retained. Structurally, a positive `_atan_small` stopping at N terms costs `4*N + 3`: one initial square, four exact operations per term, one final enclosure operation and one grid. Conditional on the inherited stop candidates N5=28 and N239=8, the two atan calls contribute 115 and 35, two interval multiplications contribute five each, and the subtraction contributes three.

This accounts for the inherited opportunity; it is not a new strict-stop or native endpoint proof. Those proofs remain behind the failed authority/charging stage. All prospective operand guards and the fixed 32,768-bit domain still require proof before numerical specialization.

After retaining an atan's initial square, its conditional remaining opportunity is `4*N + 2`: **114** for 1/5 and **34** for 1/239. The completed square charge has already paid for actual retained work. It cannot pay again for new admission. Moving the seam into a suffix also removes the corresponding prefix from the available saving. These numbers are ceilings before all new work, not proposed successful budgets.

For matched completed executions of a hypothetical valid whole-factory design:

`saving = 163*J - A_new - Delta_remaining`.

J counts actual admitted completed factories replaced; A includes every reached new discriminator, safe read, check, charge, certificate access, copy and retained occurrence, including rejected gates. Delta is the disjoint signed difference in remaining work and needs a convergence proof before being set to zero. Warm hits bypass the gate. Original lookup failures have no factory credit. Rejected paths retain their reached costs, and the original factory is not assumed unchanged after callbacks. Interrupted paths require their actual event prefix and error identity; completed-cost arithmetic cannot invent later work.

C055's three schedules fail authority/failure closure, so this identity cannot turn their divergent executions into measured savings. Complete gate cost, actual cold-call incidence and whole-request net remain unknown. A deliberately redundant direct-read screen was considered in preliminary cost work and withdrawn as a basis for rejection: it did not establish a necessary use-sensitive lower bound. The adopted result rests on source behavior, not on forcing an overbudget screen.
