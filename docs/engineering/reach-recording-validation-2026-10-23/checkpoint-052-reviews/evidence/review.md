## Exact route and deduplication

In [reach_conformance.py](../../../../../ontokin/reach_conformance.py), `validate_reach_export` builds the independent reference before `_key_comparisons`. In [reach_reference.py](../../../../../ontokin/reach_reference.py):

1. `build_reference` creates one default128 `_Arithmetic` and passes it to `ReachReference`.
2. `ReachReference.__init__` retains that parent as `self.a`, creates `_targets`, initializes source state and then calls `_build`.
3. On an original reach start, `_event` constructs the key `(lengths, target, branch, limits)`. Only a key absent from `_targets` invokes `_canonical_targets`.
4. `_canonical_targets` performs its exact algebra with the parent, then creates a fresh child at each member of `PRECISIONS = (128, 256, 512, 1024, 2048)`. It returns at the first precision whose radical, quadrant, binary64 rounding and closed-limit checks succeed.
5. `_event` immediately uses the returned coordinates in `_base_tip` and `_residual`. A cold nonzero `sincos` inside `_base_tip` asks the parent's `pi()` for its enclosure.

Therefore, counting actions as fresh child constructions is unsound when keys repeat, and counting each canonical call as a parent-pi saving is also unsound. A warm parent, an already cached base tip or sine/cosine result, zero trigonometric arguments, precision refinement and interrupted calls have different outcomes.

## Why child-to-parent publication is a real, bounded source target

The C052 parent-reuse direction makes previously exposed parent numerical payloads inputs to target computation. Reversing that direction preserves original target arithmetic: finish the original fresh child calculation first, then consider publishing only its already completed pi to an absent matching parent slot. No parent numerical payload would choose the target or certify the child result.

There is a useful structural bound on the child. Along unchanged `_canonical_targets`, its native `point`, `mul`, `sqrt`, `atan2`, `atan`, `_atan_point` and `round64` routes do not publish other cache families. Their only cache publication is through `pi()`. Under a proved native, stable-domain child lifetime with no effectful callbacks or observers, the fresh child's cache contains either no entry or the one completed pi key. This is a source theorem with explicit premises, not a conclusion from checking a returned object's type. Any changed dispatch, reachable callback, exposed alias, custom field or domain change must be excluded or retained on the original path.

The downstream consumer is concrete: `_event` -> `_base_tip` -> `sincos` -> `pi`. For original L03's first zero-time reach, the stable native setup prefix initializes vectors and quaternions, validates the chain, copies metadata/state and performs canonical algebra. Those operations do not create a parent pi or sine/cosine entry. The target has lengths `(1,1)`, point `(0,1,0)` and positive elbow branch. Its nonzero canonical shoulder and elbow require child pi, and the first residual's nonzero shoulder sine/cosine needs parent pi. Conditional on successful original128 completion and the stated native/domain/cache premises, this gives an actual source path where a fresh child pi is followed by a cold parent pi construction.

The independently reviewed C051 successful native128 miss costs 165 and an eligible hit costs 1, so this downstream replacement offers **164 gross operations before all new work**. This is not a measured L03 saving or a proof that 128 is the actually successful precision. It is normally one avoided first parent miss. Later fresh children still compute their own pi; a parent already holding pi offers no new saving from this publication policy. Do not multiply 164 by the number of distinct targets.

## Concrete gates for that next review

The next owner should freeze one publication schedule before further counts or implementation:

1. **Original target result first.** Retain original fresh children, precision order, exceptions, `_Uncertain` refinement and closed-limit/round64 checks. Consider publication only after the first128 child has completed the original successful target result. Do not move publication into failed or later-precision attempts. Do not compute a pi merely to fill an empty child cache.
2. **Origin from creation through publication.** Establish original child construction and every relevant arithmetic/Fraction/global/default/closure/descriptor dependency over the actual lifetime. A return-time shape or exact-type test is insufficient. Price the exact native gate and any protected lifetime mechanism. Reject immediately if independent origin cannot be closed within that concrete schedule.
3. **Safe parent absence and publication.** Define true key absence precisely. Never read a present parent value as proof, and do not overwrite a present value, even if it appears malformed: that would alter the original path. A native dictionary can contain hostile keys whose equality executes code. Prove bounded native key/container behavior or establish a protected owned-parent route; avoiding value inspection does not make key lookup automatically safe. `parent.lookup` promotes a present entry, so it is not an order-neutral rejection probe.
4. **Current domain, callbacks and error identity.** Keep matching bits, scale, operand domain and work/check binding through publication and downstream use. Preserve current operand and prospective failures. The same removed downstream pi work can skip effectful callbacks; child purity alone does not prove parent callback eligibility. Native zero-callback/observer premises need actual authority. Added diagnostic or fallback checks must not swallow an original error or supply a new allowance.
5. **Order, capacity and future work.** An early insertion changes lifetime and can change cache order. Retaining the same Interval by alias is not automatically a rational copy, but it is an added retained occurrence with authority/storage consequences. Account for insertion, synchronization, capacity/eviction and later recomputation. A nonfull cache at the insertion boundary alone does not prove later neutrality. C047's no-eviction proof begins after setup and does not close this gap.
6. **Complete charged ledger and relevance.** Count child key inspection, a nonpromoting parent-absence check, safe publication, type/limit/origin work, rejection, success and interruption prefixes, startup and cleanup. Cover warm parent, empty child, unsuccessful128, later-precision success, full parent, changed cap and custom/malformed paths. A parent miss is saved only if the original downstream consumer would actually miss before anything else changes the slot. All negative paths must appear in the request ledger.

This sequence is deliberately a stop/go question. If origin, safe parent-key authority or the all-path charged bound fails, close that exact schedule without requesting a census to repair it. More observed calls do not establish an invalid premise. Only after source behavior and local/all-path cost feasibility survive should a bounded collector be designed for remaining request incidence and later-cache effects.
