## 2. Implemented design and static repairs

The [source/control-flow derivation](checkpoint-035-offset-products.md)
records the operational binding selected by checkpoint034. The existing
bounded preparation traversal selects the first generic mirrored pair of
nonstationary site/follow/fixed/grip projections with the same parent,
orientation source, axis and no-intervening-seed segment. Prepared vectors
must have an identical nontrivial plane-first component, identical axial
component and nonzero opposite second components. Selection uses source
recipes, with no fixture-name or output-track predicate.

Selection is restricted to **at most one pair in the entire prepared
plan**, stronger than checkpoint034's one-per-segment condition. This closes
interleaving between different sources and permits one fixed active watcher.
Pair and path/kind/parent metadata are sealed during the existing preparation
and final metadata passes, without another source traversal or arithmetic
charge.

For coefficients `d` and `c`, shared operand `b` and signed operand `y`, the
donor still completes its original `d*b` and `c*b` multiplications. One
immutable conditional replacement adds their sealed, detached results to
the existing coefficient record. The recipient obtains them through its
existing coefficient lookup. The original expressions remain:

```text
floor128(d*b - c*y)
floor128(c*b + d*y)
```

The signed products, combination order, outer Python floor binding,
parent-position additions, radii and final floors are unchanged. There is
no cross-clock reuse, new persistent numerical table, resurrection of an
evicted slot, or overwrite of a nested writer.

| Selected work | Original | Eligible completed candidate pair |
| --- | ---: | ---: |
| Donor's two original products | 2 | 2 |
| Same-slot publication | 0 | 1 |
| Recipient's selected products | 2 | 0 |
| Total selected charges | **4** | **3** |

This ledger includes the entire added charge. Eligibility requires native
32,768-bit live and cache-marker limits, so publication's existing
synchronizer adds no second charge. The recipient performs no additional
numerical lookup. Original coefficient insertion, source visits and
surrounding work remain. A paid publication with no reuse costs one extra
operation; only one reuse breaks even. Those fallback cases remain covered
and are not claimed as savings.

The optional fixed-shape payload preserves the original coefficient type,
four-value seal and two-value return API. It binds a fresh strong evaluation token, exact bounded
clock, source pair, detached operand and two products. Product bounds are
673 numerator bits / 645 denominator bits; the shared operand bound is
138/129 bits and the existing clock bound is 1,024 bits. The numerical cache
remains limited to 256 entries, separate from the work cache and the
512-category metadata limit.

The separate `_recording_product_after_tick` observer avoids changing the
old oracle hook's nested-route behavior. The original check runs first; an
original exception skips both observers. The product observer only latches
eligibility and integrity, without raising ahead of the original operation's
prospective guard. It spans the donor through all intervening callbacks and
the recipient's full offset, then retires permanently. Final cleanup clears
only its own hook and preserves the original in-flight exception.

Independent source/cost and lifecycle review identified and repaired these
concrete issues before the first execution cut:

- Added source and arithmetic reads could invoke callback-installed
  descriptors. Admission now precedes those reads and uses bounded native
  mappings for the extra ownership observations.
- Existing plan ownership admission did not freeze cache identity, context,
  state or node/recipe tuples. The session now retains and checks their
  strong identities and exact phase fields, including both actual source
  nodes and their roles.
- A replaced class or instance `reuse` method could otherwise authorize a
  skip after the latch became false. Actual skips, capture and publication
  now perform native admission before invoking captured original methods;
  foreign session dispatch cannot reactivate reuse.
- Current-observer dispatch and cleanup could otherwise invoke foreign
  replacements. Captured internal methods and independently captured
  cleanup preserve the checked path and original exception ordering.
- A transient cache-marker or native-dispatch departure must invalidate the
  pair even if a later callback restores its previous value. The per-tick
  latch and actual-skip admission retain that departure.

The first static review cleared runtime blobs
`0ad48d2fdf61ead9c118796ee9e3c94dd1f14ecd` (centered implementation) and
`0e98ba4c2ba0c49dbf9672ecb1c0f0fd50079dbb` (arithmetic observer). Subsequent
review found a concrete omission: Fraction inherits storage dispatch through
the mutable `numbers.Rational`, `Real`, `Complex` and `Number` bases. Pinning
Fraction's own dictionary and numeric-module class identities did not detect
a getter added to one of those base classes. The product observer could
invoke that getter during an added numerator probe; a getter that restored
itself could erase the observed departure.

The repaired runtime adds raw `_PRODUCT_STORAGE` snapshots for those four
fixed bases and pins the exact captured Fraction MRO identity before added
operand probes. It adds no semantic charge and changes no expression,
radius, cache size or watcher lifetime. Independent static review cleared
the revised centered blob `e1017c79786066e263bdc7877e318003cb61bbc0`;
the arithmetic observer blob remains unchanged. This static repair and its
required fresh validation supersede the first cut's incomplete native-proof
claim. The first cut and every executed result remain preserved.
