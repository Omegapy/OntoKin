## 2. The exact conditional identity

The target is [`_Arithmetic._atan_small`](../../../ontokin/reach_reference.py), reference lines 370–387. Preserve the original conversion, sign/range checks, square, first division, alternating sum, power update, stopping test, enclosure and grid. After iteration `k` updates `power`, it computes:

```text
following_k = x^(2k+3)/(2k+3)
term_(k+1)  = x^(2(k+1)+1)/(2(k+1)+1)
```

The two expressions are equal. The bounded carry schedule keeps the first original term division and, on a later iteration only, binds `term` to the already computed local `following`. It does not move the first division before the original loop, change the stopping test, or create persistent numerical storage.

For unchanged native rational arithmetic, induction gives identical partial sums and powers. The original first strict test remains `following < 2^-(bits+8)`. For nonnegative `x <= 1/2`, terms decrease and the alternating series lies between the current sum and the next partial sum. At even `k`, the second endpoint is `total-following`; at odd `k`, it is `total+following`. The original `min/max` and outward grid therefore receive exactly the same rational endpoints. Negative values retain the original recursive calculation and final interval negation.

Those statements assume unchanged input values, native dispatch, current domain, threshold and observer behavior. The original division performs a new tick and prospective operand check. A quotient valid at the preceding boundary is not a certificate that the next boundary still has the same domain.

## 3. Gross cost, before new admission

For a successful nonnegative call with `N >= 1` completed iterations:

| Work | Original | Carry before admission |
| --- | ---: | ---: |
| Initial square | 1 | 1 |
| First and later term divisions | N | 1 |
| Alternating sum, power update and following division | 3N | 3N |
| Final enclosure endpoint and grid | 2 | 2 |
| Total | 4N+3 | 3N+4 |

Gross room is **N−1**. These are source counts, not measured savings. All new admission, rejected-path, copying, lookup, output and cleanup work must be subtracted.

At native fixed `bits=128`, the threshold is `2^-136`. After 64 terms the next term is at most `2^-129/129 < 2^-136`, because 129 exceeds 128. Thus every successful native call in this domain stops by N=64. At `x=1/2`, the preceding next term `2^-127/127` exceeds the threshold, so N=64 is attained. The maximum gross opportunity is **63**.

The pi seeds give smaller opportunities:

| Native 128-bit argument | Iterations | Original | Carry before admission | Gross |
| --- | ---: | ---: | ---: | ---: |
| 1/5 | 28 | 115 | 88 | 27 |
| 1/239 | 8 | 35 | 28 | 7 |
| Both seed calls, if both execute successfully | 36 total | 150 | 116 | 34 |

The exact stopping inequalities are `55*5^55 < 2^136 < 57*5^57` and `15*239^15 < 2^136 < 17*239^17`. This identifies the two fixed seed calculations; it does not count request-level pi misses or `_atan_small` calls.

The helper itself has no cache lookup or publication. Its callers can bypass it through pi, target or other cached results. A resident key does not establish when or how often a constructor ran.

## 4. H1: bare carry with an incompletely admitted callback graph

H1 allows the original native arithmetic/work owners and outer construction-budget method but does not exclude all effectful nested callbacks. Its mathematical premise is insufficient.

The actual order is `_Arithmetic.tick` → `ReachExecutionWork.tick/charge` → `ConstructionBudget.tick` → its nested `check`. After a normal return, the work counter and captured source observer run, followed by the arithmetic product and source observers. Both budget classes retain the same callback exception object. [Work](../../../ontokin/reach_numeric.py), lines 38–99; [construction](../../../ontokin/construction.py), lines 55–89.

A concrete source counterexample uses native `bits=128`, `x=1/2` and a preinstalled nested cancellation callback. It raises a fixed, non-ReferenceError sentinel on its 197th call-local invocation. With all unrelated guards succeeding, the original would have 259 ticks; bare carry has 196. The original reaches callback 197 at iteration `k=48`'s following-term division and propagates the sentinel. Bare carry returns before that callback.

No candidate or hostile request was executed. This example rejects bare carry with the admitted callback, not a future gate that excludes it. Any added admission ticks change the ordinal accounting and must be included separately. No observed C047 corruption or universal impossibility is claimed.

Existing centered guards are not a complete atan admission. [`_Guard.original/current`](../../../ontokin/reach_reference_center.py), lines 233–306, installs an active observer and checks plan/batch owners, watched rational leaves, records, cells, precision and optional product-session state. Its transitive graph includes [plan and batch ownership](../../../ontokin/reach_reference_plan.py). The current product gate does not authenticate every atan helper, Fraction method, work/budget callback, global, descriptor or closure.

A hooks-None gate excludes this active observer route. Fresh canonical-target arithmetic begins with unset arithmetic observers, so some observer-free calls are plausible; neither fact establishes eligible request incidence. Current operand-cap refusal and original error identity must still be preserved. In particular, the centered observer deliberately permits the original prospective guard to report a narrowed-cap failure; early fallback cannot suppress that failure.

## 5. H2 and H3: explicit repairs and their bounds

### H2: a charged checkpoint at each omitted division

This schedule adds one actual charged checkpoint for each of the N−1 omitted divisions. Its optimistic new cost is already N−1, leaving net at most zero before any other new work:

```text
net <= (N-1) - (N-1) - A_other = -A_other <= 0
```

A bare tick is not itself a complete repair of prospective operand, method, result or callback behavior. This rejection concerns the specified repair policy.

### H3: one fresh comprehensive native screen per default-precision call

A stronger plausible route admits an observer-free, unchanged native arithmetic → work → construction-budget graph with a null nested construction check. The existing [certificate native gate](../../../ontokin/reach_conformance.py), lines 2762–2829, demonstrates why that admission includes more than an outer type test.

The reviewed H3 schedule freshly probes an explicit class-field map on each candidate 128-bit call. Its four maps contain:

| _Arithmetic | 18 |
| ReachExecutionWork | 16 |

The complete names are retained in the [authority result](checkpoint-051-reviews/authority/result.json) and [cost ledger](checkpoint-051-cost-ledger.json). They include class access/storage behavior, arithmetic and budget methods, descriptors and rational operations. This is a chosen conservative screen, not a claim that every safe gate must inspect these exact fields.

Under adopted budget-counting section 3, each new class-namespace lookup costs at least one actual shared operation. Calling the entire scan one check does not erase its internal work. These 73 probes precede additional code/default/closure/global/builtin, numeric-ABC/Interval, instance/map/scalar, callback, operand and safe-gate-charging obligations. Full authority is not claimed.

Even the class-field floor defeats this chosen default-precision schedule:

```text
maximum native128 net <= 63-73 = -10
1/5 seed net <= 27-73 = -46
1/239 seed net <= 7-73 = -66
two separately screened successful seed calls net <= 34-146 = -112
```

Higher precision can have more terms; these default-precision inequalities do not reject a separately designed higher-precision route. H3 retains the original path outside its named domain, plus whatever screening/rejection cost was actually incurred.

A more specialized or amortized screen might have a different ledger. C051 neither selects nor disproves one. Such a design still needs a protected authority lifetime, complete current-state/error proof and positive whole-request bound; a remembered native Boolean is insufficient.

## 6. All paths, lifetime and whole-request limits

The [machine-readable ledger](checkpoint-051-cost-ledger.json) retains all-path costs and unknowns. Important boundaries are:

- Zero and other one-iteration native calls cost 7 under either arithmetic schedule before new admission. They offer no gross saving.
- Successful negative input retains the inner positive computation and one final negation tick. Any outer and inner screening costs are additional.
- A native out-of-range argument fails before a successful arithmetic tick. Earlier screening still costs actual work; malformed conversion/comparison and custom dispatch retain their original effects and failures.
- The original square precedes loop-domain evaluation. The first division must not be hoisted into empty or malformed-loop paths.
- For M completed nonstopping iterations, original cost is `1+4M`, versus `2+3M` before admission. A failure inside the next operation needs its exact event ledger. An attempted callback need not increment both counters.
- Nonconvergence, narrowed limits, changed precision/scale, interruption, rejected gates and caller cache hits do not inherit a completed-call saving.
- Both schedules already hold the local `following`. Rebinding a local reference is not automatically a copied rational or persistent cache slot. If a proposed repair adds copied values, retained owners, wrappers, output occurrences or storage, its actual cost and lifetime must be charged.
