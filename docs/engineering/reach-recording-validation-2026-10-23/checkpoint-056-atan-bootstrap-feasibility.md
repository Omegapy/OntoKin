Date: October 27, 2026, America/Denver. Owner: interactive-reach06-atan-bootstrap-20261027-c056-6e4b. Branch: work/reach06-atan-bootstrap-20261027-c056-6e4b. Source: C055 commit 8000959ad25e89d1794d1401c0f8c2960bcd18fc, tree 5282f90bc12c321c67829ce6d7ce62c891b32424. [Declared source scope](https://github.com/Omegapy/OntoKin/issues/26#issuecomment-6455640385).

**The specified R56 checkpoint-reassignment schedule is NO-GO.** It retains the original cold-pi expression, atan entry, square, F(0), loop setup and pending first-term exact frame. It gives each new lookup, comparison and rejected arithmetic continuation separate funding. Nevertheless, an added charge can run a callback or budget check before the original pending F(a) call. That changes which exception occurs first.

This is a conditional source counterexample to one explicit schedule. It was not executed as a hostile request or numerical experiment. It proves neither universal impossibility nor a recording outcome. Complete safe admission cost and positive whole-request saving remain unknown. The required first-stage stop applies before endpoints, implementation or a collector.

The [frozen schedule](checkpoint-056-schedule.json) specifies every state, funding assignment and witness. The [cost ledger](checkpoint-056-cost-ledger.json), [source binding](checkpoint-056-source-binding.json), [independent reviews](checkpoint-056-reviews.json), [actual validation](checkpoint-056-validation.json) and [next scope](checkpoint-056-next-scope.json) retain their separate meanings.

## 2. Original events and the active continuation

The original cold pi expression captures remember before evaluating its value argument. Within that argument, it captures sub, first mul with scalar 16, and first atan before calling atan. The later second mul and atan remain future lookups; capturing them early would itself change the original event order.

The first positive atan performs F(value), sign and upper-domain comparisons, including F(1,2). It calls the original exact square. That square's tick, conversions, guards, finite prospective checks and actual multiplication complete. It then evaluates F(0), assigns power/total, creates the range iterator from bits+8, obtains k=0 and captures the first-term exact call with a=power, b=1 and kind div.

Inside that original exact frame, self.tick() runs before the line assigning F(a), F(b). The proposed seam is immediately after the tick has returned normally, before either conversion. The following state remains active:

| Frame or pending expression | State retained |
| --- | --- |
| pi | self, key, cold result, original remember/sub/first mul/first atan call targets and the original pending arguments |
| atan | self, value, completed square, power, total, k=0, original range iterator and pending term assignment |
| exact | self, a=power, b=1, kind div; execution resumes at its original F(a), F(b) line |
| Later computation | Original dynamic guard, operand/domain/operator reads and later loop/caller expression evaluation |

The arithmetic tick captures ordinary and product observers before invoking check. Native shared work captures its work observer before the external callback, checks operations and elapsed time, increments the successful operation/category and runs that captured work observer. Arithmetic then runs its captured product observer and ordinary observer. R56 reaches admission only after all of these original events have returned normally. An original earlier exception propagates before admission.

Saving this continuation repairs the earlier expression-restart defect. It does not make the pending F conversion passive or give an added operation free funding.

## 3. Frozen event and funding states

Let U denote the unit successfully charged by the original first-term tick. R56 specifies:

| State | Event | Funding |
| --- | --- | --- |
| I1 | Read currentF from the active exact function's globals dictionary | Reassign U to this one new lookup |
| Q2/I2 | Obtain a new callback-bearing charge, then compare currentF with the expected native Fraction reference | New unit V pays this one identity comparison |
| QR | If unequal, obtain a replacement charge for the displaced original exact operation | New unit W |
| R | Resume the existing exact frame after its original tick, with the original arguments and pending caller state | W pays the original exact operation; later original operations retain their own charges |

The schedule does not count a new read and an identity comparison as one established unit. U, V and W have disjoint purposes. The previously completed square's charge is already spent.

For a strong counterexample, the schedule grants valid prior provenance for the globals dictionary and expected Fraction reference, a passive bounded raw lookup, harmless native identity comparison, authentic charging and continuation storage without finalizer/concurrency effects. These are explicitly favorable assumptions, not a complete admission implementation. A real accepted route would have to prove and fund them. The failure below remains even if they are granted.

The equal branch stops at an unselected remaining-authority stage. C055 requires rejection as soon as first-stage bootstrap fails. Designing further authentication or endpoint construction after that failure would not establish a viable candidate.

## 4. Three conditional source counterexamples

### W1: failure while buying the comparison

Take otherwise native arithmetic and ReachExecutionWork, absent work/arithmetic observers, adequate ordinary limits and two preexisting distinct exception objects E and B. All earlier callbacks return normally.

At the original first-term tick, the external callback changes the module's F binding to an existing callable R that raises E when called, then returns normally. The next callback raises B. No endpoint values are required.

The original continues at F(a), calls R and raises E. It never reaches that next callback.

R56's I1 reads R and spends U. Q2 invokes the next callback to buy the comparison and raises B before the comparison or pending F(a). A correct later identity check cannot repair a failure that has already occurred.

### W2: failure after the identity check rejects

Use the same setup, but let the Q2 callback return normally and the following callback raise B. R remains different from the expected Fraction reference.

The original still raises E immediately at F(a). R56 reads R, buys and performs the identity comparison, rejects, then invokes QR. QR raises B while trying to fund the pending original exact operation.

This witness reaches the rejected path. Original call frames and locals are preserved, and the ledger avoids double spending, but repayment before resumption still changes exception priority. Swallowing B would violate callback exception identity. Returning to the saved arithmetic afterward cannot undo B's occurrence.

### W3: a smaller remaining allowance

Keep the normal callback that installs R. Choose a valid lowered work allowance such that U succeeds by incrementing the count from L−1 to L, the maximum. Subsequent external callbacks return normally; elapsed and operand limits are otherwise adequate.

The original already funded its pending exact operation. It calls R(a) and raises E before another work-limit check.

R56 spends U on I1 and attempts V. The native work charge sees the exhausted allowance and raises its resource error before R(a). No raising future callback is needed.

These are exact source-order arguments. They do not establish that a particular source recording reaches this seam, or that an arbitrary changed environment would pass a complete gate.

## 5. What the accounting establishes

C055's inherited structural factory opportunity remains 163, excluding original lookup and final remember. Conditional on inherited N5=28 and N239=8, positive atan uses 4N+3 operations. This gives 115 and 35; two five-operation multiplications and a three-operation subtraction give 163. No new strict-stop or native endpoint calculation was performed.

The seam distinction matters:

| Location | Original numerical work still unexecuted, 1/5 / 1/239 | Original future charge units, 1/5 / 1/239 |
| --- | ---: | ---: |
| After completed square, before first-term tick | 114 / 34 | 114 / 34 |
| After first-term tick U returns, before its arithmetic | 114 / 34 | 113 / 33 |

The already paid U can be reassigned in the proposed ledger only by removing its funding from the pending original arithmetic. It is not an additional free unit.

For a hypothetical matched completion, counting from after the square includes 114 and subtracts the new lookup funded by U once, plus all other new work. Counting from after U starts with only 113 future original units and subtracts additionally charged candidate work; U must not be deducted a second time. Neither representation supplies a positive bound for a schedule whose failure behavior already differs.

If V, W and the resumed original first term all complete on a rejected path, the candidate has used three successful units for that local prefix instead of the original one: two extra successful units and no omitted-arithmetic credit. W1/W2/W3 do not necessarily reach that completed prefix. Native shared work calls external_check and performs resource checks before incrementing its own counter. A reached failed charge is therefore not automatically an incremented operation. Construction counters, when a native construction callback is actually present, have their own order.

Complete gate cost, setup incidence, remaining-request convergence and whole-request net saving stay unknown. No 164- or 180-operation universal floor is adopted. The result rests on observable order, not an asserted numerical overbudget proof.

## 6. Dependency slice and remaining proof limits

The rejection needs only a finite reached slice: the active exact globals F binding, saved exact arguments, raw lookup/identity primitives, genuine charging route and its callback/resource state, completed observer sequence, and the suspended atan/pi continuation. Native work can invoke a nested construction callback, whose own check, counters, limits and exception behavior remain relevant when present. The counterexamples choose the simpler supported external callback route and do not need that nested callback.

For an admitted atan tail, the broader C055 used-state inventory still applies: actually used arithmetic helpers, Fraction constructors/operators/descriptors and used delegates, Interval construction, work and construction authority, passive bounded storage, observers and runtime/lifetime closure. This review does not authenticate those dependencies. An unchanged function identity alone does not establish its code, globals, used cells or descriptors.

The original outer multiplier/subtraction/remember work is retained by a tail proposal; it is not new omitted-tail credit. Unrelated target-owner state, completed-child metadata and arbitrary tag scans remain outside this reached proof. Excluding them does not resolve U's displaced-work funding.

The first-stage witnesses remain valid under generous safety grants. They reject this schedule without claiming that every possible admission location or optimization is impossible.
