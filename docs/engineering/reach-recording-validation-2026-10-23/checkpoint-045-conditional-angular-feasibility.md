## A concrete conditional design

The reviewed proposal is **B-Angular/full-entry-audit/0.1**. It is limited to the first excess-construction loop of one native captured phase. Its admission conditions depend on actual bounded structure and numerical inputs, never a fixture name, frame name, arm count, source identifier or selected request option.

1. Keep the original per-bound domain/selector checks and whole-result lookup/hit behavior. Do not substitute a prefix for a warm whole result.
2. Consider a batch-local prefix certificate only under exact native source/work/storage dispatch, the full current 32,768-bit domain and a closed interval in which all surviving checks and cache operations have authenticated effects. Lowered limits, custom callbacks, observers or foreign dispatch retain the original path.
3. Apply a conservative structural profitability screen using the batch size `N` and actual current cache size `C`: require `13*(N-1) > 2*C`. This grants every call after the first as a potential hit before examining its signature. It is a necessary condition only. Signature discovery, key construction, authority checks and the screen itself are charged; none is free runtime work.
4. On a potentially profitable admitted route, traverse all `C` existing cache entries. This specific schedule charges one key admission and one value/lifetime admission per entry. Recursion, mutable category-map admission, native budget and dispatch checks, hooks, copies, per-use receipts and cleanup are additional work. A separate provenance-based or fixed-block audit is a different design.
5. Preserve the whole-cache keys, lookup/insertion/promotion/eviction order and capacity. The proposed seed would place immutable integer-pair prefix data in an optional private payload of an existing whole-result slot. At most one seed would be usable within the current batch. No second numerical cache, extra entry allowance or numeric result retained after loss of the live seed would be authorized. Any transient reference and private payload must retire before the batch returns or fails, with charged cleanup. This storage proposal still requires a complete implementation-level lifetime proof.
6. The seed call executes its full original cold calculation. A reuse could substitute only `source_leaves`, `e`, `g` and `q` at the prefix boundary, after matching current native integer snapshots of `t`, `c`, the exact numerator/denominator of `sq`, constants, method and current domain. All original intermediate operand/prospective/result guards must be established before omission. Copied or reconstructed logical values are charged.
7. Keep ordinary and dynamic position arithmetic, short-circuit comparisons, late multiplication, optional radii, whole publication and warm/cold return behavior at their original locations. Decline any optional step whose authority cannot be established, then follow the complete original calculation. No observer, callback or budget exception may be swallowed or translated by the optional path.

The proposal deliberately leaves the **late multiplication unchanged**. That removes one additional callback-separated reuse problem and limits the current opportunity to `13*31 = 403`. C044's 434 includes another 31 late sites and is not this candidate's saving ceiling.

This is a precisely rejected design, not a claim that the unfinished storage or authority proof has passed. The cost rejection below grants those remaining proofs and their costs optimistically; resolving them cannot rescue this admission schedule for the current group.

## Why the existing phase does not supply authority

[`ReachExecutionWork.charge`](../../../ontokin/reach_numeric.py) can invoke the external check and a previously captured source observer. It also reads and writes a mutable native category dictionary. Exact class identity alone does not authenticate instance overrides, dictionary keys/values, bound callback ownership or current limits. The compiler normally passes its `ConstructionBudget.tick`; that budget can itself invoke a check callback and has mutable limits and counters.

The existing captured phase is not a sealed native-work interval. `Binary64RecordingOps._require_domain` checks its numerical/Cartesian domain, while `_PhasePublication.admit` checks source and bound records. Those are useful checks for their existing contracts; they do not establish that every category update or whole-cache operation is free of foreign dispatch.

The bound records also retain Fraction references. Shallowly frozen dataclasses and a tuple of those references do not freeze each Fraction's backing numerator and denominator. New reuse therefore needs current integer-field snapshots and fresh source authority; object identity or an equality comparison against the same alias does not supply that proof.

The cache is an externally reachable `OrderedDict`. Membership and retrieval can execute equality behavior from a stored key, and eviction can release objects with finalization behavior. Its identity, length and work generation do not prove that every retained key and value is safe; direct dictionary mutation need not update the work generation. A batch proof spanning all those operations needs explicit current cache authority or a separately proved provenance mechanism. No such provenance mechanism is established by this checkpoint.

A narrower gate immediately after each original whole lookup could avoid spanning a cache operation inside the omitted prefix. It would require fresh work/count/callback authority after each preceding cache boundary. This is a different schedule, with different costs. C045 establishes no positive bound for it. Installing a new observer would be a further design with its own charged lifetime and interference proof, not an existing free mechanism.

## A useful numerical sub-proof

For a prospective conditional domain, require nonnegative native integers `t,c`, native canonical nonnegative Fraction `sq`, each integer numerator/denominator width at most **2,048**, the unchanged constants `AXIS_ERROR = 2^-74`, `PRODUCT_ERROR = 2^-91` and `MAX_RECORDING_ROTATION_STEPS = 10,000`, and the full **32,768-bit** cap.

For numerator/denominator bit bounds `(a,b)` and `(c,d)`, multiplication needs at most `(a+c,b+d)`. Addition needs at most `(max(a+d,c+b)+1,b+d)` before reduction. Rational reduction cannot increase either width. Applying these conservative rules in the original expression order yields:

| Completed prefix value | Numerator-bit upper bound | Denominator-bit upper bound |
| --- | ---: | ---: |
| `source_leaves` | 2,050 | 2 |
| `e` | 2,102 | 94 |
| `g` | 2,157 | 170 |
| `q` | 4,327 | 2,314 |

All 13 operand, unreduced prospective and result bounds fit within **4,327 bits**, below the unchanged cap. The full 13-step derivation and actual recorded angular-site widths are retained in the metadata audit. Current `sq` has a 1,075-bit denominator, so an arbitrary 1,024-bit gate would miss the observed inputs; the 2,048-bit domain covers their numerical width.

This is a numerical guard theorem only. It requires authenticated exact constants, native arithmetic and stable current authority. It proves neither the `e/q <= 1/64` predicates nor permission to move them. Both comparisons stay after position work, and failure at the first comparison still suppresses the second. It proves no cache eligibility, cancellation equivalence, storage lifetime or net saving.

## Closed cost result

Let `H` be completed prefix substitutions, and `C` the entry cache size. This batch starts with no private seed, so `H <= N-1`. The explicit full-entry audit schedule spends at least `2*C` charges. Every other added admission, signature/key operation, copy, storage operation, fallback, return check and lifecycle cost remains nonnegative.

For the idealized route that preserves whole-cache behavior exactly, grant its other work difference as zero. If that equality cannot be proved, admission is unavailable; no favorable displacement saving is assumed. Then:

`saving <= 13*(N-1) - 2*C`.

| Retained/current value | Value |
| --- | ---: |
| Batch calls `N` | 32 |
| Maximum prefix substitutions | 31 |
| Prefix gross ceiling | 403 |
| Existing cache entries `C` | 256 |
| Defined admitted-route audit floor | 512 |
| **Optimistic saving upper bound if forced through the audit** | **-109** |

The correctly conditional design rejects this group at its profitability screen: **`403 > 512` is false**. It therefore performs zero prefix substitutions on this group, plus whatever charged screening work its eventual implementation would require. It does **not** actually perform the 512-charge audit after that rejection. No candidate exists here, so neither branch is a measured candidate cost.

Even granting the unselected late reuse, the optimistic upper bound is `434-512 = -78`. At a full 256-entry cache, prefix-only reuse needs **at least 41 calls** before this audit floor alone could be overcome. That is a necessary threshold, not a sufficient admission rule or proof that a 41-call request benefits.

C043's singleton cold examples and 32-distinct-signature example remain rejected for its unconditional design. The new cost screen does not turn them into profitable work; singleton groups have no repeat, and distinct signatures yield no reusable prefix. C045's screen uses an optimistic repeat ceiling, so passing that screen never substitutes for actual signature and cost checks.

The selected floor is **specific to this two-admissions-per-entry audit policy**. A different selective audit, a proved entry provenance mechanism, a fixed-size block policy or a cache-free arithmetic reduction needs its own review. The 1,656 immediate key children are not a universal charged lower bound. The category count at batch entry was not captured, and the final 222-category map is not silently treated as the entry map.
