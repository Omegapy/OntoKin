## Objective

Produce one reviewable protocol and a hash-bound selection of existing fixtures
for a small localized-assembly-repair pilot. The protocol must allow a later
thread to implement and run a fair comparison without inventing its scoring or
decision rules after seeing results. This step prepares evidence; it does not
produce a comparative result.

Begin with the [C210 keyed-component edit](../semantic-export-c210/DECISION.md)
and [C180 comparison principles](../semantic-physical-scope-c180/README.md).
Select supported edits and unchanged-sibling requirements from actual existing
source. Do not reopen the frozen rotary or tray schedules, change their fixtures
or thresholds, or add syntax to make the prospective corpus possible.

## Required deliverables

1. A protocol stating the research question, task population, eligible supported
   semantics, proposed pilot size and repetition policy. Separate feasibility
   from any later confirmatory claim. Identify related variants of one assembly.
2. A machine-readable corpus manifest naming exact existing source paths,
   hashes, dependency closure, requested edit, permitted changes, forbidden
   collateral changes and applicable output checks. Keep evaluation cases out
   of the agent's demonstrations. If the current fixture pool cannot support
   the study, record that specific gap rather than silently expanding scope.
3. A route/applicability matrix for OntoKin, direct Blender/Python and
   OpenUSD-native authoring. Record required versions and available tools;
   distinguish unsupported semantics from an unavailable environment. Do not
   require a new `.ok` exporter merely to author an OpenUSD baseline.
4. A scoring specification with independent oracle inputs, success denominators,
   invalid-edit cases, provenance/locality checks, missing-output and timeout
   rules, and complete failure retention. Plan positive and adversarial oracle
   controls for the later implementation; source-generated expectations alone
   cannot establish correctness.
5. A run/analysis plan freezing the same model snapshot/settings, information,
   tool access, token/time limits, route order, trial pairing, setup-cost
   accounting and uncertainty method. Resolve the provisional 20-point/30%
   thresholds, primary endpoint and success noninferiority margin explicitly;
   document any justified alternative before trials.
6. An independent review and a short proceed/block decision. State the exact
   next implementation boundary, its prerequisites and its stopping rule.

## Completion condition

The selected source references and hashes verify, the planned checks are
independent enough to detect the specified failures, all baseline limitations
are visible, and the methodology is internally consistent. Run documentation
and manifest checks appropriate to these artifacts. Save the reviewed protocol,
existing-fixture bindings, unresolved limitations and restorable source in the
next verified handoff, then stop.

Do not implement the runner, execute model trials, launch Godot/Blender, add an
adapter or generate new assets in this protocol step. If an indispensable
capability is missing, finish with a precise, evidence-backed blocker and the
smallest next action. A blocker does not authorize switching to C251 sampling
or another unrelated feature.
