# C194 preparation protocol

This is coordinator setup for a later public edit-and-reuse comparison. It is
not an author trial or evidence of comparative advantage. C193 is integrated at
`3c9fcaa4daff7b32e7b813ba05041212c1a5bc2f`; its six qualified cases and original
C192 failures retain their recorded meanings.

The starters both specify a 380 mm left stop. Each target source changes only
that coordinate. The left shoe collider stays enabled. Exactly seven visible

C191 fixture with only the explicit C193 bindings and target coordinate changed.
Direct Python contains a literal design and does not parse the .ok source.

The selected source is `c193-experimental-0.1`, backend
`blender-bullet-c193-0.1`, and output `glb-guided-contact-0.1`. All v02
implementation and contract bytes, the shared constructor, independent readers,
receiving tools and their dependency archive are pinned in `INPUTS.json`.
No product or historical file is edited.

## Freeze and execution order

1. Review this preparation and the complete input inventory before native work.
   The independent receipt must approve the exact SHA-256 of `INPUTS.json`.
2. Run `seal.py` once with that receipt. It records the input/review identities
   in `FREEZE.json` before either target can execute. Commit the sealed state.
3. Run the fixed matrix once: `ok-G`, `python-G`, `ok-H`, `python-H`.
   Each target therefore has at most one fresh .ok and one direct-Python build.
4. Independently reopen each saved scene with the unchanged C193 inspector
   extended only by G/H case data. Clear the cache, inspect configuration, then
   reproduce all 481 samples without constructing or repairing any geometry.
5. Compare the actual four deliveries; run the unchanged receiving tools;
   review all twelve original imported-output panels; finalize qualification.
6. If any required gate fails, stop before author dispatch. Record the exact
   failure and propose a separately reviewed next action.

The source-directory `EXECUTION-LEDGER.json` is created exclusively before the
first native command. The runner refuses a second invocation, even with a new
output directory. It reserves each build before starting it and writes command,
stdout, stderr, return status, duration and available operation costs. An
interruption has an unknown outcome until the receipts and processes are
reconciled; do not delete the ledger or repeat a reserved constructor to recover
missing information. All four predeclared builds may finish after an earlier
gate failure to retain both-route evidence; no author may start on a failed target.

## Unchanged gates

The historical source, geometry, numerical and continuous rules remain exact.
G and H are both enabled positive contact cases: maximum penetration 0.5 mm,
contact onset within 5 ms, settling after 25 ms, residual speed at most
0.5 mm/s, rebound at most 0.1 mm, fixed/attached drift at most 0.1 mm, and all
twenty unrelated swept-pair checks. The geometry tolerance remains 0.2 mm.

Native-sample vertex error, raw-sample vertex error and the conservative
continuous raw-to-final bound each remain at most **0.2 mm**. All 481 native
frame/240 samples and the float32 carriage X/time values are preserved.
The extension changes only in-memory G/H case dictionaries. No original
reader, solver setting, recording code or bound is changed.

Each native replay must reproduce the complete 481 decoded sample records
exactly, including every matrix and bound. Original and independent serialized
file hashes are retained; JSON layout differences are not motion differences.
Both actual authoring routes must have byte-identical canonical inputs, native
traces, raw GLBs and final GLBs. The saved Blender files may differ in source tags
and binary serialization. The base and complete right-lane native trace must
also equal the retained historical baseline across both targets. Independent
source manifests, implementation copies, native command/test-hook settings,
source tags, body ownership and guide/motor frames are checked.

Receiving checks require zero Khronos errors and warnings for all eight raw and
final paths, twenty-four Three.js sampled poses and four actual Blender imports.
The final GLBs are rendered at zero, ideal contact and two seconds; all twelve
original panels require visual inspection. A receiving or visual failure fails
qualification even if native and numerical checks pass. A successful render
cannot override a failed source, native or mapping gate.

## Finite allowances

Each build retains the C193 request/host allowance of 1,000,000 operations and
80,000 ms; its unchanged build wrapper has a 100-second watchdog and the
coordinator supervises the complete wrapper for 110 seconds. Each independent
scene replay has an 80-second watchdog. Format and Three.js commands each have
120 seconds; the four-import render batch has 300 seconds, with a 570-second
outer receiving watchdog. A timed-out process group is terminated and no
automatic retry is allowed. These are computation allowances, separate from the
two-second modeled motion. No provider token/cost or exact model snapshot is
available from these command receipts; absent data is reported as unavailable.

Source parsing/static review, frozen-input verification, historical record
reading and dependency preparation may precede native execution. No preliminary
native target sweep, hidden extra constructor, alternate target, solver tuning,
sample retiming, projection change or tolerance increase is allowed.

## Conditional public comparison

Only a passing `QUALIFICATION.json` permits the next public protocol to be
frozen. That later protocol must explicitly name these prepared inputs, shared
backend, two default fresh authors with empty histories, equal declared budgets
and inspection access, matching 380 mm starts, the 365 mm first edit, and the
375 mm reuse from each author's own accepted source. The first accepted result
must be preserved and exactly regenerated during reuse. Author performance and
coordinator setup remain separate. This preparation alone dispatches no author.
