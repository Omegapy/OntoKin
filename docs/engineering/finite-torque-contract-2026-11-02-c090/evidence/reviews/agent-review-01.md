## Findings resolved before approval

**Agent schema ID collision.** The first draft reused the `.21` canonical `$id` for all three new transport schemas. That would let a schema registry silently replace predecessor definitions. The author assigned distinct `.22` IDs and included those scalar changes in the derivation. Independent rechecks found no collision and no undocumented inherited scalar removal or change. The original draft remains in `torque-v0.1/review/preparation/agent01`.

**Recording axis spelling.** Root's separate recording review found `world.x/world.y/world.z` in the recording profile while the source, state and catalog used underscores. Author amendment 02 fixes the exact identifiers and retains the initial bytes. This review accepts the corrected complete profile and explicitly refuses the dotted-axis mutation. The review is bound to amendment 02, not the original inconsistent schema.

The current successful-discovery shape requires `torque_interface`; successful resolved-object source projections require `torque_intervals`; every complete object state requires `torques`. Existing broad response portions remain open by inherited design. The newly added torque/catalog/recording records are closed. Schema closure of new records is not confused with wholesale tightening of inherited response objects.

## Static source and Agent contract assessment

The explicit source `0.22` / `torque-0.1`, Agent/0.22, GLB/0.22 and separate durable store binding are coherent. Earlier service defaults and store meanings stay intact. All changes to motion remain source-authorized; the contract does not introduce a host torque mutation API. The twelve inherited operation transports, immutable source/module/image closure and existing diagnostic envelope remain the basis of the extension.

The new source record has immutable target/interval/program identity and real UTF-8 statement, operand and duration spans. Object inspection distinguishes resolved occurrence histories from definitions, imports and source-only unavailable projections. Repair authority remains the accepted original source span with source/program revision and dependency-pin preconditions. Failed candidates cannot acquire an accepted run or artifact merely by retaining a diagnostic snapshot. Scoped source edits must preserve unrelated sibling, pinned library and PNG bytes, and accepted revisions cannot retroactively alter old run/artifact history.

The complete state separates sticky axis admission from the legacy/split motion route. Before first activation, angular projections are null and histories are empty. Zero activation still latches the axis and creates actual records. The first committed nonzero final canonical acceleration can arise from either activation or completion. Underflow and cancellation retain reference/error history without creating a canonical rotation anchor. Counts and recent records cover complete committed boundaries, and unrelated boundaries retain the last torque change. Self-frame inspection leaves the torque axis/scalar/history world-referenced.

The numerical source contract specifies exact represented clocks, exact final-set torque summation followed by the stated canonical roundings, inherited admitted own-sphere inertia and ordered intermediate impulse checks. It separates rotation from translation anchors and requires full internal rotation/error retention. The phase-domain proof explicitly includes the stationary point where it lies in a requested segment. Reference/error-origin updates remain separate from canonical anchors, so a changed ideal reference with unchanged canonical acceleration cannot disappear. A later numerical reviewer must still establish the complete recorder and supplied-byte proof; these shape checks do not substitute for that review.

The structural work contract includes genuine reference-origin initialization/change/transfer work and projection headers for empty and noncarrier states. It preserves original admitted request authority, budget, start/deadline, cancellation callback identity and final atomic commit. Every new execution needs current host/caller authority; source requests and saved successes are not grants. A terminal same-ID retry is explicitly a historical result, while a fresh ID requires fresh policy checks. That distinction avoids both replayed effects and false claims of current authorization.

The durable workflow contract requires independent read-only database inspection and exact source/request/run/artifact linkage. Unknown outcomes must be reconciled against real durable state. Cancellation, callback exceptions, response caps, staged artifacts and interrupted publication require atomic accepted-state behavior. No producer response alone counts as database evidence. Exact artifact slice/EOF/overrun semantics and immutable complete-byte reconstruction remain specified, including lower fresh retrieval caps without destructive artifact loss. Controlled `.22` playback remains a separate future adapter and cannot be inferred from the old `.6` player.

## Semantic checks that schemas cannot establish

Both contracts correctly require independent semantic readers. The probes deliberately preserve schema-valid examples with unreduced rationals, mismatched state counts, wrong interval end arithmetic, inconsistent stored clock bits, unresolved source phase indices, invalid interval-key membership and a certificate total that does not cover its components. The shape validators accept these examples as expected. Independent source/state/native-byte readers must refuse them through actual semantic checks.

Finite native-number admission, exact bit ceilings, accepted source pins, actual clocks and side/prefix, canonical sums, axis chronology, historical membership, source-derived radii and derivative bounds, full inequalities, policy authority, SQLite atomicity and complete artifact identities are runtime and independent-reader obligations. A digest-shaped string or nonnegative number is not proof of the claimed fact. The recording schema's `all_values_independently_recomputed` field is a claim to verify, not verification by itself.
