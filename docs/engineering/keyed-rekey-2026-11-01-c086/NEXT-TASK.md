## 2. Utility to review

C086 can rename a finite collection using explicit String literals, conditional selections or a supplied `Keyed<String>` map. Its adoption expressly excludes generic prefix synthesis. A reusable library therefore cannot yet compute `prefix + old_key` for newly supplied member keys without another explicit rename map. A narrowly bounded pure String concatenation operation would make namespaced reusable component groups practical for variable input collections while retaining the original payload and key provenance.

The representative task is a pinned component library instantiated twice, each occurrence receiving an explicit prefix and a finite collection of named parts. The library computes each output key from that prefix and the original key. An agent inserts or reorders input members, changes one occurrence's prefix through an exact source edit, and composes independently namespaced collections while preserving the other occurrence, source libraries, payload geometry, materials, textures and independent animation.

This advances the GOAL's typed reusable programs and scoped inspection/repair. It is not evidence of a measured authoring improvement. Preserve the requirement for a direct-tool baseline, unseen variants, repair effort, cost and quality before making such a claim. This proposal follows directly from the demonstrated C086 namespace boundary; broader modeling and physical capabilities remain required future work.

## 4. Proposed semantic boundary

The proposed operation accepts exactly two immutable String operands and returns their exact ordered Unicode scalar sequence. It introduces no numeric, Bool, key, reference or other implicit conversion. Existing numeric/vector `+` keeps its adopted meaning. Decide and freeze left-to-right evaluation, one evaluation of each actual operand, static checking of both operand types under unknown typed local values, inherited branch checking, and the precedence of operand, resource and publication failures. Empty String is a value, not a reason to omit required evaluation, dependencies, taints or work.

Version semantics belong to the unit declaring the expression. An imported `.19` helper must continue to reject String `+` when called from a newer entry. A newer caller cannot grant a pinned older definition new syntax or meanings. Cover ordinary source expressions, pure helpers, default/derived members and nested keyed callbacks, including statically checked empty collections and unselected branches. Do not broaden module identities, headers, source IDs, import pins, writable source spans or patch authority into computed Strings.

Preserve LANG-001's exact lexical boundary: raw UTF-8 scalar text and the already supported escapes remain valid; a backslash followed by `u` remains an unsupported escape. No normalization, case folding, trimming or automatic escaping is added. Combining sequences stay distinct from precomposed characters. Source coordinates remain original UTF-8 byte offsets.

A valid ordinary String is not automatically a valid stable key. Passing a concatenated result to `rekey_keyed` still enforces the exact 1–64 ASCII-character key rule and inherited collision order. A 65-character ASCII String can be valid concatenation but fail as a key. Unicode, whitespace, empty or otherwise invalid computed keys retain the rekey refusal; no truncation, generated suffix or overwrite repairs them.

Do not add interpolation, formatting, replacement, splitting, slicing, repetition, parsing, String ordering, String length APIs, new collections, mutable text or I/O in this increment. `len()`'s existing keyed meaning is not authority to add a String overload. Preserve every actual read, relevant definition dependency, generated-view taint, source revision and inherited keyed origin. Concatenation must not rewrite an earlier zip/rekey key or turn the payload's original entry span into a fictitious literal declaration of the computed name.

## 5. Resource decision required before adoption

The reviewed implementation bounds aggregate source text at 2,000,000 bytes and bounds encoded inspection/provenance JSON separately. `charge_value` counts logical values and collection entries, not String bytes. Those limits do not, by themselves, bound computed concatenation before allocation. The execution-header scanner's 65,536-byte and 256-character constants are header limits, not general String limits. Do not cite them as an inherited concatenation allowance.

Choose and justify an explicit maximum UTF-8 byte length for each newly computed concatenation result, with a fixed work schedule and current-ledger cancellation checks before allocation and publication. A 65,536-byte result cap is a concrete candidate for review: it supports general labels beyond 64-character keys while keeping one result finite. It is not adopted here and must not be tuned after seeing candidate performance. Review whether a smaller useful bound is preferable and whether a cumulative computed-byte allowance is necessary. A per-result cap alone is not a satisfactory whole-request allocation argument when many results or repeatedly doubled Strings can be retained.

The final contract must name byte versus code-point units; the exact charge quantum; bounded scan/checkpoint cadence; accounting for both operands and result copies; the point at which oversize is diagnosed; and how aggregate request bounds constrain total materialized bytes. Checking size by first encoding or joining an unbounded value is insufficient. Existing large authored Strings must remain valid under their original rules unless a separately justified versioned change explicitly says otherwise; using one as an operand of the new operation still needs the new operation's bounded admission.

Constant folding, parameter/helper caches, repeated references, empty operands and identity-like concatenations require explicit review. No path may bypass current authority, resource admission, required charging, taint/read replay or cancellation. Freeze observable stages and exact diagnostics before implementation, including unknown abstract evaluation without value-dependent allocation. Failed construction, cancelled work, exhaustion or interrupted publication must leave no partial accepted collection, revision, run or artifact.

Keep the ordinary 100,000-operation / 30,000-ms defaults. Higher entry-program requests require independently current host ceilings, and caller caps only reduce authority. Modeled duration is separate. Preserve unrelated parser, type, expression, call, value, collection, asset, request and serialization caps. New higher-budget evidence never passes an old fixed-budget gate retroactively.
