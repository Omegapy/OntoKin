# Proposed C192: public authoring comparison on one qualified backend

**Status: later task, conditional on completed C191 qualification and integration.**
First read the delivered checkpoint, current GOAL, AGENTS and STATUS, then
reconcile the actual GitHub refs, pull requests and integration lease. If C191
has an unmet gate or is not merged, finish that work before dispatching a
comparison. Do not substitute this proposal for a missing C191 result.

Start exactly two fresh subagents in this conversation's execution environment,
with `fork_turns="none"` and default settings. One will edit the explicit C191
experimental `.ok` source; the other will edit a direct Blender/Python starter.
Use separate directories and branches. A separate host or isolation preflight
is not required. This is a public shared-environment exercise, with no claim
that either participant cannot inspect the other route or the evaluator.

## Question and bounded task

Can each route make a localized left-stop edit, preserve the rest of the
seven-part assembly, regenerate native contact and later reuse its edited source
on the same pinned Blender/Bullet backend?

Prepare equivalent editable starters at the qualified 380 mm left-stop position.
The proposed first target is 362.5 mm and the proposed reuse target is 372.5 mm.
The initial left shoe face is 180 mm and the feed is 125 mm/s. Thus their analytic
contact times are 1.460 s and 1.540 s, with final left travel 182.5 mm and
192.5 mm. In both cases the right lane must retain 300 mm travel and 15 mm
clearance. These are proposed task inputs and analytic expectations, not new
measured results.

Before either participant starts, the coordinator must freeze the exact brief,
starter bytes, expected outcomes, fixed C191 tolerances, time/attempt allowances
and evidence requirements. Confirm that both starters use the same executable,
native body/helper mapping, guides, constant-feed motors, solver settings,
initialization, capture rate and permitted playback projection. A different
native shape construction or motion authority is not a same-backend control.

Provide both routes the same inspection tools, independent checker, output
requirements and documented export/projection utilities. The direct route must
retain an editable Python design and build the native scene; the `.ok` route
must use its accepted source and the explicit experimental adapter. Neither
route may hand-edit the recorded trajectory, substitute a timed stop, change a
gate, or repair a delivered scene after the formal submission.

Use the qualified C191 native constructor and captured-pose GLB binding as the
common execution and delivery baseline for both routes. The direct Python
starter can supply the equivalent design data to that constructor. Disclose
this shared preparation. C190's earlier native Blender animation exporter has
different output bytes and is not the C191 recorded-output binding.

## Run and assess

1. Give both agents the frozen first edit and their respective editable starter.
   Preserve first submissions and every failed attempt. Independently score the
   exact submitted outputs before requesting a repair.
2. Rebuild successful deliveries in fresh processes. Inspect source localization,
   stable body/collider identities, one mass owner per carriage, unchanged right
   lane and unrelated parts, native contact, and exact raw/final mapping bounds.
   Reopen and resimulate every retained successful native scene.
3. Issue the frozen reuse target to those same editable designs. Record whether
   the earlier target can still be regenerated. Keep reuse work distinct from
   starter and adapter preparation.
4. Run the unchanged independent continuous-motion checks, Khronos/Three.js
   readback and actual receiving-application inspection on the submitted hashes.
   Preserve current native `.22` behavior and all historical evidence.
5. Report paired outcomes, invalid intermediates, repair turns, human
   interventions, elapsed time and whatever provider token accounting is actually
   available. Mark unavailable accounting explicitly. Integrate reviewed work
   through an observed-head lease and save a new self-contained handoff.

## Cost and interpretation

Charge C191 contract, adapter, checker and native-starter preparation to reusable
setup. Record new C192 setup separately from each participant's task work. A
prepared finite adapter can make this edit very small; disclose that advantage
of preparation rather than treating it as free task effort.

One public paired exercise can qualify these authoring and reuse workflows. It
does not establish general superiority, blind performance, a 30–50-task study,
arbitrary contact, general classes/reuse, a production backend or completion of
GOAL. Use the outcome to decide whether a broader same-backend study is worth
preparing. Keep the current finite source restrictions visible.
