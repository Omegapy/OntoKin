# C208 independent review requirements

This review is limited to a separate CPU readback job/result binding component.
It cannot authorize a child process, advance the C201 schedule, establish native
readiness, or admit the static-tray family. The C201 wrapper and Node probe remain
pending. No C199/C200 cohort, native process, Node process, lifecycle stub, or
timed author is executed by this review.

## Independently established requirements

1. A validated C201 transaction binding and an actual retained accepted transaction
   are prerequisites. Revalidate the input lock, trusted source identities, exact
   stage command/environment/cwd and the accepted pointer/source/construction/
   receiving/receipt closures before job preparation and result acceptance.
2. A01–A04 are explicit identities with distinct routes and regeneration/equality
   references. Wrong, historical N-slot or nonexistent slots cannot substitute.
3. Job/result identities must bind the exact source commit/tree, input lock,
   approved protocol, accepted receipt, GLB and independent-audit bytes. A successful
   boolean alone is insufficient. Missing/extra/changed stage outputs reject.
4. The Node stage keeps its separate 30,000 ms outer and 28,000 ms child-work
   allowances, 2,000 ms cleanup allowance, exact safe argv/environment, stage cwd,
   bounded logs and 4 MiB result. Failed/unknown/unfinished/over-budget process or
   cleanup observations cannot become accepted binding evidence.
5. Historical probe semantics are preserved: Node v24.22.1; Khronos validator
   2.0.0-dev.3.10, zero errors and warnings, untruncated issues; Three.js
   0.186.1/revision 186; one static scene, 14 semantic objects and 12 meshes;
   no external resources, animation, rendering or simulation claim.
6. Check actual retained observations against the independently decoded audit:
   identities, hierarchy, roles/relations, matrices, local/world geometry,
   normals, indices, material and bounds. Validate finite numeric values,
   exact dimensions and complete measurement coverage. Preserve 0.000005 m
   position and 0.000001 rigid-matrix/normal allowances; forged expected values,
   permissive thresholds, missing fields, NaN/infinity and bool/int substitution
   must not hide failure.
7. The accepted pointer and all accepted closures remain immutable. Rejected or
   unknown result validation cannot erase evidence, retry, or grant continuation.
   In-memory terminal handling is only local preparation behavior; durable one-use
   sequencing and trusted actual observation provenance remain future coordinator
   responsibilities.
8. Preserve every historical C199/C200 byte, the 301 recorded protected inputs,
   four frozen protocol documents and released shared code. A component review is
   not a full-regression pass or production approval.

## Review method

Read the frozen candidate, bind its exact commit/tree and relevant file hashes,
then exercise its actual public API with independent synthetic accepted closures
and deliberately corrupted job/result/process records. Block process creation
seams during controls. Test observed behavior; do not invoke private validators
instead of the public API or derive acceptance only from author test names.

Preserve original failures and request bounded fixes from the implementation
worker. Final approval, if warranted, names the exact reviewed bytes and only this
CPU consistency boundary. Root owns publication, resulting-main checks and delivery.
