# Independent C209 review plan

## Scope and authority

Review one CPU-only extension of C208's readback-job preparation boundary: exact named Khronos Validator, Three.js and GLTFLoader entry resolution, including package metadata, under a new explicit versioned job contract. The reviewer owns controls and reports only; product files and remote refs belong to the implementer/integrator. Do not approve evolving working-tree content. Freeze the candidate commit/tree, then bind all reviewed inputs by digest before executing the independent controls. Same Linux runtime as the other agents; no separate-host evidence.

Existing `/0.1` job/result and accepted transaction behavior must remain exact or an explicit compatible entry point must preserve it. No C199/C200 bytes, frozen C201 protocol documents, ordinary defaults or resource limits may change. The actual wrapper/probe, Node loader semantics, process provenance, host sealing, native-readiness approval and admission stay pending. No Node, native, receiving, lifecycle or timed-author child may start.

## Independent control matrix

| Area | Controls and expected outcomes |
| --- | --- |
| Positive mapping | Real temporary files with synthetic host-package bytes, approved fixed package names/versions, exact canonical role mapping, graph reachability and metadata produce the named bindings/job; no ambient package resolution. |
| Metadata identity | Independently repin fixture lock/approval after wrong package name/version, missing/duplicate JSON keys, malformed or non-object metadata, unexpected fields where schema is exact, or metadata from a different package root. Invalid identities reject beyond a mere outer-hash failure. |
| Named entries | Missing/extra/duplicate role keys, swapped validator/Three/GLTFLoader targets, wrong expected suffix or manifest-driven entry substitution, bare import names, `file:`/URL paths, traversal and noncanonical absolute paths reject. |
| Inventory and graph | An unlisted file, host/repository root mismatch, package entry reachable only from unrelated role, disconnected entry, wrong package closure or repinned alternate input must not acquire named authority. Complete declared inventory equality alone must not prove package role membership. |
| Exact files | Changed hash/size/mode, symlink or hardlink, symlink ancestor, directory/FIFO substitution, and changed package bytes between binding and job inspection reject. Bind metadata and transitive entries to actual bytes, not version strings alone. |
| Version boundary | Legacy default job retains its field set and `/0.1` identity. New job has an explicit new schema and complete exact entry bindings. Jobs cannot be silently downgraded or upgraded by changing only schema/version or recomputing submitted digest. Returned structures must not mutate retained state. |
| Retained source and output | Old accepted closures, slot identity, exact output directory and job-file bytes remain revalidated. Failed mapping must preserve accepted pointer. Additional writes and altered existing job bytes reject. |
| Authority | All start/readiness/admission/next-slot fields remain false. No resolver result is an execution permit. Any retained `/0.2` result support must bind exact new job bytes and retain C208 process/probe checks; otherwise explicitly remain unavailable. |
| Preservation | Hash-check frozen protocol, historical C199/C200 inputs and candidate-wide relevant source/test inputs. Do not overwrite original failed evidence or revise limits to obtain a pass. |

Controls will use the actual C201 validator/transaction/readback APIs. Reusing the existing fixture constructor is permitted for synthetic setup, while assertions and mutations are independently selected. Fixture approval repinning is explicitly synthetic; it grants no independent production approval. Where practical, patch child-launch seams to fail if reached. Record each control's outcome, diagnostic, observed source hashes and launch counts.

## Review decisions and limits

A passing component review is limited to exact input-to-entry/job bindings. It cannot show that synthetic JavaScript implements a real validator API, that Three.js imports successfully, that `THREE.REVISION` is correct at runtime, or that declared dependency graph edges exhaust dynamic imports. Reject ambient entry selection in this component; do not describe it as a completed runtime import firewall. The future wrapper/probe and real host sealer must prove those properties.

Current historical limits remain: inherited full regression FAILED with 4,239 passing methods and 13 torque-read methods not run; C208 actual-main batch had one unchanged promotion-timeout failure with a separate successful rerun and unproven cause. A new failed control must be preserved, diagnosed and assessed, not omitted.

Completion condition: review frozen candidate diff/contracts; execute the independent CPU controls against exact bytes; record blockers or a narrowly scoped component-only decision; deliver control script, full bounded result, review and reviewed-input manifest. Integrator owns integration and actual-main verification.
