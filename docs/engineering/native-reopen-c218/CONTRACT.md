Source authority, supported semantics and native measurements must be inspectable after one reopen without reimport or repair. This step adds evidence to the existing experimental receiving promise: exact retained source authority, measured native shading and disclosed loss. It does not change the original strict normal-fidelity contract or declare a production integration.

## 2. Prelaunch inputs and source authority

Preparation is CPU-only and requires a clean committed observer checkout. It validates the exact previous plan, completion and input-lock bindings; the successful observed previous process; the saved-scene descriptor; and every previously prepared input hash. The exact source-normal payload is independently rebuilt from the fixed accepted GLB/source bundle/sidecar for byte comparison. This rebuild is a CPU authority check, not an OntoKin source run, GLB export or Blender import.

The new `receiver-source.json` preserves all nine C218 source, contract, binding and control files plus the unchanged C214/C215 helper bytes. The plan binds that committed revision/tree, exact commands, prepared artifacts, source scene, render recipe and complete denominators. Its C215 input lock is final before native launch because the scene already exists. The generic reporter artifact named `import_settings` contains an explicitly labeled `reopen_saved_scene` settings object; original import settings are retained separately and compared to the scene's persisted C217 property. No new GLB import is implied.

The scene stays at its verified existing path; `sceneArchivePath` names its historical location within the next handoff. The original file is never overwritten. Prelaunch recovery must preserve new source, inputs and independent review as actual bytes, and retain the already durable C217 scene and historical handoff.

## 4. One start and no persistence repair

Independent review and root must approve the committed observer, exact plan, saved-scene hash, all authority checks, denominators, resource limits and image recipe before launch. Root alone invokes the host coordinator. An exclusive, fsynced reservation is created before `Popen`; any reserved, attempted, failed or unknown start consumes the only allowance.

The command uses background/factory startup, `--disable-autoexec`, two Blender threads and isolated user config/scripts/data directories. The observer calls `bpy.ops.wm.open_mainfile` exactly once with `load_ui=False` and `use_scripts=False`, then verifies the actual opened path and disabled automatic scripts. It captures raw restored texts and scene/object extras before acceptance checks. It does not enable the GLB importer, create authority texts, remap source identities, add review objects, rebuild meshes, replace normals, export or save a scene.

Maximum wall time is 240 seconds. On timeout the coordinator kills its own process group and observes termination. Any exception after process creation also stops a still-running owned group with a bounded wait and records whether cleanup is known or unknown. A missing completion receipt, native error, timeout, remaining group, unknown result, changed binding, absent authority, incomplete observation or failed persisted setting stops the task. No automatic retry, second destination, renderer fallback, camera adjustment or additional render is allowed.
