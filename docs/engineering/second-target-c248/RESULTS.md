# C248 author result and limits

One held source component captures final material parameters for the original
18 parts/two source materials. It owns one fresh C247 capture, preserves its
actual receipt and source/native associations, and records typed material
values, selector/resource identities and the finite unsupported-feature
inventory. Missing or unsupported observations refuse with partial evidence;
the reader supplies no source values and performs no numerical comparison.

The Python model has **34 passing author methods**. They cover the 18-part
association, shared and copied materials, 18 traversal permutations, detached
receipts, exact-state/single-use composition, preconsumed-registry refusal,
partial inner failure, source/resource ambiguity, overrides and overlays,
instance transparency, script/shader/ORM/extra-pass rejection, every feature,
flag and texture slot, all 15 route settings, typed invalid values, known raw
culling/transparency modes, unit bounds and lasting scene/material drift.
Synthetic values deliberately differ from source expectations; negative-zero
alpha remains represented and no RGB conversion or source fill occurs.

The model uses the unchanged C247 `Capture` and its synthetic receipt provider.
It does not execute C246 callbacks or emulate Godot. Its successful result is
evidence only for that Python model. No GDScript parser, native getter,
installed storage behavior, thread isolation or atomicity has been established.

The static checker passes **183 checks** over 17 pinned primary source files,
11 unchanged authority/dependency files, the original GLB bytes, all source
node/mesh/material joins and selected API/lexical boundaries. It checks public
getter/property bindings, exact enum inventories, native material selection,
storage-label source support, same-observation validation and the single C247
ownership seam. It is not complete static analysis. Primary files, hashes,
retrieval metadata and exact claim locations are recorded in
[BINDINGS.json](BINDINGS.json). The initial guessed upstream filename
`scene/3d/geometry_instance_3d.cpp` returned 404; the actual class implementation
was retained from `scene/3d/visual_instance_3d.cpp`. The failed retrieval remains
preserved and is not a native execution failure.

Independent initial review found **C248-F01**: script and next-pass identities
were captured but validated using fresh getter reads. A changing getter could
therefore excuse an already observed forbidden identity. The corrected source
validates the same captured reference. Two explicit getter-sequence model
controls preserve the defect boundary. The initial source and review finding
remain available rather than being rewritten.

`01abd00e71cb0d2df162a76e360656b34abf782e` and corrected program/model
`a70f164f7eddb1c3d3674a9784d37d686a2f6082`. The latter supersedes the initial

The strongest result is `MATERIAL_PARAMETERS_CAPTURED_OTHER_RAW_PENDING`,

`native_acceptance` remain false; R07 remains pending. Raw material storage is
not original-source equality, and two equal readbacks do not prove atomicity.
No Godot/version/parser/import/render/save/reopen, source export, fixture
regeneration, product run or aggregate was started. No evaluated poses,
serialization, full envelope, persistence, reservation, launcher or hard
resource enforcement was implemented. No tolerance or historical failure
changed. Independent review, publication and saved delivery are separately
recorded by the root integrator against the final exact candidate.
