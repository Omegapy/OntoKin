# Independent recording source plans

The optional plan in `ontokin/reach_reference_plan.py` removes repeated
construction of the same independent source formulas within one explicit
recording phase. It supplements the existing independent body-rotation,
identity-carrier and interval arithmetic proofs. It changes no source law,
recording tolerance, public operation allowance or destination obligation.

## Domain and retained information

One reference retains at most one plan, identified by the strong state object,
opaque recording context, phase, boundary side and exact ordered carrier
selection. The optional domain contains at most 64 selected carriers, 64
objects, 128 sites, 32 joints, 32 following relations and eight active grips.
The first-visit graph contains at most 128 frames and a request stages at most
32 body or angle cursors. These are sufficient bounds for choosing this
implementation; larger or unsupported graphs use the original complete walk.

The present domain accepts prescribed roots, including an immutable captured
move law and the existing independently proved Cartesian spin law. Translation
retains the original interval scale and add equations; its captured elapsed
clock uses the independent checked exact arithmetic. A moving orientation uses
the original body seed and recurrence, with its cursor in the same pending
batch as descendant hinges. Dynamic roots retain the existing independent
implementation. A hinge's body proof still requires the original
Cartesian unit-axis, affine-source and attachment conditions. Sliders and
unproved changes of body axis decline the whole optional plan.

The plan retains immutable source operands, bounded source receipt getters,
source-derived affine coefficients and their original direct-seed closures.
It retains no completed frame map and no additional numerical cursor table.
Every computed pose map belongs to one request. All retained completed numeric
memo values and cursor values remain in `_Arithmetic.cache`, whose limit is
unchanged at 256 entries. Losing a cursor through ordinary eviction causes a
direct independent reseed even when the source-formula plan remains present.

A complete stationary frame may also reuse its original computed pose in that
same cache. The source graph must prove a stationary parent and a constant
local coordinate; a prescribed root must have a constant orientation and an
inactive or zero translation rate. Each memo key contains an opaque identity
unique to the exact captured plan, its frame path and its arithmetic domain.
There is no pose table on the plan. An evicted value is recomputed with the
original node formula, and every lookup and insertion uses the original
charged cache methods and current output/cap admission. Fresh whole-plan
source receipts are checked before and after requests even when every selected
frame is stationary. Moving roots and their translated descendants cannot use
this stationary proof.

## Exact expressions and source admission

The plan follows the original recursive walk's first-visit order. A computed
frame uses the same constant-pose, inverse, hinge, composition, vector and
interval operations in the same order. A stationary memo hit reuses the exact
completed cells after the current source and arithmetic admissions. A body orientation uses exactly the existing
independent direct seed and Cartesian interval recurrence, including rewind,
phase/context separation, the 64-step reseed ceiling, current operand caps
and the existing small-versus-broad graph arithmetic policy.

The identity-relative hinge shortcut retains its original two-argument entry
point, complete proof and charged receipt rechecks before returning an alias.
A hinge with a nonzero child origin uses the ordinary local hinge composition
and inverse-child composition. In particular, the segmented character's
Y-axis head keeps its original position equation; it never borrows a coaxial
zero-origin position argument.

A retained plan freshly reads each unique source receipt under a charged
callback before evaluating a new clock. Source differences between requests
discard and rebuild the plan, producing new body witnesses where required.
The plan is bound to the current model object, all five source-map objects,
both arithmetic owner objects and their shared work/check context. Replacing
one of these owners between requests invalidates the plan; replacing an owner
during evaluation rejects the pending result. Equal values in an old detached
model or map cannot stand in for the reference's current source.
Its topology receipt covers collection counts, active grips and every joint
and following endpoint, including relations outside the selected ancestry.
This prevents an added or redirected incoming relation from silently leaving
a formerly free-root plan usable.

All arithmetic consumes the captured immutable operands. After evaluation,
each unique actual source record is charged once again, then all source
getters and every completed output field are checked without another callback.
This replaces repeated re-admission of shared ancestor records along every
descendant's body proof. A source change during arithmetic rejects the batch;
a transient change that is restored cannot inject mutable operands into the
captured formula.

## Pending cursor publication

Both complete body rotations and the ordinary local hinge's sin/cos cursor
can participate in one source plan. Their insertion still calls the original
`remember` method, retaining its charged callback and live-cap synchronization.
A private admission closure stages the completed value and deliberately
declines immediate insertion. After the final source and output checks,
the bounded staged entries are inserted into the original cache without
another callback, preserving its usual maximum-size and eviction rules.

Cancellation, a callback exception or rejected source admission publishes no
staged cursor. A reentrant request that changes a still-retained same-context
cursor causes the outer batch to reject instead of overwriting the nested
result. The numerical cache can still evict pure memo entries or an old cursor
during an unsuccessful request; the plan introduces no hidden second copy of
evicted numeric history.

An unsupported or changed operand domain returns to the complete original
walk. Original affine, transcendental and interval failures are not caught by
the plan. Their exception identity and the shared work callback's exception
identity remain intact; a later broadened cap cannot turn a failed original
operation into a successful retry.

## Complete-validation source batches

The supplied-byte validator can explicitly keep one source batch open across
its complete endpoint and certificate loop. Each plan still contains only
immutable independent source operands and direct-seed recipes. At most 16
plans and 1,024 unique receipt objects are captured for one batch. A new plan
outside either optional bound keeps the original per-request source checks;
the already captured plans remain subject to the final batch admission.

Within that explicit scope, a previously captured plan need not reread its
unchanged source records at every key. The complete validation is provisional
until a callback-free admission compares every captured record with its actual
source getter. That admission also binds the current model, source maps,
arithmetic owners, phase-history containers, and each captured state's actual
history slot. The boundary axis must be the native immutable tuple of exact
Fraction clocks, within the original 10,000-boundary limit; its strong identity
binds every clock value. A mutable or foreign axis keeps ordinary per-key
admission. Both before/after histories must be exact native lists with one
state per boundary, so final state selection cannot invoke a foreign indexing
method. Replacing a model or state with equal values cannot borrow the
old source binding. Native source operands remain frozen during arithmetic,
so a transient source change restored before admission cannot enter an
intermediate equation. A persistent change rejects the complete proof.

This batching does not defer numerical cursor lookup or publication. Every
key uses the original 256-entry arithmetic cache, including ordinary eviction,
cold seeds, rewind handling and the 64-step recurrence ceiling. A bounded
ownership ledger records only which still-retained cursor values the batch
published. It is never read to evaluate or advance a cursor. Rejection deletes
only values still owned by the failed batch; a nested reader's independently
completed replacement is preserved. No evicted cursor is restored. A nested
request retains the original per-key source admission and cannot silently
replace an outer pending cursor.

Every unique deferred receipt is precharged before the final certificate
flush. The batch then stays open through the outward report conversions,
which also invoke the caller's work callback. Complete source and current-cap
admission runs after all of those callbacks and immediately before the passed
validation report is returned. Endpoint comparisons, supplied certificate
rows, native geometry conditions, interval arithmetic, report fields and
tolerances retain their original expressions and checks.

Only a changed operand cap detected by this added final admission can request
an ordinary replay. The helper creates a private restart instance; the reader
accepts only that exact instance. It clears the failed attempt's private
endpoint and certificate accumulators, removes its still-owned new cursors,
and reruns the complete certificate loop plus outward report conversions with
batching disabled. The existing work object and consumed counters continue
unchanged. Original arithmetic, cancellation, callback and source-identity
exceptions do not trigger a retry. A caller exception with the private
restart type is still the caller's original exception. Changed source identity
is rejected before a coincident cap change can request replay.
For that precedence, final admission first checks source identity without
numerical cap admission, then tests the cap, then retains the original receipt
operand guards. The latter guard rereads the bounded native source records;
neither pass invokes a callback, so no mutation can intervene between them.

## Verification scope

`tests/test_reach_reference_phase_plan.py` compares exact cold and advanced
interval cells, actual source-prefix GLB bytes and validation reports with the
complete original walk. It exercises fresh source receipts, phase/boundary
selection, topology and anchor changes, the character head, stationary poses
across 52 keys and forced cache eviction, body/angle atomic
publication, callbacks, narrowing, eviction, reentrancy and the original
64-step reseed limit. Existing source-body, identity, interval, callback and
operand-domain cohorts remain applicable. The helper is included in the
independent implementation input hash in `tools/reach_source_rates.py`.

`tests/test_reach_reference_source_batch.py` compares complete-reader and
ordinary per-key execution, including exact cells, actual source-prefix GLB
bytes and reports, cache contents after every key, forced eviction, recurrence
reseed, optional capture bounds, source/owner/history changes, restored
mutations, nested readers and original exception identity. Its terminal tests
exercise actual outward report callbacks, including source rejection and
same-budget full-loop replay after a final cap change.

These checks establish only their executed identities and domains. Full
recording, regression, compatibility and release acceptance remain separate
gates; measured operation savings and any failed attempts belong in the
identified run evidence rather than being inferred from this derivation.
## Stationary endpoint source proofs within the final source batch

The complete reader already retains the preceding endpoint comparison. It may
reuse that comparison only when the actual supplied values and claims match
and both the actual and ideal source pose laws remain constant. The ordinary
`recording_stationary_frames` walk re-establishes this structural fact for
every key. An already registered phase plan can establish it once within the
same bounded source transaction.

The optional proof keeps the original stationarity entry checkpoint. After
that callback it requires the live 128-bit arithmetic/full operand domain,
the same model/arithmetic/history owners, a plan registered by the current
reader context, native bounded carrier names and exact clocks, and the same
captured state at both queried clocks. Plans from other contexts, a different
boundary side or state, prepared transactions, nested readers, unsupported
shapes and plans built without this proof retain the original graph walk.
No new source plan is created by a stationarity query.

Later endpoint requests omit carriers whose preceding endpoint comparison can
already be reused, so the current pose plan may omit their stationary branch.
The stationarity proof may select an earlier plan from the same existing batch
of at most 16 plans. Its opaque context, exact state identity and boundary side
must match the registered current plan; its native plan type and source owners
must pass admission; and it must cover every queried carrier. Its receipts
remain subject to the original final transaction admission. Missing, foreign,
unregistered or other-phase plans cannot lend a stationary proof. Evicting
numeric cursor or pose entries does not invalidate an immutable source recipe
or grant access to any evicted numeric value.

Ideal stationarity is not sufficient. A zero ideal coordinate slope may
coexist with a different actual initial coordinate. During a batch's original
plan construction, stationary roots therefore capture their actual position
and orientation anchors and the actual initial values of any move/spin laws.
Stationary hinge candidates capture their actual coordinate/initial operands.
These are small immutable source receipts, not computed poses or numerical
memo entries. Native action records and exact elapsed/since clocks are
required for the optional proof. A running coordinate is stationary only when
actual initial, ideal initial and target are equal. A fixed attachment inherits
its parent's result. A moving ideal ancestor cannot produce a positive
stationarity result merely because its endpoint happens to repeat.

All extra receipts join the existing maximum of 1,024 source receipts and
16 captured plans. They are charged and re-admitted by the same final source
batch after every outward report conversion. Replacing a captured actual
anchor, initial coordinate, source authority or owner rejects the transaction.
Source identity rejection retains precedence over the private final-cap
restart. No numerical cursor, completed pose table or clock history is added.
The existing 256-entry LRU, per-key cursor lookups/publications, eviction and
64-step reseeding remain unchanged.

The query's clocks have at most 1,024 numerator/denominator bits. Captured
exact source clock leaves have that same bound; finite binary64 source leaves
have at most 1,075 bits. The original elapsed subtraction/sum and scalar
guards fit below 4,302 bits on this sufficient domain, well below the unchanged
32,768-bit operand ceiling. Narrower requests retain the original calculation.
No floating approximation or source result from the producer enters the proof.

`tests/test_reach_reference_stationary_batch.py` covers exact stationary sets,
pose cells, actual source prefix bytes, actual-versus-ideal zero-rate separation,
final actual-source mutation, entry cancellation/narrowing, owner replacement,
phase/side and unsupported-domain fallback, nested contexts, eviction and
reseeding. Full-to-pruned request sequences and actual multi-key prefixes
exercise selection of an earlier registered plan, including changed source,
ownership, context and registration. Results must be recorded from the identified committed candidate;
the existence of these tests is not a passing recording or release claim.
