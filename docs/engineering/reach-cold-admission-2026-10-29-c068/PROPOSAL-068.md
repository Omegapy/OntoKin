# Proposed native producer authority for one cold geometry scan

**Identity: OK-PROP-COLD-ADMISSION-068/0.1.0. Status: UNADOPTED. No activation or runtime implementation is authorized by this document.** Date: October 29, 2026, America/Denver.

## 1. Decision offered

Investigate one reader-local producer receipt and an enforceable passive interval for the actual ordinary `_vertex_extrema_uncached` invocation. Its purpose is to reuse genuinely established native source/list facts without the separately funded eager prefix scan rejected by [C068](CHECKPOINT-068.md). A receipt means retained evidence of specified earlier work; the word does not make that evidence authentic.

This proposal is conditional. Current source has no such receipt, protected interval or paid trusted router. No clause below changes the supported mutation behavior of existing callers. In particular, a new host restriction, accounting unit or routing mechanism requires a separately reviewed versioned adoption before implementation. The proposed identity is distinct from the rejected C058 comparison M1 model.

## 2. Scope and entry

The first candidate target is the original source-artifact request path in `tools/build_reach_source_artifacts.py`: compilation without a custom check, followed by export using `compiler.reach_work`. Its non-null external check is the native construction budget's bound `tick`; the nested construction check is absent. Rejecting all non-null callbacks would miss this target. The ordinary Agent service path has additional callbacks and receives no eligibility from this proposal.

An admissible implementation must identify a real authority root before its first optional inspection or charge. It must show why the code and state used by that first step are the intended native code and state. Calling a broad gate, consulting a caller-supplied flag, checking its own mutable token, or snapshotting the current function is not that proof. An assertion that arbitrary host mutation is unsupported would be a new P4 decision whose scope and effect must be separately stated.

The route must decline unsupported work owners, absent work contexts, custom callbacks, observers, active trace/profile hooks, modified dispatch and narrowed/widened/non-native operand domains without introducing a new foreign operation before the ordinary path. Any inspection needed to make that decision belongs in the paid router and requires the same passive-entry analysis. This is an unresolved design obligation, not a claim that a universal router exists.

If the chosen boundary relies on controlled interpreter startup, threading, hooks, signals, extension code or protected module storage, its exact claims, supported environments and validation must be enumerated. A process-wide label cannot silently exclude previously supported ordinary behavior. No callback is installed, cleared, replaced or suppressed to make the path eligible.

## 3. Receipt subjects and lifetime

The receipt must bind these actual subjects by exact identity and justified current facts. The final record layout and each occurrence count remain a C069 design deliverable; no unspecified container is authorized here.

| Subject | Required content and provenance |
| --- | --- |
| Request and invocation | Existing request work owner and this particular cold invocation; no authority survives request completion, retry or replay |
| Source positions | Retained exact immutable outer tuple, row tuples and native float leaves, with the actual independent source producer and completed production evidence |
| Stored positions | The actual live POSITION list and its native rows/leaves; decoder/accessor identity and exact supplied-byte/input association |
| Coverage | Equal relevant lengths and actual retained seed occurrence, with a justified stable list interval through seed inclusion |
| Work authority | Same meter, native construction callback and absent nested custom check/observer; operation/time bounds retained; full live 32,768-bit operand domain |
| Dispatch/storage authority | Finite exact code/descriptor/dependency and passive-storage manifest for geometry, conversion, arithmetic, meter and admission itself |
| Lifetime/invalidation | Actual owner and mechanism that protects or invalidates every relevant alias, mutation and callback transition; expected native meter updates remain legal |

The immutable source tuple is a plausible place to retain a native-type fact without rescanning every leaf. Its producer still requires authentication and its issuance, retention and later use are paid. `id(source_positions)` by itself is not a receipt; retention must prevent recycled identity, and the receipt must identify the actual production authority.

The stored list is different. `read_glb` eagerly populates it before metadata/reference/clock work. A stamp at the later POSITION lookup cannot certify fresh construction. The chosen mechanism must either cover that entire alias/callout interval or safely reestablish authority at the cold seam. A native list remains mutable even when all of its current rows are tuples. This proposal selects no copied snapshot, immutable replacement, list lock or generation counter implementation.

If an epoch is proposed, enumerate its owner and every operation that can invalidate it. A counter that foreign Python aliases can bypass provides no guarantee. Current native counter/category changes must not invalidate the proof spuriously, while a foreign key/value inserted into `counts` must not remain authorized. A bounded key scan cannot look up a possibly colliding name before establishing passive key storage.

Authority for the future-seed optimization may expire immediately after seed retirement, when C067 proves synchronized radius/floor/witness state. The unchanged suffix still executes. A claim valid for the whole cold scan must separately establish suffix coverage; neither scope automatically preserves arbitrary later foreign behavior after earlier omitted callbacks. If authority can disappear after an omission, a complete restoration/replay design is required before enabling that transition. No lazy fallback is selected here.

## 4. Proposed unit catalogue

The payer is the existing request's remaining shared work. A new operation is charged before its bounded body, once for each reached occurrence, including repeated or eventually rejected work. Original retained operations keep their existing schedule. These are proposed semantic units, not interpreter instruction counts.

| Unit | One bounded body | Exclusions |
| --- | --- | --- |
| B: binding claim | One native lookup of one named binding in already justified passive storage and one identity/presence test | No namespace scan, dynamic dependency closure or nested dictionary entry checks |
| R: field or index read | One native field, slot or sequence-entry read | No value predicate or multi-entry copy |
| T: predicate | One exact type, identity, finite, equality, length or native scalar bound predicate on already available values | A conjunction is several T occurrences; a foreign operation is ineligible |
| I: traversal | One native iterator creation or one advance, including a reached exhausted advance | No leaf checks, receipt writes or retained tuple copies |
| N: numeric/query body | One native absolute value, addition, nextafter or specified native hook/time query | No hidden series, source construction, Fraction fold or multi-query gate |
| C: record creation | One empty record with an explicitly fixed bounded layout | All populated slots require W; no dynamic capture inside allocation |
| W: occurrence | One reference/scalar/flag stored in one specified record slot, including retirement state | Repeated writes and copies pay again; no implicit whole-manifest write |
| O: retained work | The original point/conversion/error, numerical, guard, cache or surrounding operation under its existing meaning | It cannot also fund a new optional operation |

Native administration of the existing meter retains its existing unit interpretation; this catalogue does not recursively charge the meter's own instructions. Authenticating that meter and new bookkeeping is additional work. The separate source-value, JSON, retained-record and GLB-output regimes remain unchanged and apply whenever the implementation actually creates those logical values.

The manifest must map every newly introduced concrete occurrence to exactly one body. A lookup already covered by B is not also R, and its included identity/presence test is not also T. A physically repeated read is a new occurrence. Fixed expected source identities are inputs; dynamic inspection, capture or construction of a manifest must happen inside a funded request seam. Import-time snapshots do not supply unpaid request evidence or permission to bill a later copy as the original operation.

## 5. Event order and complete funding

[funding.json](funding.json) is the machine-readable event map. It names who pays, the required ordering and the failure continuation. No numeric unknown is treated as zero.

1. **Entry/router:** establish the independent passive root and native source-request route. Pay every extra query, lookup, predicate and transition. Preserve earlier ordinary first exceptions.
2. **Producer evidence:** retain only facts from actual completed independent production. Pay issuance, records, fields and every proof-specific validation. Do not attribute new work to a previously consumed producer charge.
3. **Interval maintenance:** pay every new ownership/epoch/alias check and invalidation action. Native work remains charged normally. All cache hits, misses and repeated occurrences retain their actual incidence.
4. **Cold admission:** after the original wrapper's effects, bind the current source/list/work/receipt, live cap and coverage. Every failed or partial attempt retains completed costs.
5. **Seed setup:** pay actual source-row access, row/leaf/finite/domain checks not already authentically established, three absolute values, two additions, two nextafter calls, the retained seed and bound, and pending state. Do not convert a future value to Fraction or expose its original error early.
6. **Pending scan:** keep every original point charge, conversion and error update. Charge each reached strict `U < L` and pending seed identity comparison. Omit only a proved exact fold. Current retained guards remain obligations.
7. **Retirement:** pay actual state writes and retained-reference release semantics if newly introduced. Do not silently omit observable foreign finalization; its exclusion belongs in authority.
8. **Rejection/refusal/repetition:** pay actual fallback, reconstruction, rescan, reissued receipt and repeated work; never refund an interrupted attempt or erase a failed charge. A warm hit starts no seed schedule merely to reuse stale authority.

Let `A_router`, `A_producer`, `A_lifetime`, `A_admit`, `A_seed`, and `A_retire` be the sums of all reached proposed unit occurrences in these stages, including preparation and repetitions. Repeated optional comparisons remain in `S` and `I`. Let `F` contain only additional restoration, replay or ordinary rescan work not already counted in those sums. These categories are disjoint. The complete successful matched-work premise is

`6*(B-K) > S + I + A_router + A_producer + A_lifetime + A_admit + A_seed + A_retire + F`.

The six `A` terms are **unresolved nonnegative event sums**, not six composite ticks. A concrete implementation must replace them with complete finite manifests and counts. C067's 798 ceiling or 530 favorable abstract residual does not satisfy this inequality. The losing eager-check schedule is rejected even before these other terms are added.

On charge refusal, stop at the actual event and preserve its exception and counter state. Construction and reach meters have different increment/check order; they need not show identical increments on refusal. A normal false predicate may select the original path only when doing so preserves the original pending state and does not erase prior optional work. An inspection exception is not automatically a false predicate. Lower operation/time budgets can fail sooner when genuinely new native work is added; no such failure is exempted from evidence. The live operand cap must still govern every retained guard and any omitted operation's justified domain.

## 6. Required evidence before adoption or observation

C069 must supply an exact source/interpreter-bound callout and alias table from the original source driver through construction, exporter, supplied-byte decoder, cached-list lifetime, independent source construction, topology work and wrapper lookup. It must identify the final authority root, immutable-source fact, list ownership mechanism and all mutation transitions. If that cannot be established, record a bounded rejection of this proposal's route.

A surviving design then requires an exact event inventory, paid initialization and complete-request opportunity bound with all cold/warm/rejected/repeated paths. Only an authority-safe schedule and a positive complete-request premise justify instrumentation. Any later observation must identify its finite remaining unknown before execution.

Before runtime acceptance, execute source-identified baseline/candidate equivalence, C057 colliding-key cases, foreign row and callback/observer/hook/dispatch cases, live narrowed-domain cases, coverage truncation and replacement, lower-budget/refusal and interruption cases, cache/warm/replay cases, actual original-request complete costs and elapsed controls. These are future evidence requirements, not C068 executions. Preserve every failed attempt, the unchanged original recordings and the complete reach release obligations.

Approval of this document means that its decision boundaries and cost statements are accurately recorded. It does not adopt P1–P5, certify an implementation, revoke historical C030 evidence, resolve C057, or change any current language, Agent, GLB or host-mutation semantics.
